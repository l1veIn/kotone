# 创建技能

技能（Skill）是**能分享给别人的通用做法**：一个文件夹，里面一个 `SKILL.md`（格式和 agentskills.io 一样），可以拷给朋友用。参考了 Anthropic 的 skill-creator 和 Hermes Agent 的 `skill_manage` 的做法。

## 先分清：技能还是记忆

- **技能**：别人拿去也能用的做法。例如“同传怎么做”“PUBG 报点的说法”“原神每日委托一条龙”。
- **记忆**（`memory` 工具）：只属于这个玩家的事。例如“玩家叫小林”“他习惯左手键位”“这个游戏里他的背包在右下角”。
- 拿不准时问玩家一句。

## 写之前

1. 用 `skill.view`（不带名字）看看已有的技能，避免重复；相近的就改那个，不要再建一个。
2. 跟玩家确认三件事（一次问一两个）：这个技能**什么时候用**、**要做成什么样**、有没有**要避开的坑**。
3. 刚刚一起做成的事，直接从这段对话里总结步骤：用了哪些工具、顺序、遇到的问题和解决办法。

## 怎么写

```markdown
---
name: pubg-callouts
description: PUBG 里帮玩家报点：方位、距离、敌人数量的说法，翻译队友的报点。玩家说“帮我报点”“队友说的方位是哪”时用。
---

# PUBG 报点

（正文：步骤、要用的工具和参数、例子、注意事项）
```

- `name`：小写英文、数字和连字符，最多 64 个字，和文件夹同名。
- `description` 最重要：琴音每段对话只看得到名字和描述，靠它决定要不要读全文。写清楚**做什么**和**什么时候用**（玩家可能怎么说），一两句话，最多 1024 字。
- 正文写给“另一个琴音”看：一步一步、具体到工具名和参数；说明为什么这样做，而不是只写“必须”。
- 简短：只写模型自己不知道的东西。很长的参考资料（键位表、地图点位）放到同一文件夹的别的文件里（`write_file`），正文里写“需要时用 `skill.view` 读 `<文件名>`”。
- 不写玩家的私人信息（名字、账号、Key），那些放记忆里。

## 用工具保存

- 新建：`skill.manage`，`action: "create"`，`name`，`content`（整份 `SKILL.md`）。
- 小改：`action: "patch"`，`old`（要换掉的原文，只能出现一次）→ `new`。
- 加附件：`action: "write_file"`，`path`（如 `keys.md`），`content`。
- 每次修改都会先备份旧版本；写技能要玩家同意（会弹确认），被拒绝就不要换个方式再写。

## 写完

- 用一句话告诉玩家技能叫什么、什么时候会用到，并提醒：在「琴音 → 技能」里能看到、删除，点文件夹图标能拷给别人。
- 下次遇到同类的事，先 `skill.view` 读这个技能再做；照着做不顺的地方，做完后问玩家要不要改进技能。
