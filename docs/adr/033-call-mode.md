# ADR 033：呼叫就是通话——一直在听、开口就能打断、说“退下”挂断

状态：Accepted / 已实现（2026-11-22，0.2.0-rc.4 发布）。D1–D4 玩家 2026-11-23 确认按推荐来。真机回声消除（外放 + 麦克风）还待玩家试，见 `docs/playtest-adr-033.md`。

修订：ADR 029 第五节（“半双工、答完接着听 8 秒、按呼叫键打断”）和“玩家决定：不判断这句话是不是对她说的”的适用范围。

## 背景

0.2.0-rc.3 真人测试反馈两件事：

1. **说了“允许”还卡在确认上**，只能打开 Kotone 点“允许”。
2. **呼叫之后，大部分人想要的是豆包通话、GPT Live 那样**：一直在通话，随时插话、打断；明确说“退下”“安静”就直接挂断。

### 为什么说了“允许”还卡着

确认（主会话的权限确认，后台任务经主会话问的确认）用嘴问的流程是：念完“这一步……，可以吗？”→ 听 6–8 秒 → 听到就按“好 / 不要”放行或拒绝；**没听到就说“没听清，请到聊天窗口里点”，之后只等窗口里点**。玩家之后再按呼叫键说“允许”，这句话被当成一条普通消息交给她（她没有工具能放行确认），确认照样卡着。

本机日志（2026-11-21 一局英雄联盟里）有一次正是这样：问完开始听 → 玩家在听的那几秒里按了两次呼叫键（正在听时按呼叫键 = “说完了”，第二下取消了这次收音）→ 记“没听到回答”→ 只能去窗口点。其他会掉进这条路的情况：玩家在她念问题时就回答了（她说话时不收音）；后台任务的确认刚好赶上“接着听”的 8 秒，问题被推后十几秒才念。

### 为什么现在打断不了、退不下

ADR 029 选了半双工：她说话时麦克风不收音（开着音箱也不会录到她自己，不需要回声消除），打断只能按呼叫键或喊唤醒词；答完接着听 8 秒；“退下 / 没事了”只在她没在忙时有用。当时把“一直在听、开口就打断”列为“以后（可选）”，因为要做回声消除。现在大部分人要的就是它。

## 参考了谁

| 项目 | 怎么做 | 照抄什么 |
| --- | --- | --- |
| orb（dsh-orb-cordis，MIT，DeepSeek Harness 悬浮球插件） | 四种听法（off / 唤醒 / 指令 / 插话），由一个纯函数从当前状态算出；固定后答完不用再唤醒，空闲 30 秒收起（她在干活、在念、在等回答、玩家在说话时暂停计时）；执行中和念的时候只认“退下”和带名字的插话；Windows 回声消除：WASAPI 回采默认扬声器作参考 + WebRTC AEC3，参考与麦克风按时间逐帧对齐，关掉降噪和自动增益，**不用通信类别**（否则系统把游戏音量压低 80%）；文字回声过滤兜底；“退下”在执行中、念的时候也生效，停掉执行和播报 | 空闲挂断与暂停计时的规则；回声消除整套做法；文字回声过滤；“退下”随时生效 |
| voice-call（MIT，DeepSeek Harness 语音通话插件，DeepSeek 整段识别 + 流式合成） | 开着通话麦克风一直开；起音 200 ms 就停播、取消这一轮；识别时又开口就合并；通话风格写成每次请求附带的一段说明（默认“1–3 句、100 字以内、口语”）；只有挂断按钮，没有语音指令；审批语音答不了 | 通话风格说明；“通话状态”放进每轮附注（不改系统提示，前缀缓存不受影响） |
| LiveKit Agents、Pipecat、xiaozhi（ADR 029 调研） | 打断要识别出 2–3 个字；LiveKit 先停、2 秒内没识别出字就接着说；对话记录只留玩家听到的部分 | 先压低、识别出字再停；只记听到的部分（已有） |

不照抄的：

- orb 必须喊名字才能插话——玩家要的是开口就能打断。
- voice-call 起音就取消这一轮、不能恢复——开着音箱和游戏声，咳嗽一下她就把话丢了。它的打断靠浏览器自带的回声消除，我们是原生程序，没有这一层。
- orb 等提问卡时关麦、voice-call 审批只能点——正是第 1 条反馈要改的。

详细研读记录：`docs/research/2026-11-22-call-mode-and-orb.md`。

## 决定

### 一、确认可以随时用嘴回答（已实现）

- 用嘴问过、还没回答的确认，登记在一个列表里（主会话的和后台的都算）。问完那几秒过了，玩家之后任何时候用嘴说的话，**整句只是“可以 / 允许 / 好的 / 不要 / 算了……”**（可以带她的名字、语气词），就交给最近问的那个确认；别的话照常交给她。
- 整句判断是因为“含有”判断会误放行：“对面打野在下路”里有“对”。问完那几秒里仍用原来宽一点的判断（那时玩家就是在回答）。
- 没听到时改说“没听清。说‘可以’或‘不要’就行。”；窗口里的按钮一直能点。

### 二、呼叫 = 接通通话

> **2026-11-26 晚修订**（[rc.10 试玩反馈](../research/2026-11-26-rc10-playtest-feedback.md)，玩家原话：“呼叫快捷键，我觉得也需要支持‘录音笔’、‘一句话模式’，还有就是，我觉得默认回复完玩家应该直接安静，默认不追问。现在好像每次回复完之后都会继续聆听，实际上，我觉得只有结尾是问号才自动聆听好一点。”）：
> - 呼叫键（以及唤醒词、聊天页的呼叫按钮、快捷指令）按下去以后有三种用法，在「角色 → 唤醒」里选：**说一句就走**（玩家说的“一句话模式”，术语表里的叫法；默认：听你说一句，说完自动结束、交给她）、**录音笔**（按一下开始听、再按一下结束、交给她；唤醒词、按钮、快捷指令没有“再按一下”，照说一句就走）、**通话**（就是下面原来的这一节：一直听，说“退下”、再按呼叫键或 30 秒没人说话才挂断）。说法和语音输入的交互方式一致。
> - **她说完就安静**：说一句就走和录音笔里，她回答完不再接着听；只有她这次最后一句话以问号结尾（`？` / `?`）才自动再听一次（照现在的追问时长）。通话里照旧一直听。
> - 老用户：旧配置里 `assistant.callIdleSeconds` 是 0（“不通话，回到一问一答”）的，读成说一句就走；其余照新默认（说一句就走）。设置只加新字段（原则 19）。

- **按呼叫键、喊唤醒词、点聊天页的呼叫按钮、按快捷指令 = 接通**（快捷指令 2026-11-23 加进来：它就是“替你在通话里说一句”，见术语表“通话”）。 通话里麦克风一直开着（唤醒那一路麦克风，没开唤醒就为通话单独开），本机 silero 检测到玩家开口（连续约 0.2 秒），就把这句话（带开口前 0.6 秒）交给和现在一样的收音、识别、交给她的流程。答完不用再按、不用再喊，没有“8 秒窗口”。
- **挂断**（任何一条）：
  - 说“退下 / 安静 / 挂了 / 没事了 / 不用了 / 拜拜 / 再见”（整句，可以带名字）——她在说、在做都算：停掉她正在说的话和主会话这一轮，交给后台的事继续做（做完照旧说一句）。
  - 通话中再按呼叫键。
  - **30 秒没人说话**（`assistant.callIdleSeconds`，0 = 不通话，回到一问一答）。她在说、在想、在做、在等确认、玩家在说时不计时（照 orb `idle.ts`）。气泡上显示倒计时。
- 通话里的确认：念完问题，下一句就是回答（不用再开一次收音）；第一节照样适用。
- “停下”照旧：停掉一切正在做的事，但不挂断。

### 三、开口就能打断（要回声消除）

- **回声消除**：照 orb 的 Windows 做法，用纯 Rust 的 `sonora`（WebRTC AEC3 的移植，BSD-3）在进程里做。参考信号是默认扬声器的回采（WASAPI loopback），所以她的声音、游戏声、从音箱出来的队友语音都能消掉；麦克风和参考按 WASAPI 给的时间戳逐帧（10 ms）对齐；关掉降噪和自动增益，开高通；**不用通信类别**。只用在唤醒 / 通话这一路麦克风，语音输入热键那一路不变。设置 `assistant.echoCancellation`，默认开；扬声器回采打不开时退回下面的半双工并记日志。
- **她在说话时玩家开口**（回声消除开着）：她的声音立刻降到约四分之一；这句识别出来以后：
  - 是“退下”这类 → 挂断；是“停下” → 停下一切；是确认的回答 → 交给确认。
  - 空的、只是“嗯 / 哦 / 对 / 哈哈”、或者和她刚说的话很像（回声没消干净）→ 音量恢复，她接着说，这句不交给她。
  - 其他 → 她停下（对话里记“玩家打断了，只说到：……”，已有），这句作为新的一句交给她。
  - 6 秒还没结果也恢复音量。
- **回声消除关着或打不开**：她说话时不收音（半双工），说完 0.3 秒后接着听；要打断就按呼叫键（会挂断）再呼叫，或者喊唤醒词。
- 戴耳机的玩家：回声消除开着也没坏处（参考里有声音、麦克风里没有，什么也不消）。

### 四、通话里怎么说话：不另加说明

本来打算照 voice-call 的默认通话说明（1–3 句、100 字以内、口语……）写进每轮附注。对过之后发现语音回合现有的规则已经更严（ADR 029 第八节：`speak` 最多两句、一共不超过 40 个字，细节写在 `written` 里），被打断时 `speak` 的结果也已经写着“玩家打断了，只说到：……”，所以不再加一段（少一条规则，前缀缓存也不受影响）。

## 不做的

- **判断这句话是不是对她说的。** 通话里说的每句话都当作对她说（豆包的做法）；和队友说话前说“退下”，或者等 30 秒自动挂断。这是 D3。
- 必须带名字才能插话（orb）。
- 起音就停、不能恢复（voice-call）。

## 玩家确认过的（2026-11-23：“通话模式四个默认值没问题”）

| | 问题 | 定成（已实现） | 没选的 |
| --- | --- | --- | --- |
| D1 | 通话中按呼叫键 | 挂断（和接通同一个键，像电话） | 她在说时 = 打断并继续通话，没在说 = 挂断 |
| D2 | 多久没人说话自动挂断 | 30 秒（orb 默认 30，可设 0–600） | 更长（豆包 10 分钟）；打一整局 |
| D3 | 通话里和队友说话 | 也会被她听到并回答；先说“退下” | 让她自己判断不是对她说的就不出声（要多一次模型调用、可能判错） |
| D4 | 回声消除 | 默认开 | 默认关，外放的人自己开 |

### 实施记录（呼叫以后的三种用法、她说完就安静，2026-11-26 晚）

[rc.10 试玩反馈](../research/2026-11-26-rc10-playtest-feedback.md)第 1 条，玩家原话：“呼叫快捷键，我觉得也需要支持‘录音笔’、‘一句话模式’，还有就是，我觉得默认回复完玩家应该直接安静，默认不追问。现在好像每次回复完之后都会继续聆听，实际上，我觉得只有结尾是问号才自动聆听好一点。”

**玩家看到的**：

- 「琴音 → 唤醒」呼叫键下面多了“按下以后”，三张卡片：**说一句就走**（默认，“听你说一句，说完自动交给她。她答完就安静，问了你一句才再听一会儿。”）、**录音笔**（“按一下开始听，再按一下结束、交给她。唤醒词和呼叫按钮照说一句就走。”）、**通话**（原来的通话）。“通话多久挂断”和“开着音箱也能打断她”只在选了通话时出现；原来的“不通话（一问一答）”选项去掉了（就是说一句就走）。
- 说一句就走、录音笔里：按呼叫键（或喊唤醒词、点聊天页的呼叫按钮、按快捷指令）不再接通通话；她答完就安静。只有她这一轮最后念的那句以问号结尾，才不用再按键、直接再听 8 秒（`assistant.followUpSeconds`），悬浮窗气泡写“等你回答”、显示这句问话和倒计时；没开口就安静收起。
- 录音笔：按一下呼叫键开始听，不管停顿多久都不结束，悬浮窗写“在听… 再按呼叫键结束”；再按一下就把这句交给她（没有预览、不进游戏）。
- 用嘴确认（“这一步……，可以吗？”）照旧：问完就听，说“可以 / 不要”就行。
- 老用户：升级后都是说一句就走（玩家要的默认），包括以前开着通话的；以前选了“不通话”（`callIdleSeconds: 0`）的也读成说一句就走。想要原来的样子就在“按下以后”选通话。

**怎么做的**：

- 设置：新字段 `assistant.callMode`（`one-shot` / `dictation` / `call`，缺省 `one-shot`，不认识的值按 `one-shot`；`kotone-core` 的 `CallMode`）。没复用 `assistant.interactionMode`：那是 0.1.x 提醒助手的提醒键在用的（升级用户的提醒键还看它），而且有“对讲机”、没有“通话”。只加字段（原则 19）：`callMode: call` 而 `callIdleSeconds: 0` 读成说一句就走（`AssistantConfig::effective_call_mode`），界面上从这种状态选通话时顺便把 `callIdleSeconds` 写回 30。`assistant.followUpSeconds`（ADR 033 起说“不再使用”）重新用上：问句之后再听几秒，0 = 不再听；读入时 `followUpSeconds: 0` 迁移成 `callIdleSeconds: 0` 那条旧迁移不动。0.1.x 旧提醒助手照旧没有通话（`call::mode` 返回说一句就走）。
- 只有选了通话才接通：`call::start` 看 `call::mode`，所以呼叫键、唤醒词、呼叫按钮、快捷指令四个入口一处改完；通话中途在设置里换成别的，空闲计时那一路看到就挂断（“设置里不再是通话”）。
- 录音笔只在呼叫键上：`hotkey.rs` 里呼叫键按下时 `callMode = dictation` 就调 `Orchestrator::call_assistant_dictation`（新的收音来源 `SessionOrigin::CallDictation`：语音输入录音笔的“再按停止”，但结束后直接交给她、不预览；会话 ID 照旧 `assistant-wake-` 开头，宿主照旧认作呼叫来的）。正在听时再按 = 结束交给她，和说一句就走里“提前结束”是同一段代码。在听的 `kotone://state` 事件带 `manualStop: true`，气泡（`bubble::on_state`）据此把标签换成“在听… 再按呼叫键结束”（判停用不了时原来就带这个字段，标签也对）；没碰悬浮窗本身（W 在改）。
- 她说完以后：`follow_up::after_reply_action` 一个纯函数定三种结果——通话开着 → 照旧一直听（`KeepCall`）；选的是通话但已经挂断了（说了退下、按了呼叫键、没人说话）→ 安静；说一句就走 / 录音笔 → 她这一轮最后念的那句 `ends_with_question`（去掉末尾空白、引号、括号、波浪号、感叹号、表情后是 `？` / `?`）且 `followUpSeconds` 不是 0 → 再听一次（`ListenOnce`），否则安静。“最后念的那句”在 `agent/voice.rs` 的 `last_spoken`：最后一次 `speak` 的 text；补了固定的话（“我写在聊天里了”）就是那句；之后又交给了后台、那一步没 speak 的是“交给我，好了告诉你”（都不是问句）。再听用的是和唤醒、语音提问同一条 `begin_assistant_wake`（说完即交，没开口就安静结束）；玩家已经又按了呼叫键在说、或者有语音提问在等回答时不另开。
- 后台的事交回结果的那一轮（不是玩家说的话）照旧不再听，问句也一样（没改）。
- 说法照术语表“四种交互模式”（说一句就走 / 录音笔）加“通话”；术语表“通话”“呼叫 / 挂断”“呼叫键”“唤醒”“快捷指令”几行跟着改，加了一行“说一句就走 / 录音笔 / 通话（呼叫以后）”；设置说明（`settings_guide.rs`）加了 `assistant.callMode`，`assistant.followUpSeconds` 从“内部”挪回能改的设置；`docs/assistant.md` 的呼叫键、通话两段改了。
