# ADR 021：给琴音一对“耳朵”——听懂说外语的队友

- 状态：Accepted（2026-11-17；依赖 [ADR 022](022-sessions-memory-soul.md)；放进 0.2.0）
- 调研：[让琴音听懂说外语的队友](../research/2026-11-17-hear-teammates.md)
- 相关：[ADR 020](020-voice-into-game-chat.md)（替玩家说话）、[ADR 014](014-game-agent-harness.md)（人能做的 Agent 都能做）

## 问题

队友说另一种语言（PUBG 很常见）。琴音已经能用对方的语言替玩家说话（ADR 020），但玩家听不懂队友。用户的要求：不写死一条“录音 → 翻译 → 显示”的流程，而是**给琴音工具，让她自己解决“知道队友在说什么”**；展示用现有的气泡、语音、弹幕。

## 决定（2026-11-17 修订：建立在 ADR 022 的会话之上）

讨论后的结论：翻译不做成工具（那等于工具里藏着另一个大模型），也不进主会话（打断她正在做的事、挤满上下文、陌生人的话进了能动手的上下文）。**琴音派一个子会话当“同传”**（[ADR 022](022-sessions-memory-soul.md)），她只缺一对“耳朵”。

### 只新增一对工具

| 工具 | 作用 | 照抄 |
|---|---|---|
| `voice.listen.start {app?, languages?}` | 开始只听某个程序（缺省当前前台游戏）的声音：切句、识别；**之后每听到一句，就作为一条消息进调用它的那个会话**。监听归这个会话所有 | 微软 ApplicationLoopback + wasapi-rs（按进程抓音频，琴音自己的语音、玩家的麦克风都抓不进来）；Kotone 现有 Silero VAD + sherpa-onnx SenseVoice（auto-caption 的用法）；VRCT 的过滤参数 |
| `voice.listen.stop` | 停止听 | — |

显示用现有的弹幕、语音、气泡（回复交付方式加一个“气泡”选项）；翻译是子会话的模型自己做的。

### 用起来

1. 玩家：“帮我盯着队友说什么” → 琴音 `session.spawn {task: "你是同传。先 voice.listen.start 听 PUBG；每听到一句非中文的话翻成中文，用弹幕显示；队友在叫玩家、问玩家、求救时，session.send 告诉我。", model: 快模型, thinking: 低, tools: [voice.listen.*, 弹幕, 语音, session.send]}`；
2. 子会话启动监听；每句话进子会话，它翻译、显示；要紧的话发回主会话；
3. “刚才他们说了啥” → 主会话 `session.send(同传, "总结最近一分钟")`，或玩家在对话列表里点开同传会话直接看；
4. “别翻了” → `session.send(同传, "停止翻译，总结一下")` 再 `session.stop`，或者直接 `session.stop`。**无论哪种，会话一结束，代码自动停掉它名下的监听**，不靠模型记得调 `voice.listen.stop`。

### 约束

- 只听玩家指定的程序；只在内存里处理，不存音频；听的时候有“正在听队友”的提示；默认关，第一次在某个游戏里听之前先问。
- 陌生人的话只进同传这个工具受限的子会话（不能动手、不能对外说话、不能写记忆）。
- 说得快时，连着的几句合成一条再进子会话，免得一句一次调用。
- PUBG 的语音和枪声在同一个程序里，识别质量要真机试；Discord / KOOK 干净得多。
- **说话人是工具的属性**（用户指出）：每句话带不带“谁说的”取决于录音方式，琴音拿到就用、拿不到照样翻译。按程序录音分不出是谁，所以第一版的话里没有说话人；以后换成能分清说话人的来源（例如 Discord 的说话事件），只改工具，不改琴音。

## 实施步骤（ADR 022 的会话做完之后）

1. 平台：按进程 loopback（新依赖 `wasapi` crate，MIT）；
2. 识别：VAD 切句 + SenseVoice，连着的句子合并；
3. `voice.listen.start / stop`：事件进调用它的会话，归属与自动清理；
4. 回复交付加“气泡”；琴音的提示词里写清“同传”的做法（也可以存成一个 Skill）；
5. 测试：纯逻辑单元测试；真机用隔离实例 + 一个播放外语录音的测试程序（不碰用户的游戏）；
6. 文档与第三方声明。

## 已确认（2026-11-17）

1. 第一版只用 SenseVoice（中英日韩粤）；更多语种以后加。
2. 同传默认用弹幕或气泡显示，不出声。
3. 第一版不区分说话人（这是录音工具的属性，见“约束”）。

## 实施记录（2026-11-18，分支 `claude/kotone-agent`）

- 录音：`kotone-platform-windows::app_audio`，wasapi-rs 0.27 的进程回环录音（32 位浮点 48 kHz 立体声、事件驱动、自动格式转换），混成单声道、重采样到 16 kHz。
  - **和设计的出入**：设计是“按进程树录（含子进程）”。实测这台机器上“含子进程”只覆盖直接子进程（Python 启动器 → 解释器 → 播放进程这种孙进程录不到）。改成**同名的每个进程各录一路（最多 32 个，不含子进程）**，由 `Follower` 跟着正在出声的那一路（另一路要等它安静 2 秒才能接手；跟随那一路的停顿照常交出去，切句要靠它）。限制：开始监听**之后**才启动的同名进程录不到，需要重新开始监听。
- 识别：`kotone-stt::transcriber`，silero VAD（停顿 0.6 秒算一句、最长 15 秒）+ SenseVoice（`language = auto`、ITN 开）。sherpa-onnx 的 Rust 绑定拿不到 SenseVoice 判出的语种，按文字的书写系统粗判（ko / ja / ru / th / zh / en），只作提示。
- 桌面：`voice_listen.rs`，监听按会话 id 登记；每一句发 `voice.heard` 事件并作为一条 `source = "heard"` 的消息交给所属会话（连着几句会合并成一条再交给模型）。会话结束、停止热键、托盘“停止自动化”、语音“停下”、Kotone 退出都会停掉；有监听时气泡显示“正在听队友”；停止时日志记一行统计（听到多少秒、峰值、几句）。
- 测试：
  - 单元：语种粗判、跟随规则、子会话合并消息与取回复；`transcribes_a_wav`（真模型、SAPI 合成的英语句子 → “Enemmy behind the Red house.” / “There're two of them.”）。
  - 真机（隔离 `KOTONE_HOME`，假 AI，`scripts/manual-e2e/sessions_e2e.py`）：琴音派出“同传”子会话 → 子会话开始听 python.exe → 另一个 Python 进程播放英语句子 → 子会话收到“Enmy behind the Red house.”，弹幕显示译文并 `session.send` 回主会话 → “停止同传”后子会话与监听一起停。全部通过。
  - 2026-11-20 修正（ADR 029 第二期，`scripts/manual-e2e/interpreter_e2e.py`）：逐个进程录时传的 `include_tree = false` 在 Windows 进程回环里是 **EXCLUDE**（录除了这棵进程树以外的全部声音），不是“只录这一个进程”——上面那次能通过，是因为当时机器上没有别的声音。机器上有别的程序在放视频时，听 python.exe 录进了浏览器里的中文视频，那段英语反而没录到。改成含子进程录（INCLUDE）后：只录到目标程序 3.5 秒的声音，认出英语句子，视频的声音不再进来。测试改用改名的 powershell.exe（`kotone-speaker.exe`）放声音，避免和机器上别的 python.exe 混在一起。
- 没验证：真实游戏或 Discord 里的队友语音、中文以外的非英语语种（只有模型本身支持）、长时间（一局游戏）连续运行的资源占用。
