# ADR 011：评测目标与缓存身份

- 状态：Accepted / 已采纳
- 修订：[ADR-005](005-eval-recording-replay.md)

## 问题

sherpa 模型家族合并为流式/非流式运行时后，`engineId` 不再唯一确定模型。旧评测用默认 `SessionConfig` 回放、按引擎命名结果，可能实际运行当前活动模型，却显示另一家族名称；标注变化也不会使旧 CER 失效。后端驻留 recognizer 进一步放大了跨模型复用问题。

## 决策

1. core 接收 `EvalTarget { engineId, modelId, sessionConfig }`，`options.model` 必须匹配 `modelId`。模型清单和旧别名由 STT 层解析，core 不反向依赖 STT。
2. CLI `--model` 可明确目标；旧家族 ID 固定解析家族默认模型；规范引擎 ID 未指定模型时取清单默认。无参数时按所有已安装本地模型枚举，不按运行时就绪状态枚举。mock 必须显式选择，在线引擎拒绝回放。
3. 使用专供评测的 registry；每次目标 warmup 前清除旧 recognizer，成功和失败路径均 unload。不能卸载桌面正常会话持有的实例。
4. 结果保存规范引擎/模型、配置快照、缓存版本和 SHA-256 指纹。目标指纹覆盖身份与配置，源指纹覆盖解码 PCM 与人工标注。报告仅复用全部匹配的结果。
5. 旧结果保留读取/导出兼容，缺身份缓存不复用。无需自动删除用户旧数据。

## 代价与验证

目标之间重新预热增加评测耗时，但避免把另一模型结果错误记账。预热时间不并入首字/finalize 指标。基线评测不使用当前游戏热词，目标中明确记录空热词。

单元测试覆盖家族别名、模型/引擎不匹配、目标与配置切换、同长度音频替换、标注变更、旧缓存兼容、错误退出清理；使用假引擎和临时文件，不下载或执行真实模型。运行方法见 [评测手册](../eval-playbook.md)。
