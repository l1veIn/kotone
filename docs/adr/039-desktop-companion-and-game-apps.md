# ADR 039：桌面陪伴 Agent，差异在游戏——输入归本体、自动卡片、英雄联盟做成独立的 MCP App

状态：Accepted（2026-11-25，玩家定的方向）。部分修订 [ADR 038](038-kotone-and-apps.md)（D1、D1.1、D2、D3 第 7 和第 9 条、D4、D5、D6、D7 第 6 期、“怎么定的”第一条；逐条写在 ADR 038“怎么定的”最后一条）和 [ADR 029](029-voice-call-and-background-tasks.md)“待定”里选模型的位置。

玩家 2026-11-25 夜定了方向，整晚不在。细节由 Claude 照 [软件哲学](../philosophy.md) 定，写进实现记录，玩家看结果。下面的玩家原话逐字引自 [交接第十一节](../research/2026-11-23-session-handoff.md)“玩家这一轮的原话”。

**文档里的叫法**（第十一节记下的要求：文档里讲架构不再用“她”）：

- **本体**：Kotone 自己——感官和表达（耳、眼、嘴、手）、对话、自动化、宿主（ADR 038 D2）；
- **插件**：装在本体上的 App（ADR 038）；
- **琴音**：角色（默认的那个；玩家可以换角色）。

界面上的字不变，指角色照旧用“她 / {name}”（[术语表](../glossary.md)“界面用语 v2”）。这条只管设计文档、ADR 和评审。

## 背景

玩家用了插件化以后的 Kotone，这一轮说了几件事：Kotone 到底是什么、英雄联盟插件太简陋、输入该归谁、陪玩的设置该放哪、要自动往聊天里推卡片并在右下角弹消息、插件要有 logo、音乐插件改名。原话写在下面各条里。

核对过的现状（2026-11-25，第十一节“核对过的现状”，实现时再核一遍）：

- 英雄联盟插件一张图都没有，只从客户端的 `/lol-game-data/assets/v1/*.json` 读名字和数据（`plugins/lol/src/client/http.rs`）。页面编在宿主的 Svelte 里。
- `game_chat.send` 由语音输入插件登记（`plugins/voice-input/src/plugin.rs`），关掉插件它就没了。打字本身的实现在本体（`kotone-core/src/inject.rs`、`kotone-platform-windows/src/inject.rs`、`companion.rs`），聊天键和发送时序在游戏配置的“高级输入设置”里。
- 语音输入页的“语音识别”卡片能在本地和在线之间切换、能下载模型（`plugins/voice-input/ui/AsrCard.svelte`），和“设置 → 通用 → 模型”重复。
- 聊天里的插件卡片只能由工具结果里的 `display` 产生，卡片数据不发给模型（`kotone-ai/src/agent/mod.rs`）。已经有两条不叫模型就往聊天里放东西的路：
  - 复盘提示：`append_notice_when_idle`（`apps/desktop/src-tauri/src/agent/commands.rs`），等琴音空下来加到对话末尾，不发给模型；
  - 自动化跑完的消息：`on_run_finished`（`agent/turn.rs`），琴音没在跑时只记进对话、不叫模型，之后的对话里模型看得到；正在跑时作为插话交给那一轮。
- `Host::emit` 只能发到插件自己的页面。
- 设置分两排：“陪玩”（怎么叫她 · 她怎么回答 · 权限 · 用量）和“通用”（模型 · API 连接 · 声音 · 调参 · 外观 · 系统 · 浏览器）。聊天模型在“她怎么回答”里选（`AssistantSettings.svelte`），聊天页上没有。
- 插件页的卡片用通用的 Lucide 图标（`PluginsPage.svelte`）。音乐插件 id 是 `music`，显示名“音乐”。

## 决定

### D1 定位：桌面陪伴 Agent，差异在游戏场景

玩家原话：“其实 kotone 本质是一个桌面陪伴 Agent 对吗？git 上有特别多类似的项目。耳朵眼睛嘴这些东西也是这些 agent 非常常见的。所以我们的差异化在于后面这些内容，游戏场景。”

- 一句话：**Kotone 是一个桌面陪伴 Agent。听、看、说是这类 Agent 都有的；Kotone 的不同在游戏场景：游戏插件给的数据和页面、按游戏事件主动、替玩家在游戏里说话和操作。**
- 这句替换 ADR 038 D1 的一句话。ADR 038 D1.1 那张表（队友比仪表盘多什么）照旧成立，那张表讲的本来就是游戏场景的差异。
- 怎么用这条：耳、眼、嘴照常做好，但照成熟项目做（原则 7），不在这些地方自己发明；力气花在游戏上：游戏插件做到和最好的单机工具对等（D5），再加上琴音按时机主动（D3）。
- **有多深远**：双向门。只改文档的说法和做事的先后，不改接口和配置。
- **什么事实会让我们改主意**：玩家大多在不打游戏时拿它聊天，游戏插件、游戏事件很少有人用。

### D2 输入归本体：语音识别和往游戏聊天里打字

> 2026-11-25 由 [ADR 041](041-send-to-game.md) 细化“往游戏聊天里打字”那一半：入口（`game_chat.send`）、通用发法、打字原语和输入锁归本体；每个游戏特有的发法（例如英雄联盟选人时走客户端聊天接口）由游戏插件提供，宿主按前台的游戏挑。语音识别那一半不变。

玩家原话：

- “ASR、游戏场景的输入（回车——unicode 输入——回车）是属于本体的。语音输入法接用了这两个本体的能力。”
- “语音输入这里就不能进行语音识别模型的配置，应该引导用户到设置-通用-模型切换里。”

决定：

- **语音识别**（麦克风、识别模型、本地 / 在线）和**往游戏聊天里打字**（开聊天框 → 逐字 Unicode 输入 → 发送；ADR 032 的吞键和控制台通道都算在里面）属于本体。语音输入插件借用这两样：用本体的“听一句”拿到字，自己处理完，交给本体打进游戏聊天。
- `game_chat.send` 回到本体登记，**名字不变**。关掉语音输入插件，琴音照样能替玩家在游戏聊天里发言；外部 Agent 经工具服务 / MCP 调它也照样能用。
- 每个游戏的聊天键、频道和发送时序**留在游戏配置**里（游戏列表页编辑）。原来计划把聊天键搬进语音输入插件（`plugins.voice-input.games.<游戏>`，插件重构计划和交接第十节“下一步”），**作废**。
- 语音输入页的“语音识别”卡片只显示现在用的是哪个模型（本地 / 在线、名字），加一个去“设置 → 通用 → 模型”的链接；不能在这里切换或下载。换模型只有一个地方。

**四个问题**（ADR 038 D3、[软件哲学](../philosophy.md)原则 12；代码位置照“背景”，实现时再核一遍）：

| | 语音识别 | 往游戏聊天里打字 |
| --- | --- | --- |
| 1. 谁用它 | 琴音（通话里听你说）、语音输入插件、同传插件（ADR 021，识别队友说的话）：三个用户 | 琴音（`game_chat.send`：替你发言）、语音输入插件（说的话打进聊天框）、自动化（ADR 036 D6 写的“往聊天里发字的自动化”）、外部 Agent（经工具服务 / MCP 调 `game_chat.send`）：四个用户 |
| 2. 要动本体的什么状态 | 麦克风只有一个；识别模型只该下一份、加载一份（ADR 038 D3 第 7 条）；本地识别的“启动”状态 | 全进程只有一份的低层键盘钩子（发送的约 220 ms 里吞掉玩家的按下，ADR 032）；输入锁（程序按键、琴音操作、打字共用一把，ADR 038“怎么定的”）；前台窗口的核对 |
| 3. 关掉它会连带谁 | 如果放在语音输入插件里：关掉插件，琴音就听不见了 | 如果放在语音输入插件里：关掉插件，`game_chat.send` 就没了（现在就是这样），琴音不能替你发言，自动化发字也失败 |
| 4. 放错了以后挪，要动什么 | 代码放在哪是双向门。语音识别本来就在本体，这次只是去掉语音输入页上的“换模型” | 工具名 `game_chat.send` 是单向门（玩家设的权限、外部 Agent 都认它），所以名字不变；聊天键留在游戏配置，就不用搬配置（配置格式是单向门，原则 19）；在哪登记是双向门 |

两样都有两个以上的用户，也都要动本体的状态 → 放本体。

- **有多深远**：见上表第 4 行。这样做两个单向门（工具名、配置）都不动。
- **什么事实会让我们改主意**：往游戏聊天里打字只剩语音输入一个用户（例如琴音不再替玩家发言、自动化也不发字）。

### D3 自动卡片：插件看到游戏里的事，自己往聊天里发卡片，不叫模型

玩家原话：“检测到对局可以自动推送一些双方战绩之类的卡片进上下文，可以不触发 LLM……琴音的回复上下文除了来自 LLM，也可以来自一些自动触发的事件。”

叫法：第十一节叫“事件卡片”。界面、文档、代码统一叫“**自动卡片**”（auto card，原则 17：一个概念一个词），见[术语表](../glossary.md)。

决定：

- 宿主给插件加一个能力：**往聊天里发一张卡片**。卡片和工具结果的聊天卡片是同一种（插件页面的小尺寸版本：`ui://kotone/<插件>/<页面>` + 给页面的数据），发到当前对话的末尾（没有当前对话就发到最近的主对话，照 `append_notice_when_idle`）。卡片上写明是哪个插件发来的。
- **不叫模型**，不花钱。
- **同时附一段很短的文字给模型**（例如“英雄联盟发来一张卡片：进加载了，对面打野最近 20 局赢 6 局”）：作为一条新消息追加在对话末尾，前面的东西一个字不改，前缀缓存照常命中（ADR 024“历史只追加”）。卡片的数据（10 个人的战绩）只给页面，不进模型（原则 10）。文字里有别人起的名字，按不可信数据处理（原则 9，ADR 036 D2）。
- **通话中不打断琴音说话**：卡片马上出现在聊天里；给模型的那段文字不插进正在跑的这一轮（不像 `on_run_finished` 那样插话），这一轮结束后再追加。琴音要不要就卡片开口，下一轮她自己看着办；这次不加“看到卡片就说一句”的规则（原则 2）。
- **先只给内置插件**，第三方插件给不给以后再定。往聊天和模型上下文里放东西是很大的权力（能刷屏、能放进想注入的话），给出去以后“每个插件一个进程”时收不回来（单向门，原则 11；ADR 038“不做”）。
- 限频：照 ADR 036 D5（攒一会儿再发、限频）和 Hermes 的合并思路，同一种卡片一局里不重复发。
- 英雄联盟第一个用：进选人或加载时发双方战绩卡片，结算时发这局的总结卡片。具体哪个时机发什么，照调研 `docs/research/2026-11-25-lol-app-parity.md`。英雄联盟插件自己的设置里有开关，默认开（不叫模型、不出声）。
- 和 ADR 036 D8 的“让她做”不一样：“让她做”每次触发都叫一次模型、花一次钱；自动卡片不叫。
- **有多深远**：给内置插件的这个能力是双向门（一起编译，随时能改）；给第三方是单向门，所以这次不给。给模型那段文字的格式是内部的，双向门。
- **什么事实会让我们改主意**：前缀缓存的命中数掉了（`usage.jsonl`）；玩家常关掉自动卡片（嫌吵）；琴音把卡片里的话当成了指令。

### D4 消息提示：发自动卡片时，屏幕右下角弹一个小窗

玩家原话：“自动推卡片的同时右下角可以弹个消息，这样用户知道在哪里看新内容，更有那种桌面聊天陪伴的感觉。”

叫法：第十一节叫“右下角弹窗”。界面、文档统一叫“**消息提示**”（message pop-up），见[术语表](../glossary.md)。不叫“通知”（和 Windows 的系统通知、给模型的系统消息撞名），不叫“提醒”（那是过一会儿说一句的提醒）。

决定：

- 发自动卡片时，屏幕右下角弹一个小窗：琴音的头像 + 一句话（例如“对面的战绩到了”）。点它打开 Kotone 的聊天页，定位到那张卡片。
- **绝不抢焦点**：照 ADR 018 气泡窗的做法（不可聚焦、`SW_SHOWNA` 显示，不激活窗口），照 ADR 032 的精神（不碰玩家正在用的游戏）。和气泡不同的是它能点（不整窗鼠标穿透）；玩家点了它，才打开 Kotone、把 Kotone 带到前面。
- 游戏独占全屏时不弹（和气泡一样）。
- 几秒后自己消失。
- 开关在“游戏陪玩 → 角色 → 交互”（D7），默认开。
- 这次只在发自动卡片时弹。别的事（例如后台的事做完）要不要也弹，以后再看。
- **有多深远**：双向门（一个窗口和一个开关；开关是新的设置字段，照原则 19 只加新字段）。
- **什么事实会让我们改主意**：真机里它抢了游戏的焦点或让游戏掉帧；玩家嫌吵、常关掉。

### D5 英雄联盟做成独立的 MCP 服务器 + MCP App

玩家原话：

- “英雄联盟插件太简陋了……需要把这个插件当作一个独立的 MCP apps 来做，完成度对标应该是 leagueAkari 和 aramHex，使用 Claude、Codex 之类的也可以使用它。界面上，应该有自己独特的风格和审美，app 的可用性上也要对标这些成熟的项目，在能探测到游戏生命周期之后，什么时间给用户什么提示，给用户展示什么信息，都可以参考这些成熟的项目。这些项目里怎么展示英雄头像、玩家头像，怎么展示海克斯 logo 都需要复刻。”
- “风格不需要我来拍板，你替我决定就好。”

准确说法（玩家认可）：**以 LeagueAkari、AramHex 为基准，功能和体验对等；视觉原创；它本身是独立的 MCP 服务器 + MCP App，Claude、Codex 也能直接用。** 拆成五条：

1. 功能对等；
2. 时机对等：选人 / 加载 / 对局中 / 结算各给什么；
3. 素材对等：英雄头像、召唤师头像、段位、海克斯、装备、技能、符文；
4. 视觉原创：不用拳头的商标和美术风格；设计语言由 Claude 定，写进 `docs/design/lol-app.md`；
5. 对外可用：Claude、Codex 这类宿主也能直接用。

决定：

- 英雄联盟的工具和 `ui://kotone/lol/*` 页面由 `kotone.exe mcp` 对外提供；Kotone 自己也照 MCP App 的方式显示它们（插件页里全屏、聊天里是卡片），**自己先用**：Kotone 里看到的和 Claude 里看到的是同一个页面。
- 页面是独立的 HTML（MCP Apps 的 `text/html;profile=mcp-app`），**不再编进宿主的 Svelte**。原来的数据和工具逻辑（`plugins/lol`）尽量复用。别的内置插件（网易云音乐、语音输入……）暂时还是 Svelte；英雄联盟做完看效果再定要不要也改（双向门）。
- 覆盖层（选英雄的胜率、海斗三选一的评分）保持现在的做法（本体的覆盖层，ADR 038 D5）；以后可以照 MCP 方案第 4 期用 pip 请求映射。
- 风险提示跟着服务器的说明和 App 一起发：腾讯 / 拳头的协议、LeagueAkari #523。只提示，不拦着（原则 3）。红线不变：不读游戏内存、不注入。
- 发到官方 MCP Registry 是往外发东西，今晚不做，等玩家看过再说。
- 这条改掉 ADR 038 D1.1 的“插件不逐项追 LeagueAkari 的功能”：现在英雄联盟 App 要和 LeagueAkari、AramHex 功能和体验对等。D1.1 说的“赢在琴音”（一句话的判断、跨插件、按时机主动、动手、记得你）照旧，是在对等之上多出来的。
- **许可证**：
  - LeagueAkari：**只学功能、布局和时机，一行代码都不抄**（第十一节定的）。第十一节写它是 GPL-3.0；2026-11-25 查 GitHub 接口，默认分支 `dev` 的 LICENSE 是 MIT，v1.3.x–v1.4.3 曾是 GPL-3.0（[调研](../research/2026-11-23-lol-live-data-akari.md)）。两种说法都按更严的一边做：新写的英雄联盟 App 不抄它的代码。以前照 MIT 的 `dev` 分支移植过的部分（腾讯 101 的解析，见 `plugins/lol/README.md`）移植时是 MIT，不用改。

- **有多深远**：**单向门**：对外的工具名、`ui://kotone/lol/*` 地址、服务器说明，外部宿主用上以后就不好改（原则 11）。所以名字沿用现有的 `lol.*` 和 ADR 038 D5 的 `ui://kotone/<插件>/<页面>`，不另起。页面用什么写（独立 HTML 还是 Svelte）是双向门。

### D6 素材不进安装包

玩家原话：“素材不要内置到 kotone 吧？太大了，应该可以直接从客户端拿在线的。”

- 安装包里不带英雄头像、召唤师头像、段位、海克斯、装备、技能、符文的图片。
- 客户端开着：从客户端的本机资源接口取（LeagueAkari 也这么做）。
- 客户端没开，或者页面在 Claude 这类别的宿主里显示（拿不到本机客户端）：用在线的公开来源，例如 CommunityDragon；用到的域名写进 App 的 CSP 声明（MCP Apps 要求页面声明要连的域名，没声明的宿主一律拒绝）。
- 可以有小的磁盘缓存，要有上限，放在 `KOTONE_HOME` 下面。
- 往外发的只有公开图片的请求，不带玩家的数据（原则 11：发到外面的数据是单向门）。
- **有多深远**：双向门。以后要带一小套图进安装包随时能加。
- **什么事实会让我们改主意**：国服玩家连 CommunityDragon 很慢或连不上，客户端没开时页面全是空图。那时考虑国内能连的来源，或者带一小套最常用的图。

### 实现记录（自动卡片、消息提示，2026-11-25）

交接第十一节第 17、18 条。玩家原话：“检测到对局可以自动推送一些双方战绩之类的卡片进上下文，可以不触发 LLM……琴音的回复上下文除了来自 LLM，也可以来自一些自动触发的事件。”“自动推卡片的同时右下角可以弹个消息，这样用户知道在哪里看新内容，更有那种桌面聊天陪伴的感觉。”

**玩家看到的**：英雄联盟进加载、10 个人的战绩查完（或进加载 20 秒）时，聊天里多一张“英雄联盟 发来 · 开局战绩”的卡片（就是“这局”页面的卡片，点开在右侧栏）；结算拿到这局结果时再来一张“这局总结”（单局详情，带“刚结束”）。同时屏幕右下角弹一个小窗：琴音的头像（右下角压英雄联盟的图标）、“琴音 · 英雄联盟”、“对面的战绩到了” / “这局的总结好了”，6 秒后自己消失，点它打开聊天、滚到那张卡片并闪一下。两个开关在“游戏陪玩 → 角色 → 交互 → 自动卡片”，默认都开。

**怎么做的**（细节由实现时定的那几条，照原则 7、11、19 定）：

- **宿主能力**：`kotone-plugin-api` 的 `Host::auto_card(AutoCard) -> Result<bool, String>`（名字照“细节由实现时定”的建议）。`AutoCard` = 去重键 `key`、卡片名 `title`、页面 `uri`（要是插件清单里的页面）+ `params`、页面数据 `data`、给琴音的 `note`（宿主截到 160 字）、消息提示那句 `popup`（截到 24 字，空 = “{插件名}发来一张卡片”）。**默认实现一律拒绝**（“自动卡片只给内置插件”）：只有桌面端给内置插件的 `DesktopHost` 实现它，还再核一遍插件在静态表里；以后的远程插件、MCP 服务器用默认实现，单向门守住。
- **存成什么**：一张卡片是对话末尾的两条消息。① `Message::Notice` 多一个 `card` 字段（`{plugin, pluginName, key, title, popup, ui, structuredContent}`，`ui` / `structuredContent` 和工具结果的 `display` 同一个形状，聊天里用同一个卡片组件）：Notice 本来就不发给模型；旧版本读到只显示 `text`（“英雄联盟 发来一张卡片：开局战绩”）。② 来源 `auto-card` 的用户消息：“（系统消息，不是玩家说的话：英雄联盟插件发来一张自动卡片「开局战绩」，玩家在聊天里看得到；要点见附件。）”，插件给的那句按数据附上（里面有别人起的名字，模型按不可信数据看，原则 9）。界面不显示它，对话标题也不拿它。没给 `Message::User` 加字段：它有 74 处构造，这样只改 Notice 的 7 处。
- **不叫模型、只追加**：两条都追加在末尾，前面一个字不改；页面数据只在 Notice 里，不进模型（测试：发卡片时假模型 0 次调用；DeepSeek 请求体前面的每一条逐字节不变，那句话在玩家下一句之前）。
- **时机**（`kotone_agent::auto_card::Desk` + 桌面端 `agent/auto_card.rs`）：琴音空着就马上记进对话；不空（琴音在回答、在说话、有提问在等、玩家在说话——复用 ADR 029“做完主动说”用的 `main_is_quiet`）时先压着：卡片照样马上显示（界面事件 `autoCard`，聊天里放在最后面，这一轮新来的消息插在它前面），这一轮结束、空下来再把两条一起追加（每 500 毫秒看一次；10 分钟还不空就只等琴音不在回答）。不插进正在跑的那一轮，不叫琴音开口（没加“看到卡片就说一句”的规则，原则 2）。
- **发到哪段对话**：当前对话（主会话）；没有就最近的主会话；一段都没有就开一段新的。
- **去重**：同一个插件同一个 `key` 只发一次（宿主记最近 256 个）；英雄联盟用 `opening:<对局 id>`、`summary:<对局 id>`，插件自己也记着（重连、刷新不重发）。**开关**是新字段 `agent.autoCards.enabled` / `agent.autoCards.popup`（默认都开，旧配置没有时按开，原则 19），放“游戏陪玩 → 角色 → 交互”。ADR 原文 D3 写的“英雄联盟插件自己的设置里有开关”改成了这个总开关：开关只有一处，以后别的插件发卡片也归它管（任务说明定的）。
- **消息提示**（`message_popup.rs`，窗口 `message-popup`，页面 `routes/messagePopup`）：
  - 不抢焦点：`tauri.conf.json` 里 `focusable: false`（tao 给的是 `WS_EX_NOACTIVATE`）、`focus: false`、置顶、不进任务栏；显示走和气泡同一个 `SW_SHOWNA`，不 `SetForegroundWindow`。能点（不整窗穿透）；点它才照“点托盘打开窗口”把主窗口拿到前面（那是玩家自己的动作），切到聊天页、那段对话（琴音不在回答时），卡片滚到中间、外圈闪 1.2 秒。
  - 不弹的时候：`SHQueryUserNotificationState` 报独占全屏（`QUNS_RUNNING_D3D_FULL_SCREEN`）、演示模式（`QUNS_PRESENTATION_MODE`）；报 `QUNS_BUSY`（有程序全屏）时，前台是 Kotone 认得的游戏就照样弹（无边框全屏的游戏也报这个，和气泡、覆盖层一样能显示），别的程序全屏（看视频）不弹；Kotone 自己的窗口在前台、看得见时不弹（卡片就在眼前，比设计文档写的“正显示着那段对话”简单：不用界面回报显示的是哪一页；看不见的不算，`--background` 启动后藏着的主窗口会占着前台）。不弹时卡片照样进聊天。
  - 位置：前台窗口所在显示器工作区的右下角，离边 24（窗口 344 × 104，四周 12 给阴影，小窗本身 320 × 72）；气泡在右下角正显示着时放在气泡窗口上面隔 12。亮暗、配色、字体跟 Kotone 的外观设置（窗口之间共用的外观偏好），不跟缩放。
  - 停 6 秒，鼠标在上面不走、移开后至少再等 2 秒；新的替换旧的；界面没来收起时 60 秒后宿主也收起。不进截图（`WDA_EXCLUDEFROMCAPTURE`，和覆盖层同一个函数）；测试用的 `KOTONE_POPUP_CAPTURABLE=1` 让真机脚本能截到它。
- **英雄联盟**（`plugins/lol/src/watcher/auto_cards.rs`，`watcher.rs` 只加了模块、状态里一个字段、`tick` 里一行）：照调研第五节和设计文档第四节。开局战绩：进加载（局内接口还没有游戏时间）以后 10 个人查完就发，20 秒还没查完也发（写“还在查 N 人”）；第一次看到这局时已经开打（Kotone 晚开、重连）不发。页面数据就是 `lol.scout` 的 `match_page`；给琴音的那句用 `scout::summarize` + `weak_spots` 的结论（突破口最多两人、每人最多两条原因）+ 我方最大开黑人数。这局总结：从对局进了结算就读 `/lol-match-history/v1/games/<id>`，每 5 秒一次、最多 60 秒；重开局（提前投降或不到 4 分钟）不发；页面数据是 `game_page` 加 `justEnded: true`；那句是输赢、模式、时长、我的英雄和 K/D/A、伤害全队第几。自定义、训练（队列 ≤ 0、`PRACTICETOOL`）、观战（这局里没有自己）都不发。卡片名、消息提示那句是插件给的中文（“开局战绩”“对面的战绩到了”），英文界面下也是中文，以后插件文案做多语言时再换。
- **审查后修的（2026-11-25）**：
  - 卡片和给琴音的那句可能丢：主会话原来先读对话、再认领“正在跑”，自动卡片正好在这中间记进对话，这一轮拿着旧的对话存盘就把它盖掉了（重新打开时卡片没了，琴音也没看到那句）。改成认领之后再读；往对话末尾追加的（自动卡片、复盘提示、自动化的结果、交回的后台结果）都走同一个函数 `append_to_conversation`，和认领用同一把锁，读、改、存都在锁里，那段对话在跑时不写（等，或者作为插话交给那一轮）。
  - 去重：贴出去了（记进对话或压着）才算发过，读不了对话存储时把键放掉，之后还能再发；去重表只在内存里，Kotone 重启以后看当前对话里有没有同插件同键的卡片，有就不再发（英雄联盟的键本来就带对局 id：`opening:<对局 id>`，同一局不重发，下一局照发）。
  - 压着的卡片存一份在 `agent/auto-cards-held.json`：这期间 Kotone 退出了，下次启动接着记（启动时 `resume_held_cards`）。
  - 记进对话连着出错 5 次（`MAX_FAILURES`）就放弃这张，只记一次日志；原来每 500 毫秒重试、每次都写日志。
  - 测试：`turn.rs` 模拟“选好对话 → 卡片记进去 → 认领”的交错，和“在跑时不写、结束后接在回答后面”；`kotone_agent::auto_card` 的贴不出去能再发、重启后看对话、压着的存盘读回、连着失败放弃。


**检查**：见 [插件重构计划](../plugin-refactor.md)第九节“自动卡片和消息提示”。

### 实施记录（ui.open 不打断玩家，2026-11-25）

[共享资源评估](../research/2026-11-25-shared-resources-audit.md)第二节第 6 条、第四节“聊天流”那一行（“`ui.open` 不打断玩家正在看的东西，外部 Agent 调要经权限”）。评估只读了代码，说 `ui.open` 会把 Kotone 切到聊天页、换掉右侧栏，琴音和外部 Agent 都能调，自动允许、没有节流。

**复现**（Playwright，浏览器预览里用和真窗口同一个处理函数）：玩家在「设置 → 声音」时打开同传的页面，被切到聊天页；右侧栏显示着同传时打开游戏语音，同传被换掉；右侧栏开着网页时，换成了“页面”标签；玩家在「插件」时打开 `ui://kotone/settings/models`，被切到设置。四条都复现了。外部 Agent 那一半照实说：Kotone 对外部 Agent 的调用本来就不问，而且不只 `ui.open`，所有工具都这样（[ADR 014](014-game-agent-harness.md) 第 5 节，2026-11-16 玩家确认：“全部能力开放，权限由它们自己的运行框架管”；`game.act` 也不问）。评估说的“自动允许”是琴音的默认规则（`shows-ui` 允许，`kotone-agent` 的 `every_service_side_effect_is_classified`）。

**玩家看到的**：

- 玩家在聊天页，右侧栏空着（收着、停在“卡片”、“网页”里没开网页）或显示的就是这个插件的页面：照旧直接显示。同一个插件的下一页往上叠，“返回”回到刚才在看的那页（原来整叠换掉）。设置页在聊天页时照旧跳过去（她带你过去）。
- 别的时候（在别的页面；右侧栏显示着另一个插件的页面、开着的网页、展开看的后台的事）：不切页、不换掉。聊天页右侧栏“卡片”最上面多一张“{插件} · {页面}”（“新页面，没打断你，点了才打开”，“打开”和“不看了”），窗口右下角出一个提示“「…」在右侧栏等你看”（6 秒，带“打开”；在窗口里，不拿焦点）。玩家点了才切过去。
- 同一个页面（地址 + 参数）反复打开只算一次：显示着的不重新挂、不再叠；等着的不重复放、不再提示。提示只有一个，新的替换旧的。等着的最多 5 张，只在内存里（和右侧栏的页面一样）。

**怎么做的**（照原则 2、11、15 定）：

- 规矩只写一处：界面 `apps/desktop/src/lib/stores/uiOpen.ts` 的 `canShowNow`。设置窗口报“正看着聊天页”（`chatShowing`），右侧栏报“现在显示着什么”（`sidebarShowing`）。谁调的不分，她和外部 Agent 同一条规矩：工具服务的请求里本来就不带是谁调的，为了分开要改协议，而不打断玩家以后外部 Agent 最多在右侧栏放一张卡片。
- 去重照自动卡片“同一个插件同一个 key 只发一次”（本节上面），只是 key 由宿主按地址 + 参数算，不要调用方给；提示一个替换一个照消息提示（D4）。没有用时间窗：不用定“短时间”是几秒，也不用计时器。
- 工具结果：检查地址、发 `kotone://ui-open` 照旧是 `plugins::open_page`；新的 `apps/desktop/src-tauri/src/ui_open.rs` 先登记再发、等界面回话（命令 `ui_open_reply`，最多 2 秒），把结果写进工具结果：`opened`（已经显示了）、`status`（`shown` / `waiting` = 放在右侧栏等玩家点 / `sent` = 窗口没回话）、`note`（给调用方照着说的话）。工具名、参数、原来的字段都不变（单向门）；`opened` 原来总是 true，现在是“已经显示了”。工具说明（`kotone-tools` 的 `catalog_host.rs`）、[工具服务手册](../tool-service.md)跟着改了。
- **外部 Agent 的权限没加**：工具服务没有自己的询问机制（ADR 014 第 5 节），给 `ui.open` 单独加一个就是另造一套；不打断玩家以后它也没有要拦的东西了。要不要让外部 Agent 调 `ui.open`（或者别的工具）先经玩家同意，是改 ADR 014 的事，留给玩家定。

**测试**：Playwright `apps/desktop/e2e/ui-open.spec.ts` 3 个（在别的页面不切、提示和卡片、点了才开、开两次只算一次、提示一个替换一个；聊天页右侧栏空着直接显示、同一个插件往上叠能返回、另一个插件的等着、“不看了”；开着网页、展开看后台的事时不换、右侧栏收着算空着）；`agent-chat.spec` 加了“处理完交回后端的结果”（经 `kotone://ui-open` 事件，`ui_open_reply` 带 `shown` / `waiting`）；`navigation`、`sidebar-edit`、英雄联盟 / 游戏语音 / 同传的 spec 改成新的行为（玩家在别的页面时点提示上的“打开”）。Rust `ui_open::tests`（结果的三种 status、回话交给等同一个地址的）。真机 `scripts/manual-e2e/mcp_app_real.py` 加了第 1.5 步：玩家在插件页时经 `kotone.exe tools call ui.open` 打开战绩，结果是 `waiting`（界面经 `ui_open_reply` 回了话）、没切页、一个提示、开两次聊天页“卡片”里也只有一张；回到聊天页后战绩、单局详情、英雄、强度榜每页 `shown`（同一个插件往上叠）。2026-11-25 跑：Playwright 全量 195/195，真机 34/34（截图 `target/plugin-shots/round7/real-ui-open-waiting-*.png`）。

**还没测**：外部 Agent 经 `kotone.exe mcp`（Claude Code 这类宿主）调 `ui.open`——走的是同一个工具服务，只测了 `kotone.exe tools call`；窗口还没加载完时的 `sent`（只有单元测试）；窄窗口里右侧栏收着时直接显示会盖住聊天（照“右侧栏空着就直接显示”，没另加规矩）。

### 实施记录（她正忙时插进来的：排队，不丢，2026-11-25）

[共享资源评估](../research/2026-11-25-shared-resources-audit.md)第二节第 9 条、第四节“聊天流”那一行（“一种‘她正忙时插进来’的规矩（排队，不丢）”）。评估只读了代码，说复盘提示等 3 分钟没空就放弃、工具被转到后台时自动化的结果只记一行日志就丢了，“她正忙时插进来”有四种规矩。

**复现**（单元测试，假的“她正忙”）：

- 复盘那条：她在跑一轮时来，原来的等法（2 秒一次、90 次；测试里 3 次）一直等不到她空，返回 `postedTo = None`；她空了以后对话里也没有，没排着，日志里只有“recap: … written”。复现了。真会这样的时候：一轮最长 5 分钟（用上 `game.act` 时），接着的插话还会续上；或者等的这 3 分钟里 Kotone 退出了。
- 自动化的结果：发起它的那段对话是一个转到后台的工具在跑时（插不进话），原来只记一行日志，那个工具做完以后对话里也没有。函数这一层复现了，但**现在的调用方走不到**：结果交回的对话是调 `automation.run` / `saved.*` 的那一轮记下的（`remember_run`），而这两个工具都马上返回、不会被转到后台；转到后台的工具那段隐藏对话是新开的，里面没人调过它们。照样改成走同一个队列（见下），不再有只记日志的分支。
- “让她做”：等过 2 分钟（ADR 036）就不做，只记日志、聊天里什么都没有——这是 ADR 036 定的“不做”，没写复现测试，改成不做时在聊天里留一句。

**玩家看到的**：对局复盘那条、自动化跑完的结果不再因为她一直在忙而消失：她空了以后照来的先后出现在聊天末尾（她说话、你说话、她在回答时都等）；这期间关了 Kotone，下次打开接着记。“让她做”过时没做时，聊天里多一句“自动化「…」要她做的事没做：她一直在忙，等了 2 分钟，已经过时了”（不发给她，她不会照着晚做）。设置没有变。

**怎么做的**（原则 2、15）：

- 规矩只写一处：`apps/desktop/src-tauri/src/agent/when_free.rs`（`post_locked` / `flush_locked` 是纯逻辑，有单测）。只记进对话、不叫她的东西都经它：自动卡片、复盘那条（`post_notice`，原来的 `append_notice_when_idle` 删了）、自动化的结果（`on_run_finished`）、交回不是当前对话的后台结果（`relay.rs` 的 `append_to`）、“让她做”没做时留的那句。
- 规矩：① 她这一轮就该看的（自动化的结果、交回的后台结果）那段对话正有模型在跑，就作为插话交给这一轮（照旧）；② 她空着（`main_is_quiet`，自动卡片原来就用它）、那段对话前面也没有排着的，马上记；③ 其余排队，每段对话照来的先后，一段在跑不挡别的对话；10 分钟还不空就只等那段对话不在跑；④ 只有那段对话被删了、读写对话连着出错 5 次才放弃（记日志）。
- 队列就是自动卡片原来压着卡片用的那个（`kotone_agent::auto_card::Desk`，卡片的去重照旧在它上面），从 `auto_card.rs` 挪到了 `when_free.rs`；盘上的文件名照旧是 `agent/auto-cards-held.json`（里面就是对话消息，rc.8 读得懂）。`append_to_conversation` 删了：往对话末尾写只剩 `append_locked`（不在跑才写）和 `steer_locked`（插话）。
- 复盘那条发到哪和自动卡片一样（`target_conversation`）：当前的主会话；当前是后台那段隐藏的对话时发到最近的主会话（原来会发进隐藏的那段）；一段都没有就开一段。`game.recap` 不再为了等她空最多卡 3 分钟，马上返回 `postedTo`（排着也算）。
- **还剩两种等法**：只记进对话的（上面）一种；要叫她开口说一句的另一种——后台结果交回当前对话（`schedule_report`，一直等到她空，结果在后台的登记里存着、玩家下次说话时也会一起交回，不会丢）和“让她做”（最多等 2 分钟）。没收成一种：叫她开口要花一次 AI 调用，过时的事件不该叫她晚做；而只记进对话的东西过多久都还有用。

**测试**：`agent::when_free::tests` 6 个（复盘那条一直排着、她说完接在回答后面；自动化的结果在转到后台的工具做完后进对话；有模型在跑时插话；照来的先后、后来的不抢先；一段在跑不挡别的、删掉的不记；发到哪段）；`agent::relay::tests::a_skipped_prompt_leaves_a_line_for_the_player`；`agent::turn::tests` 改成新的 `append_locked` / `steer_locked`。`cargo test -p kotone-tauri` 140 个通过。

**还没测**：真机（她正忙时游戏结束、复盘那条等她说完才出现；排着时退出再打开）；排着的复盘那条在进聊天前界面上看不到（自动卡片照旧马上显示）。
