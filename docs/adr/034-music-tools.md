# ADR 034：放歌收敛成工具——先只做网易云，Kotone 自己放

状态：Accepted（2026-11-23）。D1–D8 玩家确认（D3–D8 “按照你推荐的来”），另外要一个全局的“音乐”页（放在自动化下面，照开源的网易云第三方播放器自己写）和可以自己排的侧边栏（第五、六节）。替代 ADR 031 里“音乐只在 Kotone 的内置浏览器里放”那一节；内置浏览器本身不变。

## 背景

ADR 031 让她在右侧栏的浏览器里打开音乐网站放歌（`music-web` 技能 + `browser.*` 工具，主会话的 `music` 只能暂停 / 下一首 / 静音）。试玩下来：

- **慢**：一首歌要后台打开网页、读页面、搜、点播放，20–40 秒，网易云页面一步就要 6–19 秒；
- **意外多**：不登录网易云搜什么都是 0 首，模型以为“没这首歌”换了四个网站；VIP 单曲、没版权（周杰伦）、要扫码时得把浏览器交给玩家；网页改版技能就失效；
- 播放器用的是不挂在页面上的 `Audio` 对象，暂停和“在不在放”都要靠注入脚本猜。

玩家（2026-11-23）：“音乐相关收敛成工具感觉更好一点，现在的 browser use 有点慢，而且意外很多”“音乐播放暂时可以收敛成一个网易云……后面可以升级为多个 provider 的结构”“我们是非盈利的纯开源项目……就用非官方接口呗，让用户扫个码”。

## 参考了谁

调研见 [`docs/research/2026-11-23-netease-music-api.md`](../research/2026-11-23-netease-music-api.md)。

- **接口**：NeteaseCloudMusicApi 的维护分支 api-enhanced（MIT）：加密、扫码登录 `type:3`、各接口参数、2 分钟缓存防风控。
- **Rust 客户端**：[ncmapi](https://github.com/two-mountains/ncmapi-rs)（MIT，2026-11-17）已经有我们要的全部接口和扫码登录，tokio + reqwest + rustls，和我们的栈一样。
- **播放器**：YesPlayMusic（MIT）怎么判断一首歌能不能放、跳过试听片段；dsh-netease-music（MIT，DeepSeek Harness 插件）给 Agent 的 `netease_play` / `netease_player` 两个工具。
- **多来源的结构**：listen1 每个平台同一套方法、按 ID 前缀分派；Mineral 的 Rust trait 带能力声明（只参考，AGPL）。

## 决定

### 一、放歌是一个工具，主会话自己用（不交给后台）

主会话现有的 `music` 工具换成真正的播放器控制，一次调用就出声：

| 动作 | 例子 | 做什么 |
| --- | --- | --- |
| `play` + `query` | “我要听晴天”“放点周杰伦” | 搜歌，排成播放列表，从第一首**能完整放的**开始 |
| `play` + `from` | “放每日推荐”“放我喜欢的”“放私人 FM”“放《xxx》这个歌单” | `daily` / `liked` / `fm` / `playlist`（按歌单名找） |
| `pause` `resume` `next` `previous` `stop` | “暂停”“切歌” | — |
| `volume` | “小声点” | 0–100 |
| `now` | “这是什么歌” | 歌名、歌手、第几首 |
| `like` | “红心这首” | 加进“我喜欢的音乐” |

返回一两行：正在放什么、为什么放不了（要 VIP / 没版权 / 要登录）。她照着说一句就行，不用另读技能。

### 二、网易云：非官方接口 + 扫码登录

- 新 crate `kotone-music`：`MusicProvider` trait（`search`、`stream`、`lyric`（先不用）、`daily`、`liked`、`playlists`、`playlist_tracks`、`fm`、`like`、`login_qr_start` / `login_qr_poll`、`caps()` 说明支持哪些），**先只有网易云一个实现**；歌曲 ID 带来源前缀（`ne:12345`），以后加 QQ 音乐只是再写一个实现。
- 网易云实现是 `kotone-music` 里一层**薄客户端，照 ncmapi 和 api-enhanced（都是 MIT）抄**：全部走 eapi（AES-128-ECB + MD5，常量照 api-enhanced），保留原始 JSON。不直接依赖 ncmapi，因为阶段零发现（见下）：它的模型里没有判断能不能完整放的字段（`fee`、`privilege`、`freeTrialInfo`），它依赖的 `rsa` 0.9.10 会让 `cargo audit` 报 RUSTSEC-2023-0071、CI 过不了。抄过来的部分在 `THIRD_PARTY_NOTICES.md` 署名。网易云 2026 年在把取播放链接往更难的加密（xeapi）上推，到时候照 api-enhanced 补。
- **登录**：她在聊天里发一张二维码卡片，玩家用网易云 App 扫；设置里也能扫码 / 退出。登录 Cookie（`MUSIC_U`、`__csrf`）和 Key 一样存 Windows 凭据库，不进 config.json、不进日志。只用扫码（`type:3`），不做密码 / 短信登录（更容易被风控）。
- **账号安全**（照 api-enhanced）：同一个请求 2 分钟内用缓存；不批量取歌词、不连续重试登录；放不了的歌最多往后试几首就停下说原因。

### 三、Kotone 自己放，不再用浏览器放歌

- 播放在 Rust 里：按播放链接边下边放（不落盘、不缓存成文件），symphonia 解码 MP3 / FLAC，cpal 输出到默认扬声器，带一个播放列表。
- **她说话时音乐压低**（和通话里她被打断时压低同一套做法），说完恢复。通话的回声消除参考的是扬声器的全部声音，音乐也在里面，不会被当成玩家在说话（要真机验证）。
- 在放的时候左侧栏底部有一个小播放条（歌名、暂停、下一首），哪一页都看得见；点它去音乐页。
- 浏览器放歌那一套删掉：`music-web` 内置技能（装过的没改过就删，改过的留着）、设置里“放歌用哪个网站”（`agent.musicSite`，旧配置里的值读到就丢掉）、浏览器里登记 `Audio` 的注入脚本和 `music` 对网页的暂停 / 静音。内置浏览器其他功能不变，玩家想在网页上听歌自己点就行。

### 四、几条底线（告诉过玩家的）

- 只放玩家自己账号能放的：VIP 歌靠玩家自己的会员；**不“解灰”**（不从别的平台拉没版权的歌）。
- 不下载歌曲文件，只边下边放。
- 都在 `kotone-music` 这一个 crate 里：接口变了、或者被要求删，只动这一块。

### 五、音乐页（玩家 2026-11-23：“来一个全局的新页面：音乐，就放在自动化下面”）

左侧栏“游戏陪玩”一组里，自动化下面加一项“音乐”。版式照 YesPlayMusic（MIT，Vue）的信息结构自己用 Svelte 写：

- **顶部**：搜歌框；右边是账号（头像、昵称；没登录是“扫码登录”）和音质。
- **没登录**：中间一张扫码卡片（二维码 + “用网易云音乐 App 扫一扫”），扫了显示“在手机上确认”，过期了点一下换一张。她在聊天里要放歌而你没登录时，聊天页也出这张卡片。
- **发现**：每日推荐（一张大卡片，点了从第一首放）、私人 FM、我的歌单（“我喜欢的音乐”排第一，网格，封面 + 名字）。
- **搜索结果 / 歌单**：曲目列表（序号、歌名、歌手、专辑、时长；要 VIP、付费、下架的灰掉并标出来），双击或点播放从这首开始放这一列。
- **底部播放条**：封面、歌名歌手、上一首 / 播放暂停 / 下一首、进度、音量、红心、播放列表。
- 不做歌词页（以后可以加）。

### 六、侧边栏可以自己排（玩家 2026-11-23：“编辑位置、编辑是否显示，查看全部之类的”）

- 侧边栏两组（游戏陪玩、语音输入）里的页面都可以**在组内上移 / 下移、隐藏**；“设置”和对话列表固定不动。
- 分组标题那一行有一个“⋯”：打开“全部页面”，每一页一行：上移 / 下移、显示 / 隐藏，点名字直接打开（隐藏了的也能从这里打开）；底下“恢复默认”。在页面上右键也有同样的上移 / 下移 / 隐藏。
- 存在设置里（`ui.sidebar`：`order`、`hidden`），她也能帮你改（“把音乐放到最上面”）。新加的页面按默认位置出现，不会因为你排过序就看不见。

## 不做的

- QQ 音乐、酷狗、酷我（结构上留着，以后一个来源一个实现）。
- 歌词显示、桌面歌词、下载、本地音乐。
- 控制玩家电脑上装的网易云客户端（SMTC）。

## 阶段零结果（2026-11-23，本机真网络，ncmapi 1.9.1，没登录）

| 试了什么 | 结果 |
| --- | --- |
| 搜《晴天 周杰伦》《孤勇者》《Lemon 米津玄師》 | 都是 200，每次 200–300 ms；网易云没有周杰伦的原唱，前几条都是翻唱 |
| 取前 5 首的播放链接（旧的 `/api/song/enhance/player/url`，eapi） | 都给了链接，50–120 ms |
| 链接到底是整首还是试听（按文件大小算时长） | 陈奕迅《孤勇者》45 秒、米津玄師《Lemon》30 秒、《Enemy》30 秒 = **试听片段**；《晴天》翻唱 271 秒 = 整首 320k |
| 开始扫码登录（`qrcode/unikey`） | 拿到 unikey |
| `cargo audit` | ncmapi 依赖的 `rsa` 0.9.10 报 RUSTSEC-2023-0071 |

所以：不登录基本只能放翻唱（D5 改成第一次放歌先扫码）；要判断是不是试听，得留着原始 JSON 里的 `freeTrialInfo` / `fee`（或者按文件大小算），ncmapi 的模型里没有；不直接依赖 ncmapi。

## 风险

- **接口会变**：网易云在往更难的加密上推（xeapi / neapi）、会风控扫码。靠 ncmapi 跟进；最坏情况放歌暂时不能用，不影响 Kotone 其他功能。
- **账号风险**：短时间大量请求会被限制（有人 1.3 秒取 30 次歌词，整个账号很久取不到播放链接）。缓存、不批量、不反复登录。
- **歌曲版权**：网易云本身没有的歌（周杰伦）只能搜到翻唱；她要直说“网易云没有原唱”。
- **非中国 IP、代理**：会 `-460` / `-462`，给玩家的提示里说清楚。
