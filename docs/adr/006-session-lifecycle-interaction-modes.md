# ADR 006：会话生命周期交互模式 —— 正交触发策略 + 单键语义 + 预览只读

- 状态：已采纳（交互模式业务建模的第一波施工）
- 上下文：hold/toggle 双模式 + autoSend 开关是 v3 以来的硬编码组合，
  分散在 orchestrator 分支、匹配器、设置页三处。VAD 免按（Phase 3）与
  「说一句就走」在 road map 上，继续硬编码会让每个新模式都改三层。
  需要把会话生命周期建模为正交策略，并拍板 Preview 态的编辑能力去留。

## 决策

### 1. 三个正交决策点（会话生命周期策略）

| 决策点 | 取值 | 说明 |
|--------|------|------|
| **BeginTrigger** | A1 热键按住 / A2 热键点按 / A3 VAD 检测语音 | A3 属 Phase 3 全时免按，本期不做 |
| **EndTrigger** | B1 松手 / B2 再按一次 / B3 VAD 静音判停 / Esc 取消（恒在） | B3 下一任务做，本期只留枚举与路由接口 |
| **PostFinalize** | C1 直接发送 / C2 预览确认 | 即原 autoSend 语义 |

**流式与否、悬浮框回显不是模式维度**——它们是引擎能力（streaming）
及其在 UI 上的投影，换引擎不换模式。

### 2. 四个预设模式（策略组合的商品名）

| 预设 | 组合 | 状态 |
|------|------|------|
| 对讲机 push-to-talk | A1 + B1 + C1 | 本期（原 hold + autoSend=true） |
| 录音笔 dictation | A2 + B2 + C2 | 本期（原 toggle + autoSend=false） |
| 说一句就走 one-shot | A2 + B3 + C1 | 下一任务（VAD 静音判停） |
| 全时免按 hands-free | A3 + B3 + 待定 | Phase 3 |

配置：`config.json` 新增可选 `interactionMode`（kebab-case 预设名）。
**缺省时由旧字段 `hotkey.mode` + `autoSend` 推导策略**（兼容已有配置与
混合组合，行为零变化）；显式设置预设时以预设为准。设置页后续统一到
预设选择器，本期 UI 不改（热键/发送行为仍分开展示）。

### 3. 单键语义表（触发键按状态路由）

| 状态 | 触发键 | Esc |
|------|--------|-----|
| Idle | 开始录音 | — |
| Listening | 结束录音→转写（B1 策略下为松手结束，按下忽略） | 取消 |
| Transcribing | 忽略（A2 策略：中止） | 取消 |
| Preview | **确认发送**（A1 策略+C2 混合组合下按下忽略） | 丢弃（重说 = Esc 后再按触发键） |
| Sending | 中止（A2 策略） | 中止 |
| Error（带文本） | 重试发送（A2 策略） | 放弃回 Idle |

（括号内为本期保现状的边界：hold 系组合在非 Idle 态忽略按下，避免
begin 失败的 toast 冲掉预览文本；这是 v5 实测定下的行为，予以保留。）

### 4. 预览只读化（编辑是伪需求）

- 游戏场景错别字只有两种处置：**直接发**或**重说**，没有人会逐字编辑。
- Preview 态悬浮条移除 textarea，改只读文本 + 提示「{触发键} 发送 / Esc 重说」。
- `confirm_send` 不再接受文本参数（IPC 签名简化为 `confirm_send()`）。
- overlay 永不需要键盘焦点（SW_SHOWNA 不抢焦点的语义闭环）。

### 5. 热键捕获录入

设置页热键输入框改「点击录入」按钮：LL 钩子进入捕获模式（期间正常
匹配挂起、不吞键），取下一个非修饰键 down 时刻的「主键 + 修饰键实时
状态」作为新热键；Esc 取消录入，3 秒无操作超时。CLI 提供
`kotone-cli config set hotkey.key --capture`（终端提示按任意键）。

## 被否决项

- **独立确认键**（如 Enter 确认发送）：劫持游戏 Enter 不可接受——
  Enter 是游戏聊天框的开启/发送键，全局占用会破坏游戏本身操作；
  单键复用（Preview 态触发键 = 确认）是游戏场景的自然交互（v5 已验证）。
- **预览可编辑**：伪需求，见决策 4；连带消灭「编辑草稿同步」
  「overlay 键盘焦点」两类状态与 bug 面。
- **交互模式用三个独立开关配置**（begin/end/post 各自可选）：
  组合爆炸且无意义的组合居多（如 A1+B2），预设枚举 + 兼容推导更收敛；
  策略层内部仍按三决策点组装，未来新增取值不破坏配置 schema。
- **捕获录入用 DOM keydown**：WebView 焦点外按键收不到，且已注册热键
  会被 LL 钩子吞掉导致无法录入为同键；LL 钩子捕获与运行后端无关、
  行为一致。
