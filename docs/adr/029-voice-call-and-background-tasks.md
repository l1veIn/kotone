# ADR 029：像打电话一样和她说话——快回答、接着听、复杂的事交给子代理

状态：Accepted / 已确认（2026-11-20），实现中。调研与实测见 [2026-11-20 语音对话的及时性与连续性](../research/2026-11-20-realtime-voice.md)。修订 [ADR 022](022-sessions-memory-soul.md) 的子会话部分（见第三节）。

## 背景

0.2.0 的语音对话是照着 Coding Agent 做的：说完一句，等她想完、做完、整段合成好再念，念完就结束。玩家本机实测，说完到听见回答 15–35 秒，答完还要再按键或再喊名字才能接着说。玩家要的是 GPT 实时语音、豆包语音通话那样的手感：快，而且能接着聊。

游戏和纯 AI 语音通话也不一样：Kotone 有很多游戏工具（读聊天、发消息、提醒、自动化、操作游戏），复杂的事（例如“写一个看到某个画面就自动按键的脚本”）几十秒到几分钟才能做完，不能让她在电话里干等、也不能一直“嗯……稍等”。

## 原则：玩家只需要知道两件事

1. **填好 DeepSeek Key**；
2. **按呼叫键**（或喊她的名字）。

其余的都自动发生。界面上不出现“思考”“子代理”“工具调用”“后台任务”这些词，也不加需要玩家理解的设置：

| 玩家的直觉 | 自动发生的事 |
| --- | --- |
| 按一下，说话 | 她马上接话；不让玩家等她想（不思考、没出声前先接一句） |
| 她说完了，我还想说 | 不用再按，直接说（她答完会接着听 8 秒） |
| 她说得不对 / 不想听了 | 再按一下呼叫键：她马上停下，开始听你说 |
| 让她别弄了 | 说“停下”（和现在一样，停下一切） |
| 不聊了 | 不说话就行（8 秒后安静收起）；或者说“没事了 / 拜拜” |
| 让她办一件复杂的事 | 她说“交给我，好了告诉你”，你继续打游戏；做好了她主动说一句 |
| “弄好了没？” | 她报进度 |
| “刚才那个再改改” | 她接着改，记得之前做了什么 |
| 想看她具体做了什么 | 打开聊天窗口：同一段对话里有一张卡片，可以展开看过程 |

不做的（玩家决定）：

- **不判断“这句话是不是对她说的”**。GPT 实时语音、豆包通话也不判断；说错了玩家自己按一下呼叫键让她停。
- **不按局面调节奏**（团战时少说话等）：太复杂。

## 设计

### 一、玩家看得到的只有主会话

- **对话列表里只有主会话**。语音和打字是同一个“她”、同一段当前对话、**同一份简单工具清单**。
- **按呼叫键 = 接着聊窗口里当前那段对话**（和现在一样；ChatGPT、豆包的语音也属于你所在的那段对话）。停在“新对话”页面按呼叫键，就从这段新对话开始。
- 因为子代理不进列表，“当前对话”永远是主会话。这也消掉了现在的一个坑：选中子会话时按呼叫键，会悄悄新开一段对话（`agent.rs` 的 `agent_send`）。
- 一段对话从头到尾只有一份系统提示和工具清单，前缀缓存照旧命中（ADR 024 不变）。打字时可以照旧思考（思考是每次请求的参数）；语音回合不思考。

主会话的规矩：

- **只带“马上出结果”的工具**（标准：1–2 秒内、一步做完）：
  - 说话 / 弹幕、设提醒、往游戏聊天发一句、运行或停止已保存的自动化、切到或打开游戏；
  - **读你说话那一刻的屏幕**（见第二节）；
  - **交给子代理**、**问子代理进度**、**停掉子代理**。
  - 其余（写自动化、一步步操作游戏、改设置、联网查资料、写记忆和技能、听别的程序的声音）一律交给子代理。
- **语音回合**：不思考（DeepSeek `thinking: disabled`，推理内容永不念出来，照 Pipecat、xiaozhi、TEN 的默认）；回答一两句口语，细节等追问或放在聊天窗口（照 OpenAI 语音提示词指南）；每轮最多 3 步（照 LiveKit `max_tool_steps`）。
- **任何工具超过 3 秒没回来就转给子代理**（照 LiveKit 5 秒转后台），她说“这个要一会儿，好了告诉你”，然后接着听。

### 二、说话那一刻的屏幕

- 按下呼叫键、或唤醒词命中的那一刻，**截一张前台窗口的图**（几十毫秒），存起来；同时在后台开始识别图里的文字（有本地文字识别模型就用本地，约 0.3 秒；只有在线识别时也提前开始）。
- 回合开始时**不再等识别**（现在每次固定等约 12 秒）。只带窗口标题和程序名。
- 她需要看时调用“读你说话时的屏幕”：拿到的是那一刻的画面（聊天刷得快，不会读到后面的消息）；识别已经提前跑完就立刻返回。
- 要看**现在**的画面、或者一边看一边操作，交给子代理（`game.look` / `game.act`）。

### 三、复杂的事交给子代理

主会话用 `agent.start` 派子代理（完整工具清单见下面“照着开源实现做”），由运行时决定同步还是异步，模型不用分辨：

- **约 4 秒内做完**：主会话先说一句等待的话，拿到结果照着说。照 OpenAI 官方示例 openai-realtime-agents 的 Chat-Supervisor 模式（前台说一句“我看看”，交给更强的模型，拿回答案照念）。
- **超过约 4 秒**：主会话说“交给我，好了告诉你”，这一轮结束、接着听；子代理继续做。照豆包语音通话、LiveKit 后台工具、Pipecat 异步工具。

子代理是什么：

- **玩家看不到它是一段对话**。它在主会话里是一张卡片：“写喝药脚本 · 进行中 [停止]” → “已保存为自动化《自动喝药》→”。展开卡片能看它一步步做了什么（和工具卡片展开一样）。
- **能用几乎全部工具**，包括执行命令和读写文件（规则见 [ADR 030](030-subagent-shell-and-files.md)），可以思考（按聊天窗口的思考设置）。只少三样：不能直接对玩家开口（要说的话由主会话转达，弹幕可以发，同传就靠弹幕）；不能再派子代理（只有一层）；不能改自己的权限。
- **能接着干**：玩家说“把刚才那个脚本改成三成血”，主会话把这句交回**同一个**子代理，它记得之前做了什么。所以子代理的过程记录要存盘（续做、卡片里的“过程”、排查问题都用它），但这只是内部实现，不作为对话出现在列表里。
- **能中途发问**：需要玩家确认的事（运行自动化、操作游戏、改设置）经主会话开口问：“脚本写好了，现在运行吗？”玩家答完交回子代理。语音时复用现有的语音追问（`voice_ask`），打字时显示为确认卡片。
- **能常驻**：同传这类子代理一直跑，卡片显示“同传 · 正在听 [停止]”。
- **做完主动说**：结果交回主会话，由主会话用一句话说出来（不思考）。时机：玩家正在说话就等说完；她正在说话就排在后面；否则马上说。
- 玩家问“好了没”：主会话查进度回答。最多同时 3 个子代理；“停下”停掉全部（和现在一样）。

#### 照着开源实现做

读了三家的源码：OpenAI Codex CLI `15c5444`（Apache-2.0，Rust，子代理 V1 默认开、V2 `collaboration` 可选）、OpenCode `e51247f`（MIT）、Goose `ea5dded`（Apache-2.0，Rust），浅克隆在 `target/research/subagents/`。

| 要做的事 | 照谁 | 做法 |
| --- | --- | --- |
| 工具 | Codex V2 `spawn_agent` / `followup_task` / `interrupt_agent` / `list_agents`（`core/src/tools/handlers/multi_agents_spec.rs`）；OpenCode `subagent(agent, description, prompt, sessionID?)`（`core/src/tool/plugin/subagent.ts`） | Kotone：`agent.start {name, label, task}`、`agent.followup {name, message}`、`agent.list`、`agent.stop {name}`。`label` 是三五个字的卡片标题（照 OpenCode `description`）；`name` 是这段对话里稳定的名字，续做靠它。 |
| 不让主会话干等 | OpenCode：总是后台，立刻返回，工具说明里写“不要轮询，告诉玩家你派了什么，然后结束这轮回答”；Codex 有阻塞的 `wait_agent`（最长 1 小时），Goose 会卡住父会话的这一轮 | 主会话没有等待工具。`agent.start` 在运行时里最多等约 4 秒：做完了就把结果当工具结果返回（Chat-Supervisor 的体验），没做完就返回“在跑”，主会话说“好了告诉你”。 |
| 做完就是“空闲”，不是“结束” | Codex：完成的代理还活着，新输入在同一段历史上开新的一轮（`agent/control.rs:138-168`）；OpenCode：传 `sessionID` 就能续做，正在跑的会把新指令排进这一轮 | `agent.followup` 对空闲的子代理开新一轮，对正在跑的排进当前这轮。 |
| 闲置回收 | Codex V2：容量不够时按最近最少使用卸载空闲的子代理，留着未读消息，续做时自动从磁盘加载（`residency.rs`） | 同上，最多同时 3 个（Codex V2 默认也是除主会话外 3 个）。 |
| 结果回来 | Codex：`FINAL_ANSWER` 信封（约 1k token 上限），另发一条界面事件；OpenCode：子代理空闲时把最后的回答包成 `<background-result>` 插进父会话并**唤醒**它；Goose：默认要求子代理最后交一份 `{summary}` | 子代理最后必须交一份简短总结（照 Goose），包成一条带名字的“完成”消息插进主会话，并唤醒主会话说一句（照 OpenCode；Codex 的唤醒默认关，我们要开）。另发一条界面事件更新卡片。 |
| 先存盘再交付 | OpenCode：报告先写进待发件箱（崩溃恢复），只有明确取消才停子代理，关程序不算 | 照做。重启后不自动重跑被打断的子代理（Codex 的测试明确要求），卡片显示“中断了，要继续吗”。 |
| 被打断不报给模型 | Codex：被打断的子代理不给父会话发通知；出错和被拒绝时附上下一步建议 | 照做。 |
| 不能对玩家开口 | Codex：`request_user_input` 只有主线程能用（`tools/handlers/request_user_input.rs:67-71`） | 子代理不能说话、不能直接问玩家；要问的经主会话问。 |
| 确认请求 | Codex、OpenCode：子代理的确认请求带着子代理的 ID 直接出现在界面上（OpenCode 沿会话树找，`session-request-tree.ts`）；Goose 换个 ID 转发进父会话的流 | 打字时照 OpenCode / Goose 显示在主会话里；语音时由主会话开口问（这是我们和它们不同的地方）。 |
| 只有一层 | Codex V1 默认深度 1（超了提示“自己做”）；OpenCode 默认 1；Goose 不允许 | 子代理里不提供 `agent.*` 工具。 |
| 步数上限 | OpenCode：到 `steps` 上限时关掉工具、要求总结（`MAX_STEPS_PROMPT`） | 照做，不默默失败。 |
| 权限 | Codex：子代理照抄父会话的权限策略，角色只能收窄（`agent/role.rs`） | 照做。 |
| 玩家能不能点进去 | Codex、OpenCode、Goose 都能打开子代理那段（只读） | **不能**，只有卡片和展开的过程（玩家决定，见第一节）。 |

和 Claude Code 那种一次性子代理的差别：能接着干、能常驻、能中途经主会话发问。和 ADR 022 现在的子会话的差别：

| | 现在的子会话（ADR 022） | 子代理 |
| --- | --- | --- |
| 玩家看得到 | 对话列表里一段对话，标“子” | 不进列表，只是主会话里的一张卡片 |
| 派出去 | `session.spawn` 等它第一轮做完才返回 | 立刻返回（4 秒内做完就当同步结果） |
| 工具 | 禁止写自动化、操作游戏、改设置、写记忆、问玩家 | 几乎都能用，要确认的经主会话问 |
| 做完 | 父会话没在回答时只记下 | 主会话主动说一句 |
| 后续 | 玩家选中它发消息会新开一段对话 | 玩家对主会话说，主会话交回同一个子代理 |

界面和文档里不再出现“子会话”这个词。

### 四、等待时说什么

- **预先生成一组短句**（照 xiaozhi 的唤醒应答缓存）：填好 Key、换音色、换角色时，在后台用当前音色合成好存在本地，按音色区分；用掉一句就在后台换一句新的；带一个内置兜底音频；系统语音直接用内置音频。分两类：应答（“嗯？”“我在”）、等待（“我看看”“稍等哈”“让我想想”）。
- **规则**（照声网 `response_wait_ms`）：约 1.2 秒还没出声就播一句等待短句；**每轮最多一句**；回答先到就不播。
- 模型在交给子代理、读屏之前可以自己说一句短话（提示词里写明：每次说法不同，快工具不说）。
- **不会一直重复填充**：长任务直接交给子代理，“好了告诉你”。

### 五、接着听与打断（半双工）

- 她念完就开麦等 **8 秒**：开口就接着这段对话；没开口就安静收起。照 xiaozhi `auto` 模式、Pipecat 唤醒后 10 秒窗口。
- 她说话时不收音（所以开着音箱也不会录到她自己，不需要回声消除）。
- **她说话时按呼叫键 = 打断并开始听**：停掉合成、模型和播放队列，对话记录只留已经念出来的部分（照 OpenAI `conversation.item.truncate`、LiveKit、Pipecat）。喊唤醒词同理（唤醒检测在她说话时继续跑）。
- 说“没事了 / 退下 / 拜拜”：她不再接着听（照 xiaozhi 的退出词）。
- 气泡上显示还在听的倒计时，玩家一眼知道现在说话她能不能听到。

### 六、边生成边念

- 模型的文字一到就分句：第一句可以在“，、”处切（更快出声），之后在“。？！；：”处切，不在引号里切（照 xiaozhi `core/providers/tts/base.py`）。
- DeepSeek 语音用官方的流式接口（`wss://api.deepseek.com/v1/tools/tts`，分段发文字、边收音频边播）；其他语音引擎按句合成、排队播放。
- 实测 DeepSeek 流式接口收到 `finish_text` 之前不出声，所以**每句一路会话**，总是提前连好下一路，最多同时合成 2 句（`kotone-tts` 的 `SpeechStream`）。
- **每次调用模型一路**：这一轮开始前就把第一路准备好（握手藏在模型想第一句的时间里）；工具前那句（“我查一下”）也是边写边念；工具在跑时把下一路准备好。推理文字永远不念。
- **不叠音**：第一段正文到了才排进播报（和提醒、等待短句共用一把锁）。前面在播等待短句时只合成、不出声，播完立刻接上；回答开口了就不再播等待短句；麦克风开着时不出声（同提醒）。
- **打断**：按呼叫键、喊唤醒词、开始收音、说“停下”，都马上停（等输出设备关掉才开麦）；对话里这条回答只留念完的句子，后面加“（被打断）”，模型下一轮知道玩家没听到后面（照 LiveKit `_truncate_message`）。这段对话还在跑时等下次存盘再改，不会被这一轮的存盘盖掉；聊天窗口收到 `revised` 事件后重新读。
- 气泡跟着念到的句子更新；弹幕（关了气泡，或开了“回答同时用弹幕”）照旧显示整段。**念完（真正播完）才开始接着听。**
- 费用：每句合成前按这句的文字认领到这一轮，账本里每句一行，都记在这一轮下面。
- 退路：回复方式里没有语音、流式语音准备不起来、或模型用了 `reply.say`（她已经开口说过），这一轮剩下的照旧整段念；回答一句也没念出来（例如流式连接出错）就整段再念一次。

### 七、计时

每个语音回合记下：说完 → 识别出字 → 模型第一个字 → 第一句出声，写进日志（照 LiveKit 的指标）。之后的调整都看这组数字。

## 分期

| 期 | 内容 | 预计效果 |
| --- | --- | --- |
| 一 | 二（说话那一刻截屏、不再等识别）、语音回合不思考和短回答、四（预生成等待短句）、五（接着听 8 秒、按键打断）、七（计时） | “你好”从 15 秒到约 3 秒；答完能接着说 |

| 以后（可选） | 通话模式：一直在听、直接开口打断（要回声消除，`sonora` 或 Windows 语音捕获 DSP；注意通信音频流默认把游戏音量压低 80%） | 戴耳机的玩家前三期就够用 |

## 要先验证的风险

1. **只有在线文字识别的玩家**：提前识别仍要约 12 秒，问到画面时还是慢。可以在引导或语音输入里推荐下载本地文字识别模型，不自动下载。
2. **子代理操作游戏**：玩家正在玩，子代理去动鼠标键盘会抢手。沿用 ADR 019：每段对话第一次操作前先问，并且经主会话开口问。
3. **两层模型调用的开销**：复杂任务多一次主会话的模型调用（很短、不思考），费用和时间都要看第二期的计时数据。
