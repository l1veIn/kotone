# ADR 046：程序里调工具；英雄联盟报每一次阵亡，这一局的数据用工具拿

状态：Accepted（2026-11-27，玩家定的方向；细节由主会话照规划代理的设计定）。

修订：[ADR 038](038-kotone-and-apps.md) D2（“动作可以调用任意插件的工具”在这里实现；“保存时问玩家一次”改成 D3）；[ADR 040](040-hotkeys-belong-to-core.md) 第 3 期（热键和自动化共用一份调工具的代码）；[ADR 045](045-automation-is-programs.md)（函数清单多一个 `tool`）。

## 背景

ADR 045 之后，自动化的动作就是程序，通知、交给她都是程序里的函数。但 ADR 038 写的“自动化可以调用任意插件的工具”一直没做：程序能听插件报的游戏事件，却调不了插件。玩家的话：

- “可以，那这个缺口确实需要补上。这个事件不监听是因为插件没提供对吧？有没有办法向插件下发‘自定义事件’？或者其他方式，来监听‘队友死了我活着’这种奇葩事件?”
- “这样我们得设计一个完整的death事件，我在想，这里是不是还可以在每个事件过来直接带上全部的比赛参数？我们脚本自由度会更高？”
- 主会话建议事件保持小、整局数据做成只读工具让程序去拿之后：“很合理，用工具获取再合适不过了。”
- 验收场景：“检测到队友都死掉了（我还活着），播放BGM”。

定下的分法（照 Home Assistant）：**插件报事实，判断在自动化**；**事件说“刚发生了什么”，状态随时用工具查**。不做“往插件下发自定义事件”（那等于每个插件里再造一个自动化引擎）。

## 决定

### D1 程序里调工具：`tool(name, args)`

- 写法：`local r, err = tool("lol.match")`、`tool("music", { action = "play", query = "…" })`。`name` 直接写成字符串；`args` 是表或不写，≤4 KB。
- 等工具回来，最多 30 秒；两次至少隔 1 秒，太快自动等；停下就跟着停（正在等的那次记成已取消）。
- 返回工具给程序的数据：有结构化结果（structuredContent）用它，没有用给她的那份内容，转成只读的表（最多 8 层、256 KB）。
  - 工具自己说没成（插件返回错误、工具服务 ok=false、超时）→ `nil, 原因`；
  - 调不了（不在 D2 的范围、D3 不让、插件关着、程序里没写这个名字）→ 程序出错结束，执行记录写原因。
- 会调哪些工具按源码列出来（和“用到游戏窗口”用同一个记号器）。工具名不是直接写的字符串（变量、拼出来的）就不让存、不让跑：“tool() 的第一个参数要直接写工具名”。运行时名字不在单子上就报错。
- `tool` 不算用到游戏窗口。

### D2 能调的工具 = 热键能绑的工具，再去掉三类

| 去掉 | 为什么 | 例子 |
| --- | --- | --- |
| 自动化自己的工具 | 不让程序运行、改、停自动化（会绕圈、能绕过确认） | `automation.run` / `save` / `stop` |
| 往游戏里打字、按键的 | 程序自己有 `chat` / `key` / `click`，按键只有一套规矩（绑窗口、输入锁、名额） | `game_chat.send`、`lol.shout`、`game.act` |
| 结果不可信又只读的 | 程序拿不到结果（D4），调了只是白花时间和钱 | 在线文字识别、读聊天、`game.look`、`lol.scout` |

她对话里才有的东西（说话、问玩家、交给后台、联网搜索、浏览器、执行命令、记忆、`saved.*`）本来就不在热键能绑的范围里。

### D3 权限照常；要问的，在「自动化」页确认一次

- 判定和热键同一个：允许 → 能调；禁止，或只读模式下有副作用的 → 不能调；先问 → 这个自动化确认过才能调；插件或它的数据开关关着 → 不能调，说清要打开哪个。
- 确认记在自动化定义上（`confirmed: {工具: [当时的副作用]}`），只有 Kotone 窗口能写：编辑器里存的时候点“允许并保存”；她或外部 Agent 存的标“等你确认”，玩家点“允许”（确认时核对是不是玩家看到的那份程序）。
- 确认的是“这段程序可以调这些工具”，不是某一次的参数。程序一改就作废（谁改的都算）；只改名字、参数、触发不动它；工具后来多了副作用、第三方插件的配置变了，要重新确认（和热键一样）。
- **等你确认的自动化，确认之前完全不运行**（▶、热键、游戏事件、定时、她都起不来，说清原因），免得只做一半（话说了、歌没放）。
- 临时程序（她和外部 Agent 的 `automation.run {source}`）只能调“允许”的工具；要确认的，先存起来让玩家确认。
- 运行中每次 `tool()` 再判一次（规则可能刚改过）。

### D4 数据不是指令：程序拿不到别人写的字

结果标了不可信的工具（里面有玩家名、歌名、网页、第三方插件的内容），程序只拿得到 `{ status = "…" }`（结果里的 `status` 是小写英文词就带上，否则 `"ok"`）；没成时 `nil, "没成"`，具体原因只记进日志。这和 `ocr()` 只能问“有没有这段字”是同一条规矩；`ask()` 的护栏照旧，不加新规矩。

### D5 她运行已保存自动化的副作用按程序算

`saved.<id>` 的副作用不再写死成“按键、截图、说话”：用到游戏窗口 → 按键、截图；说话、弹幕、推送 → 显示或说出文字；`tool()` 调的 → 那些工具的副作用。结果：只读模式下她能运行只说一句的自动化了；会按键、会放歌的照旧不行。

### D6 `lol.death`：每有一个英雄阵亡报一件

- 以 `isDead` 由假变真为准（和现有的“我阵亡了”、阵亡卡片同一个判断），同一段时间里这个人的 `ChampionKill` 补上击杀者。人按名字、Riot ID、`summonerName` 对，隐藏了身份的人也对得上。
- 每局第一份数据只记样子，之前的不补；中间没读到接口那段死了又复活的不补；看不出自己在哪边（观战）时不报。
- 同一份数据里死了几个：按击杀时间排，一人一件，人数是“这一个死了之后”的，所以“最后一个队友倒下”只有那一件满足 `alliesAlive = 1`。
- 字段：`team`（死的是哪一边 `ally` / `enemy`）、`champion`、`me`（是不是自己）、`killer`（击杀者的英雄；塔、小兵、野怪或对不上时为空）、`respawnSeconds`、`alliesAlive`（含自己）、`enemiesAlive`、`meAlive`。
- 插件每 2 秒读一次局内数据，从阵亡到触发最多晚约 2 秒。守护天使、基兰大招不算阵亡；赛恩被动、艾尼维亚的蛋、扎克被动照接口算活着；佛耶戈附身时阵亡，`champion` 用这局第一次看到他时的英雄。

### D7 旧事件保留，报法合并

`lol.my_death`、`lol.my_respawn`、`lol.ace` 都留着、字段不变（已存的自动化照样触发）；“我阵亡 / 复活”改由报 `lol.death` 的同一处报，删掉单独的那套判断。

### D8 这一局的数据：`lol.match` 多给一份结构化数据

不新加 `lol.live`：现有的 `lol.match` 本来就返回这局 10 个人的英雄、等级、KDA、补刀、装备、召唤师技能、死没死、复活秒数，只是没有给程序用的结构化数据，而且文字里带玩家名（所以整个工具标成不可信）。改成：

- 给她的文字照旧，只去掉玩家名（要名字和战绩她用 `lol.scout`）；工具改成可信。
- 结构化数据（字段名就是约定，写进工具说明；camelCase，和事件数据一致）：顶层 `status`、`reason`、`mode`、`gameTime`（整数秒）、`score {ally, enemy}`、`alive {ally, enemy}`；`players[]`：`champion`、`alias`、`team`（ally / enemy）、`me`、`bot`、`level`、`kills`、`deaths`、`assists`、`cs`、`dead`、`respawnSeconds`、`position`、`spells[{key, name, readyAt?}]`、`items[{id, name}]`。
- 需要“读客户端数据”开关；不在对局里：`{status: "not_in_game", reason: loading | champ_select | not_in_game | client_closed}`。
- 接口给不出的不放：别人的金币、技能冷却、海克斯。

### D9 界面（最小）

编辑器程序下面一行“会调用：放歌（music）……”；要确认的写出原因、存的按钮变成“允许并保存”；调不了的写原因。列表上“等你确认”“用不了”小标记，点开就是同一块确认区。她存了要确认的，保存结果带 `needsConfirm`，她告诉玩家去「自动化」页点允许。

## 主会话替玩家定的（规划留的五条，照推荐）

1. 这局的数据并进 `lol.match`，不新加 `lol.live`（D8）。玩家看得到的代价：她讲这局情况时不再带玩家名。
2. 等你确认的自动化确认之前完全不运行（D3）。
3. 往游戏里打字的工具（一键喊话）程序里先不让调（D2），喊话用热键或程序自己的 `chat()`。
4. 玩家自己改了会调“要确认的工具”的程序，存的时候也要再点一次“允许并保存”（D3：改了程序就重新确认）。
5. “队友都倒了放首歌”不做成内置自动化：玩家说一句她就写好。

## 加的 / 删的

- 加：`tool()`；自动化上的确认和「自动化」页的“允许 / 允许并保存”；`lol.death`；`lol.match` 的结构化数据。
- 删：英雄联盟插件里单独的“我阵亡 / 复活”判断；`lol.match` 文字里的玩家名和它的“不可信”标记；`saved.*` 写死的副作用；热键和自动化各写一份的调工具代码（合成一份）；ADR 038 D2 的“保存时问玩家一次”（改成 D3）。
- 刻意没加：“调过不可信工具就不能 ask”这类跟踪规则；调用次数上限、花钱工具的单独规矩；“调了打字类工具也算用到游戏窗口”；新的数据工具名。
- 不变：用不用游戏窗口的判断和它带的规矩、名额、停下、`ask` 的护栏、每局叫她 3 次、文件版本号 1。

## 验收场景

“队友都倒了放首歌”：

```json
{
  "name": "队友都倒了放首歌",
  "params": [{"name": "song", "label": "放什么", "type": "text", "maxLength": 100, "default": "Legends Never Die"}],
  "action": {"kind": "program", "source": "local r = tool(\"music\", { action = \"play\", query = args.song })\nif not r then\n  log(\"没放成\")\nelseif r.status == \"need_login\" then\n  toast(\"网易云音乐还没登录，没放成\")\nend"},
  "on": {"event": ["lol.death"], "game": "lol", "match": {"team": "ally", "meAlive": true, "alliesAlive": 1}, "cooldownSeconds": 60}
}
```

不用游戏窗口、不会叫她；`music` 的副作用（放媒体）默认允许，不用确认。`match` 里的 `team: "ally"` 不能省（省了的话，只剩我活着时对面再死一个也会触发）。放歌会替换正在放的那首。

## 实现情况

分四步提交（2026-11-27，分支 `claude/automation-functions`）。玩家同一天自己做的自动化活动首页、本机游戏详情页（`e71cd75f`）在第 3 步之前，第 4 步的界面加在它上面。

**第 1 步 英雄联盟插件（`24761cca`，D6–D8）**：`lol.death` 以 `isDead` 由假变真为准，同一份数据里的 `ChampionKill` 补击杀者，`who()` 认 `summonerName`（隐藏身份的人也对得上）；一份数据里死几个按击杀时间排、人数逐个递减。`lol.my_death` / `lol.my_respawn` / `lol.ace` 保留、字段不变，改由报 `lol.death` 的同一处报，删掉单独的那套判断（`lol.my_death` 的 `respawnSeconds` 从 `12.0` 变成 `12`）。`lol.match` 给她的文字去掉玩家名、工具改成可信，`structured_content` 是给程序的结构化数据（没有页面，不进她的上下文、不出卡片）。新加 6 个测试。

**第 2 步 规则（`8af29601`，D1–D5）**：脚本引擎的 `tool(name, args)`（`ScriptHost::tool` → `ToolReply`；两次至少隔 1 秒、参数 ≤4 KB、结果转只读表，超过 8 层 / 256 KB 回 `nil, 原因`）。core：`tools_called` 和“用到游戏窗口”用同一个记号器，名字不是直接写的报错；保存时拒 `automation.*` / `saved.*`；`Automation.confirmed`（草稿带它直接拒；`AutomationLibrary::confirm` 核对玩家看到的程序，和以前的合并、去掉不再调的；程序一改就清掉；`forget_confirmations` 按前缀清）；`program_view`（不可信工具只回 `status`）。她的权限：`program_callable`（D2 三类，第三方插件自称只读的也算只读）、`program_decision`（照热键的 `binding_decision`；临时程序遇到要确认的就是不能调）；`saved_entry` 的副作用按程序算（D5）。新加 15 个测试。

**第 3 步 桌面端（`aa09a32c`）**：`tool_call.rs` 从热键里抽出“按来源调工具”，热键和程序共用一份（`Caller::Hotkey` 改名 `Caller::Automation`，判法不变）；`DesktopHost::tool`（名字在单子上、权限和插件开关、确认只在存着的程序没变时算数、30 秒和停下、不可信只回 `status`）；`ToolRules` 安排时查一遍（等你确认的、调不了的不运行：▶ 和热键说原因、她拿到错误、游戏事件和定时只记日志）；对外的定义不带 `confirmed`，改成 `tools[{name, title, state, reason}]` 和 `needsConfirm`；命令 `automation_save(draft, confirm)`、`automation_confirm(id, source)`、`automation_tools(source, id)`；第三方插件的配置变了清掉确认。验收场景写成了测试（最后一个队友倒下、我还活着时放歌，别的情况不触发）。新加 11 个测试。

**第 4 步 界面、她和文档（这个提交）**：
- 界面（D9）：编辑器改程序时防抖 0.3 秒查一次 `automation_tools`，程序下面一行“会调用：放歌（music）……”（工具说明的第一句截到第一个括号或逗号前，短的中文写成“放歌（music）”，英文说明、太长的只写工具名；完整说明在鼠标悬停里）。有要允许的写出原因、存的按钮变成“允许并保存”；点的时候“会调用”还没跟上刚改的程序，就先算一遍，要允许的工具变了就停下给玩家看，不替玩家没看到的工具点允许。调不了的写原因，照样能存。列表上“等你确认”“用不了”两个小标记，点开是同一块（新组件 `ProgramTools.svelte`）：等你确认的先读一份程序显示出来，“允许”把这份交给 `automation_confirm` 核对（这期间被她改了就不认，重读一份）；等你确认的 ▶ 不运行，直接点开这一块。活动首页最上面加一栏“等你确认”（写着要允许什么），点开跳到程序库里它那一项；“已启用的触发规则”的行也带两个小标记。没加页面、没加模板。浏览器预览照后端的规矩算 `tools[]` / `needsConfirm`，测试可以在页面加载前放 `window.__kotoneAutomationSeed` 当作她存的。
- 她的规矩（共用规矩一条）：`tool("名字", {…})` 名字直接写、没成回 `nil` 和原因；调不了的三类（用 `chat()` / `key()`）；结果里有别人写的字的工具程序只拿得到 `status`；要确认的工具试运行调不了，先存起来；保存结果里 `needsConfirm` 是 true 时告诉玩家去「自动化」页点“允许”。
- **确认过的不问两次**（主会话定的）：她运行 `saved.<id>` 时，程序里玩家在「自动化」页允许过的工具（确认时的副作用盖得住现在的，和热键、宿主同一个认法），默认要问的副作用换成新的 `runs-confirmed-tools`：默认允许，聊天里不再问一遍；不算只读，只读模式照样拒；玩家把这个自动化设成先问我、禁止照常；默认允许的副作用（放歌的 `plays-media`）原样留着。确认过时了的、没确认的照旧问（问了也只是到安排时被“要先在「自动化」页点允许”拦下）。
- 工具说明（`catalog_host.rs`）：`automation.run` 的函数清单加 `tool(name, args)`（名字直接写、30 秒、两次隔 1 秒、停下取消、`nil, reason`、不可信只回 `{status}`、调不了的范围、权限和「自动化」页的允许、临时程序只调不用确认的、改程序作废、查不过不开始）；`save` / `get` / `list` 写 `tools[]` 的四种状态和 `needsConfirm`，不提 `confirmed`。
- 测试：`kotone-agent` 新加 1 个（允许过的工具她运行时不问；只读照样拒；过时的、确认的是别的工具、没确认的照常问；玩家设的规则照常；默认允许的副作用不换），改 1 个（系统提示里的规矩）；`kotone-tools` 改 1 个（自动化工具的说明）；Playwright 新加 1 个（她存的显示“等你确认”、首页最上面也有，点允许后都没了、▶ 能运行；改了程序按钮变“允许并保存”，改回原样又是“保存”；名字不是直接写的存不进来；调不了的标“用不了”、▶ 说原因）。`cargo test -p kotone-agent -p kotone-tools` 118 + 114 个全过；clippy 没有警告；Playwright `automation`、`terminology`、`game-profile`、`plugin-events`、`plugin-risk`、`sidebar-edit`、`hotkeys-*`、`lol-plugin` 共 43 个全过。
- 文档：本节；ADR 038 D2、040 第 3 期、045 的修订说明；ADR 目录；术语表“确认”“自动化”；`docs/tool-service.md`（程序里的 `tool()`、`automation.*` 的 `tools[]` / `needsConfirm`、`lol.match` 的结构化数据和不带玩家名）；`docs/assistant.md`；`CHANGELOG.md`。
