# ADR 045：自动化只剩程序；说一句、推送、交给她都是程序里的函数

状态：Accepted（2026-11-27，玩家定的方向；细节由主会话照规划代理的设计定）。

修订：[ADR 013](013-automation-domain-model.md) §2（动作只剩程序）、§3（一个调度器只剩程序循环）、§4（名额、停下）；[ADR 036](036-game-state-and-events.md) D6（`mode`）、D8（“让她做”变成 `ask()`）；[ADR 043](043-plugin-shape-and-pushes.md)（推送不再只属于插件）；[ADR 040](040-hotkeys-belong-to-core.md) 第 3 期 P2（热键运行自动化成功时不出声也不弹）。

## 背景

玩家测试自动化时发现，用热键运行自动化每次都会弹一条弹幕。那是宿主自己加的“成功了”提示。玩家的话：

- “无论是弹幕还是语音，甚至是类似插件的发送到chat，都是工具或者函数，让脚本内部自己决定要不要发送弹幕或者语音通知，或者发送个卡片到chat？”
- “现在插件可以发送自己的界面ui到chat。我觉得要不给自动化一个工具？就是推送信息，记进聊天但是不调用模型，跟chat()不一样。”
- 主会话解释“说一句”“让她做”也可以变成程序里的函数、自动化只剩一种之后：“你说的我懂了，我觉得没问题，都做成函数，固有配置就可以轻松一些。”

自动化的位置不变：它是本体里比插件高一层的固有功能（ADR 038，照 Home Assistant：触发在本体，动作调用本体和各插件的本事），不降成插件。要统一的只有“往聊天里放东西、不调用模型”这一条路，自动化和插件都走推送；她开口说、弹幕、发到游戏聊天是不同的出口，不合并。

在这之前，自动化的动作有三种（播报、程序、让她做），每种有自己的校验和执行路径：播报有自己的投递循环、`{参数}` 占位、投递方式字段、只能用简单参数；“让她做”不能有参数、每局 3 次挂在动作种类上；所有程序都要绑游戏窗口。

## 决定

### D1 动作只有程序

定义的 `action` 只有 `{kind: "program", source}`。读旧写新：读到 `speak` / `prompt`（`~/.kotone/automations.json`，或工具 `automation.save` 收到的旧写法）时转成等价的程序再存：

- 播报 → 字符串拼接：`"该{text}了"` + 语音 → `say("该" .. args.text .. "了")`；数字参数 `tostring(...)`，开关参数 `(args.x and "是" or "否")`，和以前的显示一致；只要语音 → `say(X)`，只要弹幕 → `toast(X)`，两者都要 → `say(X, { toast = true })`。
- 让她做 → `ask("…")`（正确转义）。
- 内置的“X 秒之后提醒我”“英雄联盟进加载界面播报突破口”新装时直接是程序；老用户装过的照上面转换；删过的不装回。

文件 `version` 还是 1：rc.13 认得 `program`，读新文件不出错（跑到 `push` / `ask` 时报“没有这个函数”）。

### D2 通知、交给她都是程序里的函数；不写就安静

| 函数 | 去哪 | 说明 |
| --- | --- | --- |
| `say(text, { toast? })` | 她开口说 | ≤300 字；阻塞，排进她的输出队列；麦克风开着先等、语音失败改弹幕（和以前的提醒一样）；最多 240 秒；停下就跟着停。`toast = true` 时语音和弹幕同时出现 |
| `toast(text)` | 弹幕 | ≤300 字；不阻塞 |
| `push(text)` | Kotone 聊天里记一条 + 悬浮窗显示一行 | ≤40 字；走插件推送同一条路，不调用模型、不出声；两次至少隔 1 秒；她之后在对话里看得到（附一条不叫模型的说明，和插件推送一样） |
| `chat(text, { channel })` | 游戏里的聊天框 | 已有，经“发到游戏”入口（ADR 041） |
| `ask(text)` | 交给她（主会话） | 就是以前的“让她做”：等她空下来（最多 2 分钟），作为系统消息放进主会话，附上触发它的游戏事件；每次花一次 AI 调用。只在保存的自动化里能用；话里不能带从游戏事件填进来的参数值（别人起的名字不能进指令的位置）；按游戏事件触发时每个自动化每局最多叫她 3 次 |

宿主不再替自动化加“成功了”的提示：热键运行自动化成功时不出声也不弹（没运行起来照旧开口说原因，那时程序没机会自己说）。调工具的热键照旧弹一行工具返回的结果。

### D3 提醒是“晚一会儿开始、只说一句”的程序

她的提醒工具、0.1 升级上来的旧助手、0.1 提醒导入都生成同一种程序（`say(args.text)` / `toast(args.text)` / `say(args.text, { toast = true })`）。旧执行记录里的播报在打开文件时全部换成这种程序（已结束的作为历史）。调度器只剩程序循环；以前播报循环保证的东西改由 `say()` 保证：一次只投递一条（她的输出队列）、240 秒上限、取消后等壳收尾（最多 5 秒）、语音与录音互斥、语音失败改弹幕、0.1 的提醒用旧语音引擎。

### D4 用不用游戏窗口，看程序里写了什么

程序里出现按键、打字、发到游戏聊天、鼠标、看屏幕、`game_focused` 这些函数名，就算“用到游戏窗口”（按源码保守判断，宁可多算；注释和字符串里的不算）。

- 用到的：规矩全部照旧——安排时前台要是允许自动化输入的游戏并记下这个窗口；到点时窗口要还在、她没在操作游戏；游戏不在前台就暂停；窗口关了就结束。
- 没用到的：不看前台、不绑窗口，不会因为窗口没了失败或被停，不挡她操作游戏。
- 兜底：窗口函数在没绑窗口的执行里一调用就报错，不进暂停等待。

### D5 名额：同时最多 3 个绑了游戏窗口的执行在跑

其余执行只受“等待中 + 运行中最多 100 条”限制。提醒不会因为有 3 个按键宏在跑而失败。

### D6 停下：行为不变

停掉全部运行中的执行；取消等待中、**用到游戏窗口**的执行；等待中的提醒（不用窗口的）留着，单条在「自动化」页取消。原因：“停下”不只是停止热键，玩家说“停下”打断她、按 Esc 停她操作游戏也走这里，不能顺带悄悄取消“5 分钟后提醒我买眼”。

### D7 延迟是触发的属性

工具有 `delaySeconds`；任何自动化声明了数字参数 `delay_seconds`，运行时就晚这么多秒开始，两者相加，合计不超过 7 天（以前只对播报有效，现在对所有自动化有效）。

### D8 游戏事件触发

`mode`（single / restart / queued）只对用到游戏窗口的程序生效，不用窗口的每次触发都跑（和以前的播报一样）。触发它的事件随执行记录保存，供 `ask()` 附上；对外只露事件的 `type` 和 `game`。

### D9 界面

编辑器没有动作种类的选择。新建时选模板：说一句 / 推送一条 / 让她做 / 空白程序（按键类已经有 7 个内置程序，复制它们）；程序默认折叠，玩家多半只填参数。新的“说一句”不再支持 `{参数}` 写法（旧的转换时已经变成拼接）；要用事件里的字，让她写或改程序。“用到游戏窗口”“会叫她”由后端算好给界面；▶ 只对用到窗口的先倒数。

## 删掉的规矩

- 动作三选一，以及各自的校验：播报参数只能是简单类型、`{参数名}` 占位、`delivery` 字段；“让她做”不能有参数。
- 播报循环和它带的一整套：一次一条的投递管道、单独的超时和取消收尾、`ReminderDelivery` 端口、`schedule_speak`、“投递中”的单独恢复文案。
- “程序都要绑窗口”：只说话的程序不再要求前台是游戏，不占名额，不挡她操作游戏。
- 两个“按动作种类”的特例：`mode` 只对程序生效、每局 3 次挂在“让她做”上，改成看程序里写了什么。
- 界面：动作种类切换、播报内容框、回答方式勾选、“让她做”输入框、执行记录里的播报标记。
- 热键运行自动化成功后的那条弹幕。

## 加的

`push`、`ask` 两个函数，`say` 的 `{ toast = true }`；“用到游戏窗口”的判断和窗口函数的兜底报错；`ask` 的两道护栏；`delay_seconds` 推广到所有自动化；4 个模板；执行记录的 `event` 字段。

## 不变的

最多执行一次、错过不补、绑定窗口（对用到窗口的）、人随时能停、单次最长 30 分钟、最多安排在 7 天内、等待中 + 运行中最多 100 条、执行记录最多 1000 条。

## 代价

- 旧的“播报”自动化显示成一小段程序；要改说的话得改程序里的字，或者让她改。
- 只用弹幕的提醒在独占全屏下弹不出来时，记录里不再标成失败（原因写进日志）。
- 装回 rc.13 以后，新版本安排的、还没到点的提醒在旧版里会失败（“没有记录目标窗口”）。
