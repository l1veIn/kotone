# ADR 035：英雄联盟工具——这局的玩家、战绩和召唤师技能

状态：Accepted（2026-11-23）。玩家看过草案后改了三处（D4、D5、D6），原话：“我们是开源软件，感觉没必要这么谨慎啊，既然有其他开源项目做，我们也可以做啊，最多加点提示”“召唤师技能直接无视风险尝试从 API 读取，战绩也是直接查全部战绩，隐藏战绩的玩家还要特别标出来”。其余按草案。

## 背景

玩家（2026-11-23）想这样用：

- “琴音，帮我查一下这把游戏选手们的战绩，告诉我对面谁是突破口。”
- “琴音，帮我记录一下对面的召唤师技能。谁没闪？帮我发在聊天框。”

并且“可以添加一系列英雄联盟的工具。后续可能会有工具管理的问题出现，后面再说”。以后还要加给建议用的数据：BP 胜率和克制、海斗的海克斯数据，见“以后”。

在这之前，她只能做两件事：看屏幕（`screen.at_speech`），往聊天里打字（`game_chat.send`）。她不知道这局有谁、谁带了什么技能，也查不了战绩。

调研和实测见 [`docs/research/2026-11-23-lol-live-data-akari.md`](../research/2026-11-23-lol-live-data-akari.md)。要点：

- 局内有 Riot 官方的只读接口 Live Client Data API（`127.0.0.1:2999`），能拿到 10 个人的英雄、召唤师技能、等级、KDA、装备、游戏时间和事件。**国服实测：26 个接口都没有冷却字段。**
- 客户端本地接口 LCU 有这局 10 个人的 puuid、战绩和段位。端口和令牌从 `LeagueClientUx.exe` 的命令行读，**国服实测不用管理员就能读**。还有客户端自带的中文游戏资料（`/lol-game-data/assets/v1/…`）：英雄的称号、名字和英文 id，召唤师技能和基础冷却，装备，以及海克斯（`cherry-augments.json`，海斗的以 `ARAM_` 开头）。
- 战绩很快：自己最近 20 局第一次约 1.5 秒，之后约 20 毫秒；单局详情约 20 毫秒。海克斯大乱斗的队列 id 是 2400，战绩里每局记着 `playerAugment1–6`。
- 风险（已经告诉玩家，玩家决定照做、加提示）：
  - Riot 25.17 起限制第三方的召唤师技能冷却计时；
  - LeagueAkari 2025-07 起声明不支持国服，有封号和发战绩被禁言的报告。

## 参考了谁

- **LeagueAkari**（MIT，`dev` 分支）照着写的部分：
  - 从命令行读端口和令牌；
  - 对局阶段；
  - LCU 的战绩、段位接口；
  - 局内用 `teamParticipantId` 看谁开黑；
  - 手动召唤师技能计时：冷却 × 100 / (100 + 急速)，大乱斗和海斗的急速是 70，无限火力是 300。

  只照 MIT 的版本写，不拷 v1.3.x–v1.4.3（GPL），不碰它的预编译 `.node`（选人阶段反匿名）。
- **RiftStats / hh-lol-prophet / Porofessor**：参考了大乱斗以伤害为主的评价方式，以及连败、第一次玩、绝活这些标签。这几个项目的许可证没查，只参考思路，没拷代码。

## 决定

### D1 数据从哪来

- **Live Client Data API（局内）**：官方接口，只读，不用令牌。
- **LCU（客户端）**：只发 GET。读这些：对局阶段、这局的 10 个人、战绩、段位、中文游戏资料。
- **不做**：
  - 不直接请求腾讯或 Riot 的服务器（SGP），实测 LCU 已经够快；
  - 不在选人阶段还原被隐藏的名字；
  - 不读游戏内存；
  - 不往客户端写东西。往聊天发字仍然只走已有的 `game_chat.send`。

### D2 一组 `lol.*` 工具，先做三个

| 工具 | 例子 | 给什么 |
| --- | --- | --- |
| `lol.match` | “对面谁没带闪”“谁没闪”“现在几比几”“对面 AD 出了什么” | 模式、游戏时间、比分；10 个人的英雄（称号 / 名字）、玩家名、召唤师技能（记过的标上“几分几秒好”）、等级、KDA、补刀、装备、阵亡；最上面一行写“对面谁没闪（几点好）、谁没带闪” |
| `lol.spell` | “阿狸闪了”“刚才亚索交了点燃”“阿狸的闪记错了” | 记下谁在什么时候交了什么（默认闪现）；返回什么时候好，以及一句可以发到聊天框的话（“阿狸 闪 14:32 好”） |
| `lol.scout` | “查一下这把的战绩”“对面谁是突破口”“我们辅助最近怎么样” | 10 个人（或指定的一个人）最近的战绩、标签，以及“对面最可能是突破口的一两个”和原因（D3） |

- 三个工具都在主会话里用（马上返回），都放在“游戏”组。结果按不可信数据交给模型，因为里面有别人起的名字。
- 以后接着加，见“以后”。工具多了以后怎么管（例如只在英雄联盟开着时露出来，或者放进 `tools.find`），按玩家说的后面再定。

### D3 “突破口”由工具算，她只负责说

- **样本**：每人最近 20 局，**全部模式**（玩家：“直接查全部战绩”）。按模式分开统计，峡谷和大乱斗的数字不放在一起比；和这局同一模式的单独列一行。
- **每人的数据**：
  - 最近 20 局几胜几负；连胜或连败；
  - KDA、场均死亡、分均伤害（同模式）；
  - 这个英雄最近玩过几局、赢了几局（0 局就是“第一次玩”）；
  - 单双排段位；
  - 和这局的谁开黑（局内用 `teamParticipantId` 判断）。
- **突破口**：在对面 5 个人里按几项加分，分数相对的是对面的平均水平：
  - 胜率、KDA、同模式分均伤害低于对面平均；
  - 连败 3 局以上；
  - 第一次玩这个英雄。

  连胜 3 局以上要减分。分最高的一两个就是候选，工具把原因一起写出来，例如“4 连败、这个英雄第一次玩、分均伤害全队最低”。
- **说法**：她用信息的口吻说，不贴“牛马”一类标签。

### D4 召唤师技能：接口读不到冷却，手动计时（照 LeagueAkari）

- 玩家先要求从接口读。实测国服局内接口的 26 个接口都没有冷却，客户端接口在局内也没有。所以做法是：玩家说“阿狸闪了”，`lol.spell` 按现在的游戏时间（来自局内接口）记下来。之后玩家问“谁没闪”，`lol.match` 能答；玩家说“发出去”，她用 `game_chat.send` 发。
- **冷却怎么算**：
  - 基础冷却来自客户端的游戏资料，按这局的模式选对应的那一条，例如闪现 300 秒、标记 80 秒。
  - 乘上 100 / (100 + 急速)。急速 = 模式（大乱斗 / 海斗 70，无限火力 300），加上明朗之靴（10）或深红明朗（20），装备按局内接口里那个人当时的装备算。
  - 星界洞悉看不到。峡谷里结果会写“没算星界洞悉”。海斗的“闪现 2”这类海克斯也看不到。
- 玩家说“几秒前交的”就往前推；记错了可以清掉。这局结束就全部清掉。
- **规则风险**：Riot 25.17 起限制第三方冷却计时。玩家知道，决定照做；界面上加提示（D5）。

### D5 默认就用，界面上提示风险

- 两个接口默认都读，不用玩家先打开。
- 英雄联盟的游戏配置页加一段说明：Kotone 会读英雄联盟客户端和局内的本地接口（只读），用来查战绩、记召唤师技能。国服用这类功能可能违反腾讯的用户协议，LeagueAkari 等工具有封号、禁言的报告，风险自负。
- 设置里有一个开关 `games.lol.clientData`（默认开）。关掉之后三个工具都只回答“已关闭”。

### D6 隐藏战绩：照样读，特别标出来

玩家设成隐藏的（`privacy` 不是 `PUBLIC`），读得到就照样用，同时标“隐藏战绩”；读不到就说“隐藏战绩，查不到”。她说到这个人时要提一句。

### D7 发到聊天：玩家明说了才发，一条要短

- 玩家说了“发出去”“发聊天框”才发，只发队伍频道，一条一行。
- 国服的聊天过滤可能把消息拦掉，甚至禁言（LeagueAkari #373），这一点写在 D5 的提示里。

### D8 结构

- **新 crate `kotone-lol`**：
  - 从进程命令行读端口和令牌；
  - LCU 和局内接口的 HTTP 客户端，只连 127.0.0.1，不校验自签证书（照 Akari）；
  - 数据结构、游戏资料、战绩统计、突破口、召唤师技能计时、把结果写成给模型看的几行字。

  除了网络请求，其余都是纯函数，用实测录下来的 JSON（去掉玩家名和 puuid）做测试。
- **桌面端 `lol.rs`**：
  - 英雄联盟开着时，每 2 秒看一次对局阶段；
  - 进加载界面就在后台查这局 10 个人的战绩（同时 2 个，每人 20 局）；
  - 每局的结果和技能记录都放内存，这局结束清掉；
  - 执行三个工具。
- **`kotone-agent/src/lol.rs`**：工具说明。提示词的能力概览里补上“查这局的战绩、记对面的召唤师技能”。

## 以后

- **知识类工具**：BP 的胜率和克制，例如从自己的英雄池里选什么来克对面；出装和符文；海斗每个英雄的海克斯数据。数据来源已经调研，见 [`docs/research/2026-11-23-lol-data-sources.md`](../research/2026-11-23-lol-data-sources.md)。建议：
  - 国服的峡谷、大乱斗、海斗统计用腾讯 mlol / 101 的接口；
  - 海斗的英雄 × 海克斯胜率用 czgreat/aramhex-data（CC BY-NC，要署名）；
  - OP.GG 官方 MCP 作全球数据的备用，先问 OP.GG 同意；
  - 外号用腾讯 `hero_list.js` 的 `keywords`。

  这部分另写一个 ADR。
- 选人阶段看自己队友的战绩（不还原对面的名字）。
- 赛后复盘（ADR 025）读这局的战绩详情。

## 还要实测（要玩家开一局真人对局）

1. 加载界面能不能从 `gameflow/session` 拿到 10 个人的 puuid，玩家名在哪个字段。
2. 查别人的战绩要多久（每人 20 局）、隐藏战绩会返回什么。
3. 开黑的 `teamParticipantId` 是不是同一组人一样。
4. 国服游戏聊天有没有时间戳。
