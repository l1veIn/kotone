# ADR 012：独立提醒助手与本地交付

- 状态：Accepted / 已采纳
- 参考：[Sokuji 对照研究](../research-sokuji.md)

## 问题

自然语言创建定时提醒需要语义解析、持久化调度和语音/弹幕交付。把提醒当作游戏文本后处理，会混淆“发送到游戏”和“稍后通知自己”，也会把 AI 请求、模型生命周期与播报实现耦合到原有识别流程。

## 决策

琴音面向屏幕前用户本人，到时直接说简短正文，例如“打野有闪了”，不附称呼或开场白，不替用户向其他人喊话或添加未请求的战术指导。独立助手热键默认空，语音入口复用现有 ASR，依赖运行时启动。`assistant.interactionMode` 使用独立三值类型，默认对讲机，另提供录音笔和说一句就走；旧助手独奏配置兼容为对讲机，游戏输入模式保持独立。录音笔结束后先显示只读预览，确认才提交给助手，其他模式按结束规则提交。创建提醒区域同时提供语音按钮和快捷键提示：按钮操作携带固定会话凭据，只有自己发起的助手会话可以结束、确认或取消，迟到操作不能影响后续录音。桌面同时提供不依赖语音启动的文字入口。助手请求走共享 `kotone-ai` 连接与凭据服务，使用受限 `voice_reminder`、`danmaku_reminder` 工具。宿主只接收校验后的提醒意图，不执行模型代码。默认语音+弹幕，可配置。

`kotone-core::reminders` 管理有界提醒与持久化；`ReminderDelivery` 端口承担交付；`SpeechOutput` 提供 Windows SAPI 和本地 Kokoro INT8 两种实现。默认 SAPI，直接使用本机已安装声音，无需下载 Kotone TTS 模型，音质由本机声音决定。Kokoro 为可选引擎，由用户手动下载约 147 MB 模型，复用已有 sherpa-onnx，无 GPU、Python 服务或云端合成；提供三个中文女声，支持语速和音量。专用 worker 管理加载、推理、播放和空闲释放，代际取消确保旧推理结果不能在开始录音后发声。缺少引擎配置时采用系统语音，不覆盖已有显式选择。模型和第三方组件许可见 [TTS 研究](../research-tts.md)。

调度独立于 ASR 启停，但应用退出后不投递。重启补投递窗口为 120 秒，较早提醒标为 Missed；崩溃时的 Delivering 恢复 Failed，避免重复播报。语音与采音互斥，取消与迟到任务不能再开始播报；录音持续超过等待窗口则尝试弹幕。弹幕使用透明窗口、不抢焦点且鼠标穿透；默认在屏幕上方右向左滚动一行文字，可带内置琴音表情。距顶部以 CSS 像素配置，按当前窗口与实际内容高度限制在屏幕内，尺寸变化不会重启动画。滑行时长按实际条宽、屏幕宽度与配置速度计算，过长文本自动缩小，必要时加速以限制最长 45 秒。弹幕适配无边框/窗口化，独占全屏不能虚报显示成功。

正文 1–300 字符、延迟 1 秒至 7 天、单批至多 8 条、待投递至多 100 条。每条提醒保留终态，语音故障的弹幕降级也保留失败信息。完整用户行为见 [助手手册](../assistant.md)。

## 结果

AI 基础设施由后处理和助手共享；STT、TTS、游戏注入和弹幕是独立能力。未来新增语音实现可替换端口，不必扩展识别模型 registry 或篡改 post-processing pipeline。隐私说明明确音频识别与 AI 文本请求的外发边界。
