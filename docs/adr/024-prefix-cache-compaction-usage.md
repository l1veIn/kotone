# ADR 024：前缀缓存、上下文压缩与用量账本

- 状态：Accepted（2026-11-18，实施在分支 `claude/kotone-agent`）
- 照搬：DeepSeek Harness（MIT，commit `ca33fd68`）的请求组织、压缩请求形状、命中率算法；Goose（Apache-2.0，Copyright 2024 Block, Inc.，commit `196698819392`）的压缩时机、提示词要点与“原始历史保留、只是不再发给模型”；Hermes Agent（MIT）的“压缩没效果就别反复压”
- 调研记录：`target/research/dsh-cache-report.md`、`target/research/compaction-report.md`（本地，未入库）；结论见下
- 修订：[ADR 015](015-agent-scope-and-stack.md) 的上下文预算（原来按字数滑动窗口）；[ADR 022](022-sessions-memory-soul.md) 的“会话开始时冻结快照”扩展为“冻结系统提示与工具清单”
- 2026-11-27 补（[ADR 048](048-her-voice-in-one-place.md)）：价格表加在线语音合成 MiniMax（Speech 2.8 Turbo 2 元、HD 3.5 元每万字符）和阿里云百炼 Qwen3-TTS-Flash（0.8 元每万字符），汉字都算 2 个字符（`usage::tts_cost`）；硅基流动、火山、自定义接口只记字数

## 问题

玩家：dsh 的 DeepSeek 缓存命中率很高，照搬它；再加费用统计。审我们自己的请求，发现四处在打断 DeepSeek 的前缀缓存：

1. 系统提示随入口变（聊天窗口 / 语音两份说明），而两个入口共用一段对话；当前游戏的说明也写在系统提示里；
2. 工具清单中途会变：`tools.find` 启用新工具、两个入口的工具不同、改权限时隐藏 / 显示工具；
3. 历史超过 2 万字（语音入口）/ 6 万字（聊天）后按字数从最早的轮次开始丢——之后**每一轮的开头都不一样**；超出时还在系统提示末尾加一句“更早的对话已省略”；
4. 截图每来一张就把最早的一张换成文字，较早的消息每次请求都在变。

另外没有上下文压缩，没有按天 / 按月的用量和费用。

## 决定

### 1. 请求组织（照 DeepSeek Harness）

- **系统提示在一段对话开始时生成一次，之后一个字都不变**（存在会话状态里）：角色、做事规则、**两个入口的说明都写进去**、记忆、Skill、已保存的自动化。
- **会变的信息跟着这一轮的用户消息走**：`<kotone-context>` 附注写入口、现在几点、当前游戏（名字和配置 id）、游戏语音开没开；游戏换了才附上玩家写的游戏说明，系统提示里的游戏记忆不是这个游戏的就附上这个游戏的记忆。附注随消息存盘，重发时一模一样。数据块里伪造的附注标签会被改写。
- **工具清单一开始就全给、之后不变**（DeepSeek 的 `/chat/completions` 没有中途加工具的办法；dsh 也是全部注册）：`tools.find` 只做查找（按名字、说明、分组关键词排序）；改权限、新保存的自动化不改清单，禁止的工具在调用时拒绝，新自动化下一段对话才成为工具。`reply.ask` 两个入口都在清单里，聊天窗口调用时报错让她直接在回复里问。
- **历史只追加**：去掉按字数滑动的窗口（只留 40 万字的最后防线）；截图攒到 6 张才一次丢掉最早的 3 张；存盘的条数上限只丢最后一个检查点之前的（那部分已整理过）。
- **推理内容**原样带回（rig 已经这样做；DeepSeek 在带工具时要求带回）。
- **空回复**：模型偶尔把整段回答写进思考里、正文为空（真机实测出现过）。这一轮没用过工具时，同样的请求再发一次（前缀全中），还是空才收下；丢掉的那次照样记账。

### 2. 上下文压缩（Goose 的时机与提示词要点 + DeepSeek Harness 的请求形状）

- 估到 `agent.compactAtTokens`（默认 64,000；DeepSeek 上下文 100 万，但每次请求都带整段对话，太长首字慢）时，在调用模型前整理一次，一轮最多一次。
- **整理请求 = 平时的系统提示 + 平时的工具清单 + 平时的消息 + 最后一条整理要求**（dsh 的做法），所以整理这一次也命中缓存。整理要求是中文、按陪玩分节的 Markdown 检查点（玩家的要求、玩家的原话、游戏与场景、做过的事、出错与解决、没做完的、正在做的、下一步、其他），规则改编自 Goose 的 `compaction.md` 与 dsh 的 compaction instruction（原样引用错误、没有的不编、不提新想法、已有检查点就合并成一份）。
- 检查点存成一条带 `compaction` 的说明，**插在原样保留的最近一段之前**；它之前的消息不再发给模型，但都还在（界面照常显示，点开能看摘要）。保留段从一条用户消息开始，不超过这段历史的 1/4、也不超过 1.2 万字（dsh 按比例保留最近一段）。
- 之后发的是“检查点（一条用户消息，结尾一句改编自 Goose 的 continuation：不要提摘要，自然地接着）+ 保留段 + 新消息”，又是只追加。
- 能整理掉的较早部分不到阈值的 1/8（大头是系统提示和工具清单）时不整理（Hermes 的“没效果就别反复压”）；没有可整理的较早对话时也不整理、不提示；整理失败原样继续并在聊天里注明。

### 3. 用量与费用（dsh 只算命中率，费用 Kotone 自己算）

- `<KOTONE_HOME>/usage.jsonl` 只追加：每次花钱的调用一行（对话、压缩、复盘、在线语音合成、语音识别、文字识别），记 token（输入 / 命中 / 输出 / 推理）、字数、音频时长、张数、费用与币种、模型、对话 id，**不记内容**。超过 8 MB 留一份旧档。
- 命中数取 DeepSeek 的 `prompt_cache_hit_tokens`（rig 也认 `prompt_tokens_details.cached_tokens`）；**命中率 = 命中 ÷ 输入**（dsh 的公式，不含输出），显示成整数百分比、没全中不显示 100%（dsh `token-format`）。
- 价格表写在代码里、标明来源和核对日期（DeepSeek 官方价格页，2026-11-18）：`deepseek-flash` 与 `deepseek-v4-pro`，北京时间工作日 9–12、14–18 点高峰价，其余半价；节假日离线判断不了按工作日算（偏高，界面注明是估算）；`deepseek-chat` / `deepseek-reasoner` 按 Flash 估；语音合成每万字符 1.5 元（汉字算 2 个字符，限时 5 折）、语音识别每小时 0.39 元（按秒向上取整）、文字识别每千页 1.5 元。价格表里没有的模型只记 token。
- 界面：每轮下面显示“输入（命中缓存 x%）· 输出 · 约 ¥”；「琴音 → 设置 → 用量」看今天 / 本月、按用途、价格来源和压缩阈值。工具 `usage.summary`（琴音和外部 Agent）。

## 结果（真实 DeepSeek，`scripts/manual-e2e/cache_real.py`，2026-11-18）

- 同一段对话聊天 5 轮 + 游戏内 4 次：除第一次请求外命中率 **98.7%**（每次 95.0–99.2%），每次约 0.0015 元；第一次请求要带约 1.8 万 token 的工具清单（0.037 元），换一个隔离实例再跑时第一次也命中了 98.5%（DeepSeek 的缓存跨会话保留）。dsh 的记录是相邻步骤约 99.9%（它的笔记 `2026-10-22-series-start-unchanged-prompt-prefix.md`），我们稍低，主要是每轮新增的消息本身不命中。
- 压缩：整理那一次命中 94.5%，整理后第一次 88.7%（新摘要那段不命中），之后回到 98.7–98.8%；整理前告诉她的召唤师名字和打野习惯，整理后照样答对。
- 和 DeepSeek 后台账单逐笔对账**没有做**（拿不到后台）；估算的不确定处：节假日、限时折扣结束时间。

## 没有照搬的

- Goose 把整段历史拍平塞进系统提示、不带工具去摘要：前缀全不命中，不用。
- Goose / Hermes 的工具输出成对摘要、周期性裁剪：会改写较早的消息，每次都打断缓存，不用。工具结果在产生时截断一次（8,000 字），之后不再改。
