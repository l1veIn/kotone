# ADR 028：按“游戏陪玩”重新设计交互流程和界面

状态：Accepted / 已采纳（2026-11-20）。设计稿与玩家确认的 14 项决定见下文；D1 分组名由玩家定为“游戏陪玩”，其余按设计稿推荐。

2026-11-25 修订（[ADR 039](039-desktop-companion-and-game-apps.md) D2、D7）：设置不再分“陪玩 / 通用”两组——陪玩那一组（怎么叫她 · 她怎么回答 · 权限 · 用量）搬进“游戏陪玩 → 角色”页，改叫 唤醒 · 交互 · 权限 · 用量，设置只剩原来的通用；选聊天模型回到聊天页输入框旁；语音识别的启动、启动快捷键、“打开时自动启动”从语音输入的识别卡片搬到“设置 → 模型 → 语音识别”，语音输入页只显示当前用的模型。下文 D12 和第三节里的设置结构是当时的样子，以 ADR 039 为准。

## 背景

0.2.0 把 Kotone 从语音输入法变成桌面端的游戏陪玩 Agent，但界面还是语音输入法的骨架：打开先看到语音输入，标题栏是“启动 / 停止 Kotone”，没点「启动」时呼叫按钮写“先点右上角「启动」”，琴音的设置藏在「琴音 → 设置」里。新用户要先理解“启动”才能和角色说上话；老用户一升级就被新概念包围。

这次把角色放到主位：打开就是聊天页，一个 DeepSeek Key 打开全部功能；语音输入法变成一个完整的子板块；“启动”只留给真正需要加载模型的本地语音识别。

## 一、核心概念（界面文案以此为准，见 [术语表](../glossary.md)）

| 概念 | 定义 | 出现在哪 |
| --- | --- | --- |
| 呼叫 | 开始一轮和角色的语音对话。三种触发：呼叫键、唤醒词、聊天页的呼叫按钮。听和答都在**气泡**里。 | 聊天页呼叫按钮及下方说明；「设置 → 怎么叫她」 |
| 语音输入 | 说话，原话打进游戏聊天框。**不经过 Agent**。状态显示在**悬浮窗**里。 | 侧栏「语音输入」子板块 |
| 停下 | 停止角色正在做的事和所有自动化。四种方式：她操作时按 Esc、停止热键、说“停下”、托盘「停下」。 | 「设置 → 系统 → 停下」；托盘 |
| 启动 | **只和本地语音识别有关**：把本地识别模型加载进内存。 | 只在用本地识别时出现：识别卡片、标题栏状态、聊天页一行状态、托盘 |
| 气泡 / 悬浮窗 | 气泡只属于角色，悬浮窗只属于语音输入，永远不混用。 | 游戏里 |

统一规则：凡是要听你说话的功能，都等语音识别准备好。在线识别打开 Kotone 就就绪；本地识别有 未启动 / 准备中 / 已启动 / 出问题了 四种状态。打字聊天、自动化、定时提醒与启动无关。

| 入口 | 在线识别 | 本地 · 未启动 | 本地 · 准备中 | 本地 · 已启动 | 本地 · 出问题了 |
| --- | --- | --- | --- | --- | --- |
| 语音输入热键 | 直接听 | 悬浮窗提示“本地语音识别未启动”和启动方法，键照常传给游戏（D8） | 悬浮窗“正在准备…” | 听 | 悬浮窗写原因 |
| 呼叫键 | 直接听 | 气泡提示同上 | 气泡“正在准备…” | 听 | 气泡写原因 |
| 唤醒词 | 开着就听 | 不听；设置里写“本地语音识别启动后开始听” | 不听 | 听 | 不听 |
| 聊天页呼叫按钮 | 直接听 | 先启动，准备好就开始听 | 等准备好再听 | 听 | 重试启动再听 |

启动快捷键（`runtimeToggleHotkey`）和“打开 Kotone 时自动启动”（`ui.autoStart`）只在本地识别时显示；换回在线识别时隐藏，值保留。

## 二、流程

### A. 新用户（主路径）

1. **欢迎**（`ui.legacyUpgrade = notNeeded` 且 `ui.firstRunCompleted = false`）：主按钮“添加 DeepSeek Key”；次要链接“只想用语音输入？”（→ V）和“稍后配置”（→ 聊天页的 Key 卡片，记为引导完成，D14）。
2. **填 Key**：一个密码框，先本地检查格式（照 DeepSeek Harness：可打印 ASCII、不能是 `NAME=value`、不能整个带引号），再读一次模型列表测试连接（不花钱）。通过后写入：新建 DeepSeek 连接、`assistant.connectionId`、语音识别 `deepseek-asr`、文字识别 `deepseek-ocr`、语音合成 `deepseek-tts`、联网搜索 `deepseek-search`、`ui.firstRunCompleted = true`。例外：玩家已经自己下好并选了本地识别模型时，语音识别保持本地。
3. **已连接、设呼叫键**：列出换成 DeepSeek 的几项；呼叫键默认 `~`，可录别的键（冲突检测：语音输入热键、其他热键、常见游戏按键），也可以不要。
4. **聊天页**：输入框里放好“你能做什么？”，玩家自己点发送（D2）；它也是第一个起手提示。她按系统提示里的“能力概览”回答（只说真实存在的工具和技能），结尾按每轮附注里的呼叫方式给下一步。
5. 在线识别打开就能用，全程看不到启动按钮。

### V. 只想用语音输入（不需要 Key）

进入语音输入子板块，顶部展开四步引导：选游戏 → 识别方式（不填 Key 时只有本地识别；在线识别那一项写“需要 DeepSeek Key → 让 Kotone 帮我配置”）→ 热键和交互模式 → 说一句试试。写入游戏、识别模型、热键、交互模式、`ui.firstRunCompleted`、`ui.startPage = voiceInput`（D13），下载本地模型后“打开时自动启动”默认勾上（D9）。之后可在子板块底部“重新走一遍语音输入引导”。

### B. 从 0.1.x 升级的用户

判定沿用 [ADR 027](027-0.2-upgrade-transition.md)：合并默认值前，配置里没有 `agent` / `toolService` / `callHotkeyDefaulted` 的就是 0.1.x，记 `ui.legacyUpgrade = pending`。**“看过新引导”就是 `legacyUpgrade` 不再是 `pending`**，不另加标记。

1. **升级欢迎**（即使 `firstRunCompleted` 为真也显示一次）：写出他现在的语音输入设置（热键、识别模型、游戏、提醒助手），说明都没变；在线识别的老用户加一句“在线识别不用再点「启动」”（D7）。“继续使用语音输入法”是第一个、最醒目的按钮。
2. **继续使用语音输入法**：只写 `legacyUpgrade = dismissed` 和 `ui.startPage = voiceInput`，其余一律不动——热键、本地识别和启动按钮、提醒助手、自动启动都照旧；不开呼叫键和唤醒词，不装内置程序，不检测已装游戏，不做对局复盘（ADR 027 的静默规则保留）。以后每次打开落在语音输入。侧栏和大家一样完整（D4），点聊天看到的是 Key 卡片和“回到语音输入”。
3. **添加 DeepSeek Key，认识琴音**：走 A 的填 Key 和设呼叫键，但**不动语音识别**（本地就继续本地，启动按钮照常）；文字识别、语音合成、联网搜索换成 DeepSeek（D6）。写 `legacyUpgrade = optedIn`，新连接和呼叫键写进 `assistant.companionBindings`（0.1.x 的提醒键和连接原样保留）；呼叫键默认空、推荐 `~`；落地页改成聊天（D5）。

### C. 换成本地识别

语音输入 → 输入 → 语音识别卡片：“换成本地识别：免费、离线、边说边出字”。下载完立即启动一次，“打开时自动启动”默认勾上（D9）。之后识别卡片、标题栏、聊天页、托盘出现启动 / 停止和状态。换回在线识别：卸载本地模型，这些都消失，启动快捷键和自动启动的值保留。

## 三、界面结构

- **打开落在哪**：聊天页；逃生通道用户、走完 V 路径的用户、或在「设置 → 系统」把“打开软件时显示”改成语音输入的，落在语音输入。新字段 `ui.startPage`（见“配置兼容”）。
- **侧栏**（参照 DSH）：新对话和对话列表在最上面并占满剩余高度；底部固定「游戏陪玩」分组（角色 · 游戏列表 · 自动化）、「语音输入」一项（0.1.x 用户再加提醒助手），然后 设置 · 关于。图标栏形态顺序不变。
- **聊天页三种状态**：没有 AI 连接 → Key 卡片（和引导里填 Key 是同一个组件，照 DSH“回到空白会话就检查有没有 Key”），下面“用别的服务商？设置 → API 连接”；已配置 → 呼叫按钮，下面写当前的触发方式（“按 ~ 或者说‘琴音琴音’”，没有呼叫键时“设一个呼叫键 →”）；本地识别没启动 → 呼叫按钮上方一行状态和「启动」。
- **角色页**：只留 角色 · 记忆 · 技能；聊天从侧栏进入（`section: chat` 照旧）。
- **语音输入子板块**：一个侧栏入口，三个分页对应原来的页面 ID：输入 = `general`、文字处理 = `processing`、历史 = `history`。顶部“让 Kotone 帮我配置”（有可用的角色就在聊天里预填一句请她帮忙，没有就先填 Key）。输入分页：语音识别卡片、语音输入热键（原“录制热键”）、交互模式、悬浮窗（含从「系统」搬来的样式）、语音输入的其他热键（重发、切频道、文字处理开关、切换流程，从原「其他热键」搬来），以及一行共享设置（麦克风 → 设置 → 声音，游戏 → 游戏列表）。历史只有语音输入的记录，和角色的对话列表分开。
- **设置**：陪玩组（怎么叫她 · 她怎么回答 · 权限 · 用量）+ 通用组（模型 · API 连接 · 声音 · 调参 · 外观 · 系统）。陪玩组就是原「琴音 → 设置」整页（D11）：这些设置换角色时共用，不属于某个角色。放置标准：“如果删掉角色，这项设置还需要吗？”需要的放通用组。原「其他热键」拆走：语音输入的四个热键进语音输入，停止热键进「系统 → 停下」，启动快捷键进识别卡片（D12）；“音效”改名“声音”并收进麦克风和“录音时降低扬声器音量”。新增分页 ID `call`、`reply`、`permissions`、`usage`；原有分页 ID 不变。
- **标题栏**：在线识别时什么都不显示（只剩资源占用）；本地识别时一个状态胶囊，点开是 启动 / 停止 / 去语音输入设置。
- **托盘**：打开主页面 ·（只在本地识别时）启动 / 停止本地语音识别 · 停下 · 退出。
- **设置位置说明**：`settings_guide` 每一项改到新位置；前端 `parseLocation` 同时认新旧两种写法，旧对话里的“去看看”链接也跳到新位置。

## 四、后端行为

- **在线识别打开即就绪**：启动时 `ui.autoStart` 为真或活动识别模型是在线模型就启动运行时；换识别模型的所有入口（设置页、工具服务、`settings.update`）都经状态推送点检测到变化，调用 `runtime::after_asr_change`：换成在线 → 启动或重启；从在线换成本地 → 立即启动一次；本地换本地 → 保持“需要重新启动”。在线识别改了热词、语言等会话设置时自动重启一次。启动 / 停止快捷键和工具服务的 `runtime.stop` 在在线识别时不起作用。
- **没准备好时只提示、不吞键**（D8）：运行时不在“运行中”时，用低层钩子的**被动**具名热键盯住语音输入热键和呼叫键——命中会产生事件，但按下、按住重复和松开都放行给游戏。语音输入热键只在悬浮窗提示（悬浮窗设为不显示、独占全屏时不显示），呼叫键只在气泡提示（气泡关着就不提示）。没有低层钩子时不提示。
- **呼叫在识别没准备好时**：`assistant_call` 先启动（启动中就等它），然后开始听。
- **“停下”统一**：`stop.rs` 的 `stop_everything` 依次停全部自动化、角色正在做的操作、她派出的子会话、这一轮对话和正在念的话。停止热键、托盘「停下」、语音说“停下”都调用它。
- **气泡关掉时**（D10）：角色的录音会话不再借用悬浮窗显示，只用声音和弹幕；0.1.x 的提醒助手照旧用悬浮窗。
- **“你能做什么？”**：系统提示加“能力概览”一节，从工具清单分组生成（`kotone_agent::prompt::capability_overview`），测试保证提到的每个工具都存在、每个分组都覆盖；每轮附注（聊天入口）加上呼叫方式和语音识别是否就绪，结尾的下一步建议才准确。

## 五、借鉴 DeepSeek Harness 桌面端

读的是本地源码 `target/research/deepseek-harness` @ `ca33fd68`（MIT），并用安装版对照。来源记录见 [`docs/third-party/deepseek-harness-ui.md`](../third-party/deepseek-harness-ui.md)。

| DSH 的做法 | Kotone 怎么用 | 不同之处 |
| --- | --- | --- |
| 首启欢迎窗：没登录且没 Key 就显示，每次冷启动都检查；“稍后配置”不写标记（`welcome-api.ts`） | 聊天页每次打开都检查有没有 AI 连接，没有就显示 Key 卡片 | 引导弹窗本身只弹一次，不打扰只用语音输入的人 |
| 欢迎页两个入口：登录 / 添加 API Key（`WelcomePage.tsx`） | 添加 DeepSeek Key（主）/ 只想用语音输入？（次） | Kotone 没有账号登录 |
| Key 页：一个密码框，不选服务商；保存并继续 / 稍后配置 / 返回 | 照搬布局和三个出口 | 加了测试连接（DSH 不测，错 Key 要到第一次发消息才报错）和“去开放平台创建”的链接 |
| 本地格式检查：可打印 ASCII、不能是 `NAME=value`、不带引号 | 照搬（`deepseekSetup.ts`） | — |
| Key 只写不读，界面只拿到成功或失败 | 已有系统凭据库，保持 | — |
| 一个 Key 靠默认组合生效：默认模型 `deepseek-flash`，联网搜索也用同一个 Key | DeepSeek 连接被语音识别、文字识别、语音合成、联网搜索复用；引导里显式切换并列出 | Kotone 把切换写进设置，玩家在“已连接”页看得到换了哪几项 |
| 落地是空白新会话，输入框居中（`EmptyHero.tsx`） | 已在用，加了呼叫按钮和起手提示 | DSH 没有起手提示 |
| 侧栏：新会话、会话列表、底部固定的设置入口 | 对话列表提到分组上面，分组固定在底部 | — |
| 内置 `dsh-doc` 技能回答关于 Harness 自己的问题 | 同一思路：“你能做什么？”按能力概览回答 | 概览放进系统提示，由工具清单生成并有测试对齐，不靠模型自己去读技能 |
| 升级时给已有 Key 的安装覆盖默认偏好 | **不照搬** | Kotone 不改老用户的配置（ADR 027） |

## 配置兼容

遵守 [`docs/development.md`](../development.md) 的规则：已有字段只写旧版本认识的值，新能力放新字段。

- 唯一的新字段 `ui.startPage`：字符串，`"voiceInput"` = 语音输入，空串或任何不认识的值 = 聊天。存成字符串而不是枚举，以后加取值也不会让 0.2.0 把整份配置当成损坏。0.1.x 会忽略它。
- 老用户装回 0.1.x 再保存，会丢掉 0.2 的新字段，再升级时会被认成 0.1.x、再看一次升级欢迎页。这是可以接受的。
- 页面 ID（`general`、`processing`、`history`、`assistant`、`advanced` 等）和所有设置字段名不变；`advanced` 只新增分页 ID。

## 删掉的

- 所有“先点右上角「启动」”类提示（呼叫按钮、语音唤醒、标题栏、系统页、模型页、提醒助手语音、热键保存后的“启动 Kotone 后生效”）。
- 原语音输入首页的“启动 Kotone”横幅和“试试游戏陪玩”卡片；标题栏的启动 / 停止按钮（`RuntimeButton`）。

### 真机验收记录（2026-11-20）

`scripts/manual-e2e/copilot_flow_real.py`：调试构建、隔离 `KOTONE_HOME`、玩家真实的 DeepSeek Key 只在内存里；经 WebView2 的调试端口操作设置窗口，不发系统按键。

- 新用户（17/17）：欢迎 → 填 Key → 五项都换成 DeepSeek、呼叫键 `~` → 聊天页预填“你能做什么？”；在线识别没人点启动就在运行，聊天页、语音输入、标题栏都没有启动按钮。她的回答按真实能力列了几项（替你说话、看画面操作、播报提醒、自动化、查资料、帮你配置），结尾是“进游戏按 `~` 就能叫我”。换成本地 X-ASR 后立即启动、标题栏出现状态；停掉后聊天页显示“本地语音识别 · 未启动”，点聊天页的呼叫按钮先启动再听；换回在线识别后状态消失，启动快捷键的值保留。
- 0.1.x 配置 → 继续使用语音输入法（7/7）：升级欢迎页写出原来的热键、本地识别、游戏和提醒助手；原有设置值一个没变，只多了 `legacyUpgrade = dismissed` 和 `startPage = voiceInput`；重开直接落在语音输入，不再弹引导。
- 0.1.x 配置 → 填 Key（6/6）：语音识别保持本地，呼叫键默认空、选 `~` 后写进 `companionBindings`，旧提醒键 Alt+F9 原样保留。

真机发现并修掉的两个问题（浏览器测试里的模拟后端碰不到）：

1. **0.1.x 用户启用琴音时整个应用卡住**（ADR 027 原有代码）：`update_settings` 是同步命令，跑在主线程的 IPC 回调里，启用时在回调里直接建气泡窗，WebView2 嵌套创建控制器死锁（线程栈：`update_settings → create_startup_windows → WebviewWindowBuilder::build → wait_with_pump`）。改为交给后台任务建窗口。
2. **填完 Key 进聊天发不出去**：聊天页还拿着打开软件时读到的“还没有选 AI 连接”。改为连接或角色的 AI 设置一变就重新读一次 Agent 状态（`agent-chat.spec.ts` 加了回归测试，去掉修复会失败）。

没在真机上验的：按语音输入热键 / 呼叫键时悬浮窗、气泡的“没准备好”提示（低层钩子按设计忽略模拟按键，只能人工按）；托盘菜单的实际显示（切换本地 / 在线时重建菜单没有卡住，菜单内容没截图核对）。
