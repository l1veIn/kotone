# ADR 025：可切换的角色、自定义唤醒词与对局复盘

- 状态：Accepted（2026-11-18，实施在分支 `claude/kotone-agent`，放进 0.2.0）
- 照搬：Character Card V2 格式（规格仓库没有许可证，只实现格式）与 V3 的 `chara_card_v3`（MIT）；SillyTavern 的“角色卡归角色、玩家 persona 与世界书共用”的分法（AGPL，只借概念、没有用代码）；sherpa-onnx `text2token`（Apache-2.0）的 ppinyin 拆分规则；`pinyin` crate（MIT）
- 修订：[ADR 022](022-sessions-memory-soul.md) 第 2、6 节（身份从“一份”变成“每个角色一份”）；[ADR 017](017-voice-wake.md)（唤醒词跟着角色）

## 角色

- **每个角色各一份**：名字、头像（琴音用全套立绘和表情；其他角色没传头像时显示名字的第一个字，不冒用别人的形象）、性格（SOUL.md）、声音（`provider/voice`）、唤醒词、开场白。
- **所有角色共用**：关于玩家的记忆（USER.md）、她的笔记（MEMORY.md）、每个游戏的记忆、技能、设置。换角色不会忘掉玩家。
- **内置**：琴音（默认）、小雨（温柔安静，DeepSeek 海星）、小林（沉稳男声，DeepSeek 暗潮）、**大肥鱼**、**Claude大小姐**；玩家可以新建、改、删（内置的只能恢复默认）。
- **社区二创形象（玩家 2026-11-18 决定直接打包）**：大肥鱼取自 PC2005-cloud/dsh-pet 的动画帧，Claude大小姐取自 opsCar/claude-daxiaojie-assets 的大头贴；两者形象都是 CC BY-NC-SA 4.0（非商用、相同方式共享）。做法：裁成 7 种状态的头像（256×256 WebP，约 350 KB），放在 `apps/desktop/src/assets/roles/`（目录里写明出处与修改），协议全文随安装包发布，角色页显示署名；性格是 Kotone 自己写的。**这部分素材永远不能商用**：Kotone 以后收费或做商业版时要拿掉。默认唤醒词实测（`wake_eval.py --words`）：大肥鱼 8/8、你好大肥鱼 8/8、大小姐 7/8、你好大小姐 8/8，选了“你好大肥鱼”“你好大小姐”。
- **存储**：`<workspace>/roles/<id>/role.json` 就是一张 Character Card V2（`spec: chara_card_v2`），Kotone 的字段在 `data.extensions.kotone`（头像文件、声音、唤醒词、一句话介绍）；性格在同目录的 `SOUL.md`；琴音的性格仍是工作区根目录的 `SOUL.md`，升级前的数据不用搬。原来设置里的名字和头像第一次启动时记进琴音的卡。导出时性格填进 `description`；导入 V1 / V2 / V3 JSON 时不认识的字段原样保留（V2 要求）。
- **有意偏离 V2**：卡里的 `system_prompt` / `post_history_instructions` 不替换琴音的系统提示（里面有工具和安全规则），只原样保留在卡里。
- **切换**：`roles.switch` 把名字和头像写进设置 `agent.identity`（气泡、聊天、侧栏都读它）、记下 `agent.roleId`、**开一段新对话**（系统提示在一段对话里不变，ADR 024）；语音合成按当前角色的声音（属于正在用的引擎时）；唤醒检测按当前角色的唤醒词重新开始。工具 `roles.list / get / switch / create / update / delete` 琴音和外部 Agent 都能用；`agent.roleId` 不能直接用 `settings.update` 改。

## 自定义唤醒词

- 现在的唤醒模型（sherpa-onnx KWS，WenetSpeech zipformer）认拼音 token。照 `text2token`（ppinyin）：每个字取带声调拼音，拆成“声母 + 带调韵母”（y、w 也算声母；零声母整个算一个；j/q/x/y 后的 ü 写作 u），每个 token 都要在模型的 `tokens.txt` 里（内置一份，SHA-256 与下载校验的一致，没下模型也能检查）。参考输出（琴音琴音、你好琴音、小爱同学……）逐字一致。
- 拼音用 `pinyin` crate：逐字取音，和 pypinyin 的单字读音全部一致，但不按词消歧——多音字在界面上给下拉框让玩家选，读音存进角色卡。
- 规则：只能用汉字，3–8 个字（3 个字提示偏短，推荐 4 个字、名字重复两遍）；常用语拒绝；不能用时说明哪个字不认识；默认唤醒词是名字重复两遍（琴音默认仍按「语音唤醒」里选的预置）；角色的唤醒词不能用时退回“琴音琴音”。关键词行的阈值写法照 sherpa-onnx `EncodeBase`（这个模型的词表里有 `#0`…`#29`）。
- **实测**（`scripts/manual-e2e/wake_eval.py`，离线喂给和桌面端同一个检测器）：SAPI 两种语速 + DeepSeek 两种声音，单说和后面跟指令：琴音琴音 8/8、你好琴音 8/8、小雨小雨 7/8、小林小林 8/8、星野星野 8/8；3.9 分钟不含唤醒词的普通说话（有“小林”“琴女”“雨天”这类近似词）0 次误唤醒；灵敏度“正常”和“高”结果一样。真机经 VB-CABLE（`roles_real.py`）三个角色的唤醒词都喊醒了，其中切回琴音后的第一次“琴音琴音”两次运行都没中、第二次中了（原因没查清，可能与 sherpa-onnx #3994“停顿后第一次漏检”有关）。**还没有真人声音和游戏背景音的数据**，所以界面上标“实验性”。

## 对局复盘（陪玩特有，自己设计）

Goose、OpenClaw、Hermes 都没有“按游戏进程的一局”这个概念，所以这一块自己设计；思路来自 Goose 评估（由 Rust 核心在对局结束时主动触发一次摘要），写记忆的规矩照 Hermes（有上限、写入前做注入检查、只记以后用得上的）。

- **一局** = 某个游戏配置的进程从出现到退出（每 5 秒看一次进程）。只整理玩了 3 分钟以上、并且这一局里叫过琴音或跑过自动化 / 提醒的；什么都没发生就不调用 AI。
- **一次调用**：这一局的对话（含子会话听到的话）、工具调用、提醒、自动化 + 旧的游戏记忆 → 返回 3–6 条复盘和合并后的游戏记忆（保留仍然有用的、合并重复的、删掉过时的，≤ 3,800 字，超了从末尾丢）。记忆写回 `memory/games/<id>.md`；复盘作为一张卡片留在当前对话（等琴音空下来再加，不发给模型）；记账为“复盘”。
- 可以关（`agent.matchRecap`，默认开）；工具 `game.recap {game?, sinceMinutes?}` 手动整理。
- **实测**（真实 DeepSeek，`recap_real.py`）：游戏内说了三件事（按键、Boss 打法、玩的英雄和提醒），结束进程后复盘出现在聊天里，游戏记忆记下了按键、Boss 打法和玩家习惯，0.003 元。实测中发现她第一次写游戏记忆用了中文名而被拒绝——于是每轮附注里写上游戏配置的 id。

## 顺带的安全修正

真机测试“跟队友说我去拿龙了”时，她选了打字（`game_chat.send`），字和回车打进了前台的桌面。现在：前台进程不是当前游戏配置的就不打字（桌面、文件夹一律不打）；游戏语音开着时附注写“游戏语音：开着”，提示词说明“跟队友说”就用嘴说，默认用玩家的原话和语言；真实服务的测试脚本禁止会按键的工具。
