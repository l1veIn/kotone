# ADR 020：琴音用虚拟麦克风替玩家在游戏语音里说话

- 状态：Accepted（2026-11-17）。用户确认方向，按调研的默认做法实现，并补充两条要求：**VB-CABLE 要自动安装**；**声卡相关的配置也要能交给 Agent**。
- 调研：[琴音用麦克风替你说话](../research/2026-11-17-voice-into-game-chat.md)
- 相关：[ADR 014](014-game-agent-harness.md)（三层：基础能力 → 自动化 → Agent，人能做的 Agent 都能做）、[ADR 017](017-voice-wake.md)（语音唤醒）

## 问题

玩家说“琴音，跟队友说一声我去拿龙了”，琴音的语音要让**队友**听到，也就是要进游戏的语音聊天。游戏语音只读麦克风，所以要一个“虚拟麦克风”：Kotone 往里放声音，游戏把它当麦克风读。

## 决定（每一部分照抄谁）

| 部分 | 照抄 | 做法 |
|---|---|---|
| 虚拟麦克风 | VB-CABLE（VB-Audio，捐赠软件）；Soundux 的安装脚本（`VBCABLE_Setup_x64.exe -h -i`） | 不自己写驱动。没装时**自动安装**：从官网下载 `VBCABLE_Driver_Pack46.zip`（固定 SHA-256），解压到 Kotone 目录，以管理员身份静默运行官方安装程序（Windows 弹一次授权）。Kotone 的安装包里不带它；安装前界面写明它是 VB-Audio 的捐赠软件、来自 vb-cable.com |
| 声音怎么进去 | TTS Voice Wizard（MIT）：合成的语音播到 CABLE Input，同时自己听一份 | “说给队友”的话：合成一次，送进虚拟麦克风；玩家照常从自己的耳机里听到同一句 |
| 玩家自己的声音 | cpal `examples/feedback.rs`：输入流 → 环形缓冲 → 输出流 | 开着“游戏语音”时，真麦克风的声音实时转进 CABLE Input，和琴音的声音混成一路（琴音说话时把玩家的声音压低一半，避免叠在一起听不清） |
| 游戏选麦克风 | AudioDeviceCmdlets / EarTrumpet 用的 `IPolicyConfig::SetDefaultEndpoint` | 很多游戏（据调研 PUBG、CS2）只用 Windows 的默认录音 / 默认通信设备。提供“把 Windows 默认麦克风设成 CABLE Output”和“改回原来的”，先记下原来的设备 |
| 按键说话 | 不做（第一版） | 建议游戏里改成自由麦；以后可照 Soundpad Auto Keys：播的时候按住说话键 |

## 交给 Agent（为 Agent 而生）

人在设置页能做的，琴音和外部 Agent 都能做：

- `voice_chat.status`：VB-CABLE 装没装、两个设备在不在、开没开、Windows 默认麦克风现在是哪个、转发在不在运行、当前语音引擎能不能送进游戏；
- `voice_chat.install`：自动下载并安装 VB-CABLE（会弹管理员授权，**先问玩家**）；
- `voice_chat.default_mic`：`{use: "cable" | "restore"}` 把 Windows 默认麦克风设成 CABLE Output，或改回原来的（改系统设置，**先问玩家**）；
- `voice_chat.say`：把一句话说给队友听（**先问玩家**，可以在权限里改成直接执行）；
- `voice_chat.test`：往虚拟麦克风放一段测试音，同时从 CABLE Output 录回来，确认通了；
- 开关、混不混真麦克风、用哪个真麦克风：设置项 `voiceChat.*`，经 `settings.update`。

## 约束

- 默认关；开着时才转发麦克风。**Kotone 没运行时，游戏里选了 CABLE Output 的话队友听不到你**——界面写明。
- 语音唤醒、语音输入永远不该听 CABLE Output（否则琴音会被自己唤醒）；设备选成它时提示。
- 系统语音（Windows SAPI）直接出声、拿不到声音数据，不能送进游戏；用 DeepSeek / Kokoro / 在线引擎时可以。
- 只送“说给队友”的话，平时的回答、提醒不送。

## 实施步骤

1. 平台：VB-CABLE 检测、静默安装（下载、校验、解压、提权运行并等待）、Windows 默认录音设备读 / 写；
2. 平台：转发与混音（真麦克风 + 琴音的语音 → CABLE Input）；
3. 语音合成：一句话除了自己播，还能交给转发器；
4. 设置项、设置说明、工具、权限、琴音的提示词；
5. 设置页；
6. 测试：纯逻辑单元测试；真机只测转发和测试音（这台电脑已装 VB-CABLE），**不改用户的 Windows 默认设备、不重装驱动**；
7. 文档与第三方声明。

## 实施记录（2026-11-17）

- 平台：`kotone_platform_windows::voice_chat`（检测、录音设备与默认设备、提权运行并等待）、`voice_router`（转发与混音、测试音与录音峰值）；语音合成新增“只合成不播放”（`SpeechOutput::synthesize`）；设置 `voiceChat.*`；桌面 `voice_chat.rs`（启停、安装、默认麦克风、说一句、测试）与五个工具；琴音的常用工具里有 `voice_chat.say` 与 `voice_chat.status`，安装 / 改默认麦克风 / 对队友说话默认先问；设置页「琴音陪玩 → 设置 → 游戏语音」。
- **许可上的一处出入**：VB-CABLE 包里的 `readme.txt`（2024）写“未经作者同意不能把它放进别的软件的安装流程”，而官网许可页（https://vb-audio.com/Services/licensing.htm）写的是可以随应用原样分发、也可以静默安装，只要保持捐赠软件模式。Kotone 的做法是**不打包**：用户点了“安装”才从官网下载原版、运行官方安装程序，界面与文档注明来源与捐赠软件，落在官网许可页的范围内。
- **验证**：纯逻辑（设备名识别、混音、闪避、缓冲上限、默认设置、权限）有单元测试，设置页有 Playwright 测试。这台电脑（已装 VB-CABLE）上真机验证了：读录音设备与默认设备、440 Hz 测试音经转发器从 CABLE Output 录回（峰值 0.30）、隔离实例启动即转发、`settings.update` 开关启停、`voice_chat.test` 通过、系统语音时 `say` 给出原因、已安装时 `install` 直接返回。
- **没验证**：自动安装的真实下载 + 提权静默安装（本机已装，没卸载重装）；切换 / 改回 Windows 默认麦克风（会改用户的系统设置，没在真机上跑）；混入真麦克风（测试时关掉了，没占用用户的麦克风）；用 DeepSeek / Kokoro 的 `say`；任何真实游戏里队友能不能听到。

## 实施记录（玩家这边那一遍和她轮流放，2026-11-25）

- **问题**（[共享资源评估](../research/2026-11-25-shared-resources-audit.md)第二节第 8 条）：`voice_chat.say` 在玩家这边放的那一遍（宿主的 `speak`）直接调扬声器，没拿播报锁（提醒、她整段念的话、填充话、边生成边念的回答轮流用的那一把）。复现（`apps/desktop/src-tauri/src/assistant.rs` 的测试，改前 5 个都失败）：她正在说时这一遍照样放（边生成边念有自己的输出设备，两段同时出声）；这一遍在放时她下一句照样开口；放的时候“她在出声”是假的（音乐不压低；通话里没开回声消除时不挡麦克风，可能把这句当成玩家说的）；本地语音的队列满一次这一遍就丢、只记日志；麦克风开着照样放（会录进去）。评估说的 `speak_now` 不是轮流的那条路（它先停掉正在放的，唤醒应答用），所以没照它改。
- **宿主的 `speak` 和她自己的话走同一条路**（`assistant::speak_in_turn`）：排队拿同一把播报锁，放的时候一直拿着；麦克风开着先不出声（最多 30 秒，同提醒）；本地语音队列满了稍等再试（最多 3 秒，放在提醒、她的话共用的 `queue_speech` 里，它们也不再因为队列满丢掉一句）；记进“她最近说过的话”（通话里认回声用）；玩家让她停下时一起停。放不出来、又不是被停下的，照提醒的做法改用弹幕显示这句，原因交回插件。
- **工具不等玩家这边那一遍**：她常在同一步里先 `voice_chat.say`、再 `speak`“说了”（提示词就是这么教的）。边生成边念的“说了”在模型写参数时就开口、拿着播报锁，要等 `speak` 执行才收尾；工具是一个一个执行的，`voice_chat.say` 要是等这一遍，两边就互相等着。所以队友那一路照旧合成完马上送进 CABLE（行为不变），玩家这边那一遍交给宿主排队，工具不等它；停下她时（插件的 `stop`）还在排队、正在放的这一遍也不放了。听到的顺序：她没在说话时这一遍马上放，她接着说的“说了”排在后面；她已经在说时这一遍排在她后面。
- **“她在出声”只有一种判断**：`assistant::she_is_audible`（播报锁被拿着、应答 / 追问在念、边生成边念）。音乐压低（`Host::she_is_audible`）和唤醒、通话的半双工（原来 `wake.rs` 的 `her_voice_playing`）都用它。`her_voice_playing` 原来多看一个“气泡在念”：气泡在念的时候声音一定由前三样之一在放（`bubble::say` 包着拿播报锁的交付，边生成边念的气泡在 `voice_reply` 的登记里），多看它只会在气泡卡住时一直不听麦克风，去掉了。别的“她忙不忙”的判断（呼叫键打断、填充话、通话空闲计时、回合结束等她说完）还各看各的几项，见评估第 8 条的说明，留给“声音焦点”那份总则。
- **测试**：`assistant::tests` 新加 8 个（上面 5 个复现 + 停下时一起停、调用方不等了就停、一直放不出来要报原因）；`voice_chat::tests::the_player_side_echo_does_not_hold_up_the_tool`（工具不等、停下她时丢掉还在排队的那一遍）。真机：`scripts/manual-e2e/voice_chat_real.py` 加了“玩家这边那一遍没被丢”的检查和相关日志（`插件的话排在她后面放`），改成跑 exe 的副本；2026-11-25 跑了 7 项全过（真 DeepSeek、VB-CABLE）：她分两步说（先 `voice_chat.say`，下一步 `speak`“说了，我去拿龙了。”），`say` 合成完送进 CABLE 就返回（这一步 2.4 秒），玩家这边那一遍随后放了 0.8 秒，她的“说了”在它放完以后才出声，没有叠在一起、没被丢。这次她没在同一步里接着 `speak`，所以“排在她后面”那条路只有单元测试管着。
- **没测**：音乐压低的实际听感（要网易云登录）；通话里开着回声消除时这一遍被当成回声的效果；真实游戏。
