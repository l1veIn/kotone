# ADR 013：自动化的领域模型（定义 / 触发 / 执行记录），提醒并入自动化

- 状态：Accepted / 已采纳（2026-11-16）
- 修订：[ADR 012](012-reminder-assistant.md) 的调度部分（提醒不再有独立调度器）
- 参考：[演进计划 §12](../product-evolution-game-tools.md#12-自动化大模型写程序沙盒执行2026-11-16-定方向)、[自动化实现记录](../research/2026-11-16-companion-scripts.md)

## 问题

Kotone 先后长出了两种“替用户做事”的能力：

- **提醒**（ADR 012）：过 N 分钟播报 / 弹幕一句话，有自己的持久化调度器；
- **自动化**（原“陪玩脚本”）：大模型写一小段 Luau 程序，立即对游戏窗口按键、看屏幕。

用户要的东西继续往两边长：“5 分钟后开始每秒按 Q”“保存这个，以后按热键直接跑”“每隔 `间隔` 秒按 `键`”。如果两套各自扩展，会有两个调度器、两份“进行中”列表、两套停止方式，Agent 也要学两套接口。

同时，这些能力合在一起已经很像云函数产品（函数 + 触发器 + 调用记录 + 入参）。我们需要决定借鉴哪些、拒绝哪些，而且要趁**还没发布**时定下来：配置兼容规则（[开发手册](../development.md)）要求旧字段的值永远不改，存盘格式和工具接口一旦发布，以后改动成本很高。

## 决策

### 1. 领域划分

| 领域 | 管什么 | 拥有的配置 / 数据 |
| --- | --- | --- |
| 语音输入 | 按热键说话，文字打进游戏 | 录音热键、语音识别模型、文字处理、历史 |
| 陪玩 | 理解用户的话，调一次 AI，**决定**做什么 | AI 连接、能力自检、自动发送、快捷指令 |
| **自动化** | 替用户**持续**或**稍后**做事；提醒属于这里 | 已保存的自动化、调度与执行记录、停止热键、上限 |
| 感知 | 截图、文字识别、聊天跟踪 | 所选的 OCR 模型 |
| 输出 | 语音播报、弹幕、模拟键盘输入 | 声音、音量、语速、弹幕外观 |
| 游戏适配 | 每个游戏的差异 | 按键、频道、热词、陪玩说明、聊天框位置 |
| 模型与连接 | 统一模型清单、AI 连接、密钥 | 模型目录、下载、凭据 |
| Agent 接口 | 把以上能力开放出去，不放业务逻辑 | 工具服务、事件、MCP、Skill |
| 应用 | 启动、托盘、热键冲突、更新、诊断、配置兼容 | — |

陪玩只负责“决定”；回答和打字交给输出；凡是要等待、重复、盯屏幕的事交给自动化。

### 2. 自动化分三层：定义、触发、执行记录

| 层 | 内容 |
| --- | --- |
| **定义**（Automation） | `id`、名字、说明、入参声明、动作、创建者（用户 / 陪玩 / Agent）、更新时间 |
| **触发**（Trigger） | 立即；延迟 N 秒；指定时刻；热键（经快捷指令；2026-11-25 起是热键表里绑 `automation.run`，[ADR 040](040-hotkeys-belong-to-core.md) 第 3 期）。数据结构为以后的“每天几点”“事件”留位置，暂不实现 |
| **执行记录**（Run） | `id`、来自哪个定义（或临时程序的快照）、入参、目标窗口、触发方式、到期时间、状态、日志、按键数、结果 |

**动作**只有两种：

- **播报**：一段文字 + 方式（语音 / 弹幕 / 两者）。这就是今天的提醒，不需要游戏在前台；沿用 ADR 012 的投递、语音与录音互斥、弹幕降级等规则。
- **程序**：一段 Luau 源码，由 `kotone-script` 在沙盒里运行，受 §12 的护栏约束。

陪玩或 Agent 临时写的一次性程序是“匿名”执行：执行记录里保存源码快照，用户点“保存”才变成有名字的定义。

**入参**：定义声明参数，类型限于 数字（范围）、文字（长度）、布尔、枚举、按键名、屏幕区域、颜色。调用时先按声明校验，再交给程序（Luau 里是只读的 `args` 表）。屏幕区域与颜色参数由设置页的框选 / 取色控件填写。保存下来的自动化靠入参复用：热键或 AI 只填参数，不重写程序。

### 3. 一个调度器：开始之前归调度器，开始之后归程序

延迟是**触发**的属性，不写成程序里的 `wait(5 分钟)`：

| | 开始前（等待中） | 开始后（运行中） |
| --- | --- | --- |
| Kotone 重启 | 保留（存盘） | 停止，按住的键松开 |
| 能等多久 | 最长 7 天 | 最长 30 分钟 |
| 占“同时运行最多 3 个”的名额 | 不占 | 占 |
| 需要游戏在前台 | 不需要 | 程序需要（失焦暂停） |

ADR 012 的提醒调度器（持久化、重启恢复、取消、错过不补、历史）推广为**自动化调度器**，留在 `kotone-core`；到期后经端口把动作交给桌面宿主执行（播报走现有投递，程序走自动化执行器）。core 仍不执行模型代码，也不依赖脚本引擎。

“5 分钟后提醒我买装备” = 延迟 300 秒 + 播报；“5 分钟后开始每秒按 Q” = 延迟 300 秒 + 程序；“现在每秒按 Q” = 立即 + 程序。

### 4. 借鉴云函数，但语义相反的地方一律按游戏场景定

| 云函数的默认 | Kotone 自动化 | 原因 |
| --- | --- | --- |
| 失败自动重试、至少执行一次 | **最多执行一次，绝不自动重试** | 按键是真实输入，重放可能放错技能、发错消息 |
| 迟到的事件照样处理 | **错过就丢弃**：到期时间已过 120 秒（Kotone 没开、崩溃）标为“错过”，不补执行；崩溃时“运行中 / 投递中”的记录恢复为“失败” | 迟到很久的按键比不按更糟 |
| 无状态，在哪跑都一样 | **绑定下指令时的游戏窗口**：程序类执行在创建时记录目标窗口；到期时窗口已关闭则失败，不改投当时的前台窗口 | 不能对别的窗口按键 |
| 无人值守 | **人随时能停**：停止热键、托盘、`automation.stop`；总时长 / 步数 / 按键数 / 按键间隔上限 | 安全底线 |
| 环境变量、密钥、网络 | **都没有** | 沙盒 |
| 入参可以是任何数据 | **入参在调用时固定**；屏幕上识别的文字是不透明对象，不能变成入参、按键或打字内容 | 数据不是指令，防聊天框注入 |
| 满了就排队或扩容 | 到期时已有 3 个程序在跑：这次执行**失败并提示**，不排队 | 排队会造成“晚了很久突然按” |

停止热键、托盘「停止所有自动化」与不带 `id` 的 `automation.stop`：停止全部运行中的程序，并取消全部**等待中的程序**；等待中的**播报**（提醒）不受影响。单条播报在「进行中」列表里取消。

### 5. 暂不做

链式调用 / 编排（一段程序里写几个函数即可；以后需要再加 `run("名字", 参数)`，计入同一组上限）、重复触发与事件触发、版本与别名、并发扩容、程序访问其他工具。

### 6. 接口（工具服务）

- 定义：`automation.save`（新建或按 `id` 覆盖）、`automation.get`、`automation.list`（已保存的定义）、`automation.delete`；
- 执行：`automation.run`（`id` + `args`，或临时 `source`；可选 `delaySeconds` 或 `at`），返回执行记录；`automation.runs`（等待中、运行中与最近的执行记录）；`automation.stop`（按执行记录 `id` 取消 / 停止，缺省见上文）；
- 事件：`automation.finished`（含执行记录 `id`、来源定义、状态）。

`automation.list` 的含义由“执行记录”改为“已保存的定义”，执行记录改由 `automation.runs` 返回；这些工具尚未发布，此时改名不影响用户。陪玩的提醒动作改为创建“延迟 + 播报”的执行；此前没有独立的提醒工具，Agent 由此获得查看与取消提醒的能力。

### 7. 存储与兼容

- 定义存 `~/.kotone/automations.json`，调度与执行记录存 `~/.kotone/automation-runs.json`，都带 `version`，原子写入；
- 第一次启动时把 `reminders.json` 里**尚未到期**的提醒导入为“延迟 + 播报”的执行记录，并在新文件里记下已导入；`reminders.json` 不改不删，0.1.13 仍可读。代价：回到旧版时看不到新版里创建的提醒；
- 配置里已有字段的值不变（如 `assistant.route` 仍写 `reminders`）；新增配置一律用新字段；
- 上限：等待中 ≤ 100、同时运行的程序 ≤ 3、延迟 ≤ 7 天、源码 ≤ 8000 字、执行记录保留 ≤ 1000 条。

### 8. 界面

左侧导航：通用 · 文字处理 · 陪玩 · **自动化** · 游戏适配 · 历史记录 · 高级 · 关于。

- **陪玩**：AI 连接、能力自检、自动发送、**快捷指令**（一个列表，每项选“交给 AI 的一句话”或“直接执行的已保存自动化 + 参数”，可绑热键）；
- **自动化**：「进行中」（等待中与运行中放在一起，倒计时、取消、停止）、「已保存」（编辑、入参、框选 / 取色）、「记录」、停止热键；
- **声音与弹幕**（声音、音量、语速、弹幕外观）从陪玩移到「通用」。

## 结果

提醒、陪玩里的“帮我按键”、热键触发的固定动作和 Agent 的调用落到同一套模型、同一个调度器、同一个“进行中”列表和同一组停止方式上。云函数式的三层结构让保存、复用与入参自然成立，而“最多一次、错过不补、绑定窗口、人能停”这几条把它和无人值守的后端任务区分开。后续阶段（统一调度器、定义与入参、界面、陪玩第四种动作、框选取色）都以本 ADR 为基础。
