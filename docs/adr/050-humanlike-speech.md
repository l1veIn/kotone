# ADR 050：说话更像真人——人格写成示范、通话规则去掉调度员腔；推送带一句预置的话，打得特别好或特别差时她再说几句

状态：Accepted（2026-11-28）/ 实现中（见文末“实现情况”）。

修订：[ADR 029](029-core-voice-model.md) 第八节的通话规则（“只说结论”改写）、[ADR 043](043-plugin-shape-and-pushes.md) D3 的这局总结和今天的状态（卡片上加一句预置的话）。调研：[说话更有活人感](../research/2026-11-28-humanlike-speech.md)（DSH 社区的“养鱼”插件、MaiBot、N.E.K.O、SillyTavern、AI 主播、图灵测试论文）。

## 背景

玩家：“调研一件事：如何让kotone说话更有活人感？”调研的结论：她听起来不像真人，主要原因是提示词，不是模型。人格只有两行形容词（`workspace.rs` 的 `DEFAULT_SOUL`），通话规则是“最多两句、40 字、只说结论”，没有一句示范，也没写她可以有态度。

玩家看完调研说“可以”（同意先做第一批），又提了一条：

> “我觉得像是插件之类的也可以更加‘拟人’，比如某把游戏结束，玩家打的特别好，推送这局总结时候可以来一句‘Ｃ麻了’，或者更长的给情绪价值的那种，还有今天的状态这里也是，这部分可以预置一些内容”

问玩家这句话由谁来写，玩家选了“预置为主，她补长的”：插件按固定规则从预置的句子里挑一句短的放在卡片上；只有打得特别好或特别差的时候，再叫她说一句更长的。

## 决定

### 她自己（第一批，只改提示词）

1. **人格写成示范对话**（SillyTavern、Ali:Chat：模型从示范里学口气和长度，形容词几乎没用）。三个内置角色（琴音、大肥鱼、Claude大小姐）的默认人格改成：一两行说她是谁、和玩家是什么关系，然后 10 组“玩家说 / 她回”的示范（“只是示范，不是你们真聊过的事”），覆盖被单杀、赢了、输了、骂队友、排队、去吃饭、要不要换英雄、五杀、闲聊这几类；最后一行写“示范只是口气，别照抄原句；同一句话别反复说”（OpenAI 实时语音指南里的 Variety 规则）。示范的三条底线（第一版评测里踩过）：**不描述她没看到的事**（“下路崩成那样”会教她编观察）、**不凭记忆答游戏知识**（出装、版本要先查，规则里有寒冰的例子）、**不贬低玩家、不跟着骂队友**（接情绪，不接骂人）；每句示范的开头字不同，免得口癖集中。玩家没改过人格的（磁盘上和旧的默认一字不差），读的时候按新的；改过的不动。
2. **通话规则去掉调度员腔**（N.E.K.O、airi、Jones & Bergen 的图灵测试、DeepSeek V4 用户反馈）。机制都保留：必须用 speak、最多两句 40 字、先查后说、`written`、`reply.ask`。“只说结论”改成：可以先接一句反应再说事；可以有态度、直接说不同意、可以吐槽；不知道就说不知道；不说谢谢、不客套、不总结升华、不催玩家休息。
3. **每轮附注末尾加一句风格提醒**（SillyTavern 的 Author's Note；DeepSeek V4 的角色扮演指令也放在用户消息末尾；人设 8 轮内就会漂移）。只在通话入口加。附注本来就在用户消息里，只追加，不影响系统提示的前缀缓存。
4. **温度照旧不传**（试过 DeepSeek 官方“通用对话”推荐的 1.3，没采用）。真 Key 评测（23 个游戏时刻 × 4 遍 × 3 个角色，同一份新提示）：不传温度时坏回答（没调 speak、只写正文、括号旁白）0 次，1.15 时 2 次，1.3 时 4 次。通话里没调 speak 玩家就什么都听不到，代价比多样性大；不传时同一时刻几遍之间的重复率高几个百分点（琴音 11% 比 6%），留给第二批的口癖回避表。

### 推送里的一句话（这局总结、今天的状态）

5. **卡片上加一句预置的话**。插件按固定规则从预置的句子里挑一句：同样的数据永远挑出同一句（属于 043 的“固定规则 + 固定说法”，插件分内的事），不同的局换着来。
   - **这局总结**按这局的事实分档：五杀；赢了，伤害全队第一，死得少（“C麻了”这一档）；赢了；输了但伤害全队第一（“尽力了”）；输了。每档一组句子，按对局 id 挑，连着两局同一档时不挑同一句。
   - **今天的状态**按今天的连胜 / 连败和胜负分档（如三连胜以上、三连败以上），按日期和局数挑。
   - 只说她的口气、不评判队友（“队友坑”这类话不写，评判人是她的事，见 043 D2）；输了只安慰，不嘲讽、不劝玩家去休息。
   - 句子写在插件的 messages 里（中英文各一套），跟角色无关。
   - 卡片上显示；给她的那句说明里也带上这句（她知道卡片上说了什么，免得接着说重复的）。不念出来：这两条推送本来就只有卡片这一种样子。
6. **打得特别好或特别差时她再说几句**（照“突破口”的做法：插件报事实，判断和措辞在自动化里交给她，ADR 046）。
   - 英雄联盟插件加一个事件 `lol.game_end`：这局结算、拿到结果时报一件，数据是事实——赢没赢、模式、时长、我的英雄、K/D/A、伤害在全队排第几、有没有五杀、今天现在几连胜 / 连败。
   - 加一个内置自动化“这局打得特别好或特别差时她说几句”：按 `lol.game_end` 触发，程序里判断够不够“特别”（例如赢了伤害第一、五杀、三连败以上），够了才用 `ask()` 交给她：用你的口气说一两句给玩家情绪价值的话，可以接着卡片上那句说，不重复它；没什么想说的就不说。
   - 每次真叫她花一次 AI 调用，只在特别的局才叫，所以默认开；在「自动化」页可以关。
   - **允许她不说**（MaiBot、dsh-fish、N.E.K.O）：`ask()` 交给她的这一轮，她不调用 speak、也没写字就结束，不在聊天里留空消息。

## 不做

错别字、表情包、星号动作、打字延迟、好感度数值、在提示里列禁用词。理由见调研第五节：念不出来，或者已经证实没用。口癖回避表、喂回模型的历史去套话、对局心情、自然提起旧事是调研里的第二、三批，这一轮不做。

## 实现情况

### 第 1–4 条：人格、通话规则、风格提醒（2026-11-28）

- `crates/kotone-agent/src/workspace.rs`、`roles.rs`：三个内置角色的新人格；旧文本留作 `LEGACY_DEFAULT_SOUL` / `LEGACY_SOULS`，`role_soul` 读到和旧默认一字不差的文件就按新的读（不改磁盘）。
- `prompt.rs`：通话规则删掉“只说结论，像打电话一样口语”和“现在什么版本→26.22”的例子（等于教她报版本号），改成“像真人打电话：可以先接一句反应再说事”；两个入口共用一句“照你的人格说话：可以有态度、直接不同意、吐槽；没看到、不知道的就直说，别编；不说谢谢、不客套、不总结升华、不催玩家休息”。通话入口的附注末尾加“说话照你人格里的口气，短。”，系统提示不变（测试断言）。
- 评测：`scripts/manual-e2e/humanlike_eval.py`（真 Key，`--variants` 选对比哪几组；导出提示的是 `kotone-agent` 里 `#[ignore]` 的 `export_humanlike_eval_prompts`）。最终提示对旧提示：问句结尾约 50% → 24–32%，“随时 / 要不要我帮你”这类客服腔没了；要查的题 12/12 先查（搜索或看屏幕），没查就报数字 0/12；坏回答 2/552，和旧提示同一水平。还没解决：几句示范的说法会被反复借用（大肥鱼“尾巴都竖起来了”），留给口癖回避表。

### 第 5、6 条：推送里的一句话、`lol.game_end`、内置自动化（2026-11-28）

**玩家看到的**：

- “这局总结”卡片标题下面多一行小字，是插件按这局的事实挑的一句（“C麻了”“尽力了，伤害第一还输”“没事，下把再来”）；全屏单局详情在标题行下面。她收到的那句说明末尾写着“卡片上写了：“C麻了”。”，不念出来。
- “今天的状态”卡片标题下面同样一行（“今天手感火热”“换个英雄换换手感？”），只在三连胜 / 三连败以上、或打了 3 局以上胜多负少 / 负多胜少时有；打平、只打了一两局没有。不给她留话（照 043 B 轮第 3 条：一天里一直在变）。
- 「自动化」页多了一个内置的“英雄联盟这局打得特别好或特别差时她说几句”，默认开：赢了而且伤害全队第一、拿了五杀、或者今天已经三连败时，一局结束她接着卡片上那句再说一两句；别的局不叫她、不花钱。

**怎么做的**：

- **句子**（`plugins/lol/messages/{zh-CN,en}.json`）：每档一条 `plugin_lol_cheer_<档>`，几句用 `|` 隔开，中英文每档句数一样。这局总结 5 档各 8 句（`penta`、`carry`、`win`、`lost_top`、`loss`），今天的状态 4 档各 6 句（`today_hot`、`today_cold`、`today_up`、`today_down`）。插件只在页面数据里放 `cheer: {tier, index}`，页面按界面语言取（`app/src/format.ts` 的 `cheerLine`）；给她的那句用中文那套。
- **分档和挑句子**（新模块 `plugins/lol/src/watcher/auto_cards/cheer.rs`，纯函数）：
  - 这局总结（`game_tier`，从上往下第一条对得上的）：这局有五杀（单局详情的 `pentaKills`，`pages::game_page_for` 每行新加了这个字段，详情里没有时是 null）→ 赢了、伤害全队第一、KDA ≥ `CARRY_KDA` = 5（用 KDA 不用死亡数：大乱斗、海斗里死得本来就多）→ 赢了 → 输了但伤害全队第一 → 输了。按对局 id 对句数取模；上一局挑的（档，第几句）记在 `CardState.last_cheer`（不落盘），同一档又挑到同一句时换下一句。
  - 今天的状态（`today_tier`）：连胜 ≥ 3 → 连败 ≥ 3 → 至少 3 局且胜多负少 / 负多胜少；按日期里的数字加今天的局数取模（同一天同样的局数挑出来的一样，卡片内容不变，宿主照旧回“没变”）。`today::today_page` 多一个字段 `cheer`（`{tier, index}` 或 null）。
- **给她的那句**：`summary_note(page, me, cheer)` 末尾加“卡片上写了：“…”。”，照样不超过 160 字。
- **`lol.game_end`**（`watcher/auto_cards.rs` 的 `summary_card`）：拿到这局的详情、发完这局总结之后报（先推后报：她被自动化叫起来时卡片和说明已经在对话里了）。`summary_card` 本来就不看推送开没开（开关由宿主在 `Host::push` 里管），所以推送关着也报。自定义、训练、观战、重开局、60 秒拿不到结果、详情里找不到自己的不报。数据（`game_end_data`，camelCase，`plugin.toml` 里登记）：`win`、`queue`、`durationSeconds`、`champion`（短名字）、`kills`、`deaths`、`assists`、`damageRank`（1 = 全队第一）、`pentaKill`（详情里有这一项才给）、`todayWinStreak` / `todayLossStreak`（算上这局今天现在几连胜 / 几连败，另一个是 0）。连胜连败要读一次自己的战绩（这一局多半还没进去，`today::streak_after` 按这局的结果接上，进去了也不重复算；“今天”按开局时间、本地 0 点分界，和今天的状态一样）；读不到时这两个字段都不给，程序里按缺省 0 算。
- **内置自动化**（`crates/kotone-core/src/automation/library.rs` 的 `builtin_lol_game_end`，id `builtin-lol-game-end-cheer`）：按 `lol.game_end`（game: lol）触发、**默认开**、不绑游戏窗口。参数 `win`、`damage_rank`、`penta_kill`、`today_loss_streak` 由事件的同名字段自动填上（ADR 036 D6）。程序：

  ```lua
  -- 这局打得特别好或特别差才叫她（args.* 由“这局结算了”自动填上）。下面的数字可以改
  local LOSS_STREAK = 3 -- 今天连败到几局算“特别差”
  local great = (args.win and args.damage_rank == 1) or args.penta_kill
  local rough = args.today_loss_streak >= LOSS_STREAK
  if not (great or rough) then
    return
  end
  ask("这局刚结束，这局总结的卡片上已经有一句预置的话了（给你的说明里写着）。这局的结果看附上的游戏事件。用你的口气说一两句给玩家情绪价值的话，可以接着卡片上那句说，别重复它。没什么特别想说的就不说：不调用 speak、也不写字，直接结束。")
  ```

  `ask()` 的话是写死的，不拼事件里的值（护栏会拒）；这局的结果她看 `ask_message` 附上的游戏事件。**没开“一局一次”**：一局只有一件 `lol.game_end`（`game.match_ended` 在它之前就把这一局的次数清零了），开了反而让玩家改了程序再存时多一条“判断不满足也会占掉一局一次”的提醒（`trigger_hints`）；每局叫她最多 3 次的上限照旧。老用户升级时也装上（内置自动化按 id 只装一次，删了不装回）。「自动化」页列表上标“内置”（`AutomationList.svelte`）。
- **“允许她不说”**：现在 `ask()` 交给她的那一轮走通话入口（`entry_of`：来源 `automation` 是 `Entry::Call`），系统提示写着“这一轮必须用 speak 回答”。她什么都不写、不调 speak 就结束时：`kotone-ai` 的循环把第一次的空回复丢掉、同样的请求再发一次（多花一次调用），还是空就收下一条空的回复；聊天和悬浮窗的小窗都不显示空的回复（`timeline.ts` 只在有字时加一块），气泡的“在想…”在这一轮结束时收起，不出声。所以“不在聊天里留空消息”本来就是这样。这次只对来源 `automation` 的一轮（`context.rs` 的 `is_automation_ask`）再改了四处，玩家自己开口的通话一轮不变：① 空回复不重发：`AgentLimits` 加一个开关 `retry_empty_reply`（默认 true），`kotone-ai` 的 `run_turn` 只在它开着时重发；桌面端语音入口的上限抽成 `context.rs` 的 `call_limits`，自动化交给她的一轮关掉它（她故意不说时不再多花一次调用）。② 1.2 秒没出声不替她说“我看看”（`context.rs` 的 `wants_filler`，`turn.rs` 的 `drive` 用它）。③ 只写了字、没调 speak 时结尾不念“我写在聊天里了”（`voice.rs` 的 `closing_line` 看这一轮第一条消息的来源；出错、没做完的那两句照旧念）。④ 系统提示 ask 那条规矩补半句“自动化交给你的那一轮，话里说了可以不说就可以不说”（`prompt.rs` 的 `COMMON_RULES`；下一段对话的前缀缓存失效一次）。内置自动化 `ask()` 的话里也写明了“没什么特别想说的就不说：不调用 speak、也不写字，直接结束”。她在这一轮写了字却忘了调 speak 时：字照常记进聊天（主窗口、悬浮窗的聊天小窗开着时也看得到），但不出声、气泡不显示、也不再念“我写在聊天里了”，玩家不看聊天就不知道她说了什么——这一点没改，留着观察。测试：`kotone-ai` 1 个（关掉开关时空回复直接收下、只请求一次、没有撤回事件），桌面端 `context.rs` 1 个（自动化那一轮不重发、不接“我看看”，语音、唤醒、快捷指令、工具来的一轮照旧；聊天、后台交回的照旧不接）、`voice.rs` 原有测试加 3 个断言（只写了字 / 什么都没写不补话，出错照旧说），`kotone-agent` 系统提示的规矩测试加一句。
