# ADR 038：Kotone 是什么——她，加上装在她身上的插件（照 MCP Apps）

状态：Accepted（方向，2026-11-24）。部分由 [ADR 039](039-desktop-companion-and-game-apps.md) 修订（2026-11-25，改了哪些见“怎么定的”最后一条）。

玩家定了方向：本体轻，复杂度都放进插件；语音输入是典型的插件；界面上叫“插件”。原话：

- “这些 Apps 应该有自己独立的目录，收敛属于它们自己的复杂度。配置页也可以大幅度减负。”
- “我只能给你说大致的方向，很多细节我把握不住。”

所以下面的细节由 Claude 按 D3 的原则定，做的时候写进实现记录，玩家看结果。MCP Apps 是插件里“界面”那部分的规范。

## 背景

玩家（2026-11-23 到 24）讨论战绩怎么显示时说：

- “为什么不直接参考 LeagueAkari 这类战绩软件做一个完整的页面？……这个卡片本身就是一个完整的 LeagueAkari，用户可以查看、点击用户跳转到玩家个人战绩……我们的 Agent 不需要自己拼 json，只需要导航到这个页面就行……数据类工具我也是这么想的。”
- “我们也需要做成 MCP Apps 或者 OpenAI Apps SDK，音乐那套也应该规范一下……这些 Apps 的边界是怎样的？……通过这种 Apps 的方式可以拆分出很多工具出去。”
- “游戏语音也拆出去……我们可以把整个架构做的轻量又简单，所有的复杂度拆到 MCP App 里去，我们甚至现在可以确定下来‘我们到底是什么’。”
- “游戏聊天或者说语音输入法都应该算 APP……自己本身就有完整功能的 app。自动化应该是一个特殊的，可以操作其他 APP 的 APP……或者自动化应该不算 APP？界面上可以叫插件？”

Kotone 的定位改过几次：

| 时间 | 定位 |
| --- | --- |
| 0.1.x | 游戏里的语音输入法 |
| 2026-11-15（[产品演进 §1](../product-evolution-game-tools.md)） | “固定定位为工具”：人格和对话交给外部桌宠，Kotone 给本机能力 |
| ADR 014、028、029 | 内置的她成了中心：玩家只要一个 Key 和一个呼叫键 |
| 2026-11-23 | 功能越来越多：主会话 35 个工具，工具服务 72 个，还在往里加。一个英雄联盟工具要在 8 个地方改，每加一样本体就重一点 |

## 参考了谁

| 照搬什么 | 来自 |
| --- | --- |
| **界面 = 工具 + 它自己的页面**：工具声明用哪个页面（`_meta.ui.resourceUri` 指向 `ui://` 资源）；宿主拿工具结果把页面画出来，用户在页面里操作不经过模型；给模型的文字（`content`）和给页面的数据（`structuredContent`）分开；不支持界面的宿主照样能用文字 | [MCP Apps](https://modelcontextprotocol.io/docs/extensions/apps)（MCP 第一个官方扩展） |

| **英雄联盟插件照着做（统计和覆盖层部分）**：海斗选英雄看胜率、三选一时评分直接贴在海克斯卡片上、角上按需出现的详情按钮；只靠截图识别；识别时遮掉自己画的东西 | [aramhex](https://github.com/czgreat/aramhex)（代码 MIT，数据 [aramhex-data](https://github.com/czgreat/aramhex-data) CC BY-NC，要署名） |

Kotone 已经有 `kotone.exe mcp`：把所有工具作为 MCP 工具对外提供。照 MCP Apps 做，以后 Claude Desktop 这类宿主也能显示 Kotone 的页面。

## 决定

### D1 一句话

**Kotone 是一个陪你打游戏的角色。她听得见、看得见、说得出、记得住；她会的本事都装在插件里。你和外部 Agent 用的是同一套插件。**

- “她”是产品，插件是她的本事。
- “能力都开放给 Agent”（产品演进 §1）不变，现在按插件开放。

### D1.1 为什么还要她

玩家问（2026-11-24）：“这些都是可以独立使用的，那么我们还要 kotone 干嘛？……加入 Agent 有哪些进阶的体验和功能？我们总要超越 LeagueAkari 的吧？”

插件要做到不叫她也好用（“先有完整功能，再开放给 Agent”），这样她说的话有可靠的数据，玩家也能点开卡片核对。但 Kotone 不是“更好的 LeagueAkari”，是**一个自带 LeagueAkari 和 OP.GG 的游戏队友**。LeagueAkari 是仪表盘，她是会帮你看仪表盘的队友：

| | LeagueAkari / OP.GG | 有她以后 |
| --- | --- | --- |
| 对局中 | 要切出去看，团战里切不了 | 开口问、耳边答（“谁没闪”“对面 AD 出了什么”） |
| 信息 | 一屏数字，自己读 | 只说要紧的一句（“对面辅助五连败，劫第一次玩”） |
| 跨插件 | 战绩和数据是两个软件 | 合起来说（“对面亚索是绝活，克你的艾瑞莉娅，前期别换血”） |
| 时机 | 你去点它 | 按游戏事件主动说（加载界面说突破口，阵亡时说出装） |
| 动手 | 用鼠标点 | 说“阿狸闪了”就记下；“发出去”打进聊天；放歌、跟队友语音 |
| 记性 | 每局从零开始 | 记得你的英雄池、常犯的错、上局谁单杀了你，赛后复盘 |
| 游戏 | 只管一个游戏 | 同一个她陪你玩所有游戏 |

所以插件不逐项追 LeagueAkari 的功能，会封号的（自动接受、自动选英雄）本来也不做。插件做到稳、准、能看；赢在她：一句话的判断、跨插件、按时机主动、动手、记得你。

### D2 本体

判断一样东西是不是本体，就问：**没有它，她还是她吗？**

| 本体 | 包括 |
| --- | --- |
| **她** | 角色卡（名字、声音、人格）、记忆（含复盘）、对话（主会话马上答、后台慢慢做）、技能、联网搜索、提醒（过一会儿说一句） |
| **感官和表达** | 耳朵：麦克风、呼叫、唤醒、语音识别、热词。眼睛：看屏幕、文字识别、读游戏聊天（截图 + 文字识别 + 聊天跟踪）。知道你在玩什么：游戏列表、游戏配置、游戏中心（ADR 036 的状态和通用事件）。嘴：语音、气泡、弹幕。**手**（2026-11-24 补）：看着游戏点和按（computer use，`game.look` / `game.act`，ADR 019）、在网页上操作（内置浏览器，`browser.*`，ADR 031） |
| **自动化** | 什么时候做什么。触发：手动、她调用、热键、定时、游戏事件。动作：说一句、让她做、调用任意插件给她的工具。权限照常，保存时问玩家一次。照 Home Assistant：一个能调用所有插件的东西本身就是宿主，所以它不是插件 |
| **宿主** | 插件的清单、开关、权限（允许 / 询问 / 禁止）、她的工具清单、页面怎么显示（聊天卡片、右侧栏、左侧栏的“插件”页）、对外接口（工具服务、MCP、CLI）、模型连接和用量、诊断、开机启动、更新 |

剩下的都是插件。

### D3 插件的边界

1. **一个插件就是你不叫她也会打开来用的一块东西**：有自己的页面，有自己的数据来源。
2. **开关和风险提示都在插件身上**，例如英雄联盟“读这局的数据”。插件关掉，它的工具、页面、事件都没了。
3. **给她的工具尽量少**，每个插件 1 到 4 个，都是入口型的（“查这局的战绩”）。页面里翻页、看详情、搜索要用的工具标成只给页面用（`visibility: ["app"]`）。
4. **工具结果分三份**：
   - 给她的文字：很短，她要拿来说话；
   - 给页面的数据：她那一刻看到的样子，存进记录；
   - 用哪个页面显示：`ui://kotone/<插件>/<页面>`。
5. **插件之间不直接调用。** 要配合就经过她（她先后调两个插件的工具），经过自动化，或者经过游戏事件。
6. **她的工具清单只跟着开关变，不跟“现在在玩什么”变。** 一段对话里工具清单不变，DeepSeek 的前缀缓存才命中（ADR 024）。
7. **插件用本体的能力，不自己再做一份**：听（录音、语音识别）、看（截图、文字识别）、说（语音、弹幕）、调她。麦克风只有一个，识别模型也只该下一份；本体给插件的是“听一句”（开始录、停下、边听边给识别出来的字），插件拿到字以后做自己的事。
8. **一个游戏一个插件**：同一个游戏的战绩、统计、覆盖层放在一个插件里；不同的数据来源用插件里的开关和风险提示分开（`plugin.toml` 的 `sources`）。只关一个来源，插件里用得上的部分照样能用。
9. **游戏配置在本体，但只留游戏本身的事**：名字、图标、进程名、窗口标题、启动路径（游戏列表）；热词（耳朵）；陪玩说明（她）；聊天框位置（眼睛，读聊天用）。插件对某个游戏的设置存在插件自己那份设置里，按游戏 id 分开（`plugins.<插件>.games.<游戏>`），游戏配置页下面显示各插件提供的小节。内置的 lol、dota2、cs2 是游戏配置，不是插件；游戏专用的插件用 `games = [...]` 挂在它们上面。
10. **游戏专用的插件自己带游戏中心的适配器**，例如英雄联盟插件带 `lol` 适配器（ADR 036）。本体只知道哪个游戏在跑、在哪个阶段；游戏里面发生什么，由插件报告。

**落地时先答四个问题**（2026-11-24 加，“浏览器和 computer use 放哪”的讨论之后；详见 [软件哲学](../philosophy.md) 原则 12）：

1. 谁用它：她、玩家、还是别的插件？有几个用户？
2. 它要动本体的什么状态：窗口、全进程只有一份的钩子（Esc、呼叫键）、停下她、免问？
3. 关掉它会连带谁？
4. 放错了以后挪，要动什么：单向门还是双向门？

有两个以上的用户，或者要动本体的状态，就放本体；否则做成插件。四个答案都要能拿代码核对，答案写进实施记录。上面第 1 条（“你不叫她也会打开来用”）只用来判断一样东西值不值得有自己的页面，不单独用来判断放本体还是插件。

### D4 插件清单

| 插件（目录） | 页面 | 给她的工具 | 只给页面用的 | 现在的代码 |
| --- | --- | --- | --- | --- |

| **按键程序**（`key-programs`） | 程序编辑、内置的宏（连发、连点、按住……）、每个游戏允不允许程序按键 | 运行程序 | 编辑器里的校验、存图片 | `kotone-script`（ADR 013） |

自动化里的“程序”动作，就是调用按键程序插件的工具。

英雄联盟是一个插件，里面有两个数据开关（玩家 2026-11-24 同意合并）：“读客户端数据”和“用网上的统计”，各带风险提示。先是按玩家说的“需要包括查战绩 app 和 op.gg 的数据 app”拆成两个，后来发现最好用的功能都要同时用两边的数据（选英雄时给已选的英雄标胜率、三选一按这局的英雄打分、阵亡时按对面的装备说出装）：分开的话要么只能经过她，要么得打破“插件之间不直接调用”。LeagueAkari 自己就带 OP.GG 和腾讯的数据，aramhex 也是一个软件。

**每个插件的页面、工具、数据来源、代码在哪、怎么搬，见 [插件重构计划](../plugin-refactor.md)。**

### D5 契约（照 MCP Apps）

- **每个插件一份清单**（`plugin.toml`）：
  - id、名字、说明；
  - 页面列表（`ui://kotone/<id>/<页面>`）；
  - 工具列表，每个标给她还是只给页面；
  - 开关和风险提示；
  - 挂在哪些游戏配置上（游戏专用的插件）；
  - 带哪个游戏中心适配器。
- **工具结果**：`content`（文字）、`structuredContent`（数据）、`_meta.ui.resourceUri`（页面）。只有文字进她的上下文。
- **页面怎么显示**（三个位置都由本体提供，插件不自己开窗口）：
  - 聊天流里是这个页面的小尺寸版本（快照），点开在右侧栏显示完整页面，旁边还能接着和她聊；
  - 不叫她也能直接打开：左侧栏有一个“插件”页，每个插件一张卡片（照 MCP Apps：一个插件就是一个 App），卡片上有开关；点卡片进这个插件的 App，整块内容区都是它的，用它自己的界面风格，宿主只留一条“← 插件 · 名字”。数据开关和风险提示在插件自己的界面里。以后第三方的 MCP Apps（从别的仓库拉来的）也是这里的一张卡片，在同一个位置打开（沙盒 iframe）。2026-11-24 玩家定的，见“怎么定的”；常用的另有捷径（聊天卡片、`ui.open`、音乐的小播放条）；
  - 游戏上方的覆盖层：贴在某个角或某块区域上（例如海斗三选一的三张卡片），照 aramhex。覆盖层只有一个，在本体里（气泡、弹幕、悬浮窗本来就在本体），置顶、点击穿透、性能、截图时遮掉自己这些难的部分只写一次。
- **`ui.open {plugin, page, params}`**：她（和外部 Agent）直接打开某个页面，例如“打开我的战绩”。本体的设置页也给地址，她可以带你过去。
- **她的系统提示**：能力概览按插件列，关着的不列。
- **工具只定义一次**：她的工具清单、工具服务、MCP 都从插件清单里读。

### D6 目录

```
crates/                本体：kotone-core（设置、游戏列表、游戏中心、自动化）、kotone-agent / -ai（她）、
                       kotone-stt / -tts / -ocr / -platform-windows（感官和表达）、
                       kotone-plugin-api（新：插件契约）、kotone-tools / -cli（对外接口）
apps/desktop/          宿主：窗口、聊天、侧栏、本体设置、加载插件
plugins/<id>/          每个插件一个目录，自己的复杂度自己收着：
  plugin.toml          清单（D5）
  Cargo.toml, src/     数据来源、工具实现、游戏中心适配器；依赖 kotone-plugin-api、kotone-core 和自己的第三方库，
                       可以用系统适配层（kotone-platform-windows）里没有状态的系统调用（音频设备、重采样、打字注入……）；
                       不碰 Tauri、桌面端、她（kotone-agent / -ai），全进程只有一份的东西（Esc 和呼叫键的钩子、
                       停下她、免问）只经宿主（2026-11-24 定，见“怎么定的”）
  ui/                  页面和它的设置页
  messages/            自己的中英文文案
  skills/              给她的技能（可选）
  e2e/                 页面的测试
  README.md            是什么、数据从哪来、有什么风险
```

- **宿主和插件之间只有 `kotone-plugin-api` 这一条缝**：
  - 插件实现“我是谁、有哪些工具、调用工具、后台开始跑”；
  - 宿主交给插件的是本体的能力：开口说、弹幕、自己那份设置和存储目录、往游戏中心报事、凭据库、语音识别和文字识别。
- **一期的插件都是内置的**，编译在一起，不做动态加载。
- **设置页减负**：
  - 本体设置只剩：她（角色、声音、怎么回答）、听（呼叫、唤醒、语音识别）、看（文字识别）、游戏列表、模型和连接、权限、自动化、插件（一张列表，每个一个开关）、关于；
  - 插件的设置在它自己的页面里；
  - 配置文件里插件的设置放到 `plugins.<id>` 下面，旧字段照兼容规则迁过去。

### D7 分期

每一步都能单独编译、单独提交；每搬一个插件，报一下本体删了多少行、玩家能看到什么变化：

1. **契约和宿主**：`kotone-plugin-api`、插件注册、`ui.open`、聊天卡片、右侧栏显示插件页面、设置里的“插件”页。
2. **英雄联盟**：最新、边界最清楚；顺便做这局、玩家、单局三个页面。
3. **音乐、游戏语音、同传。**（浏览器原来也在这里，2026-11-24 改成留在本体，见下面“怎么定的”）
4. **语音输入**：最大的一块，有悬浮窗、文字处理、注入、挡键。
5. **按键程序。**
6. 以后：`kotone.exe mcp` 提供 `ui://` 资源，外部宿主能显示；Kotone 的聊天里显示别人的 MCP Apps（沙盒 iframe）。

## 怎么定的（2026-11-24）

- **游戏聊天**：语音输入是插件，往聊天框打字的一套都在里面，她替你发言也走它。
- **语音识别只有一份，在本体**（玩家问：“语音输入法插件自己有 ASR，然后本体也有 ASR 吗？”）：语音输入插件像手机输入法，麦克风和识别由“系统”（本体）提供，插件管什么时候听、听到的字怎么处理、送到哪里。读聊天是截图加文字识别，属于本体的“眼睛”。起初分错到了语音输入里，玩家指出：“读聊天怎么能是语音输入呢？不是 OCR 吗？”
- **自动化**留在本体；Luau 程序、内置宏拆成“按键程序”插件。
- **浏览器和 computer use 留在本体，是她的“手”**（2026-11-24 后来改的；原来浏览器是插件，computer use 在“按键程序”里）。玩家问“ADR 里写了浏览器也进插件吗？这里我们如果再次讨论，会有不一样的结果吗？”，又说“我也是觉得，浏览器操作可能不太适合插件化。我记得我们 kotone 还有 computer use 对吗？”，先改成了两个都留在本体。之后玩家说“我有些摇摆不定，这个 computer use 和 browse use 的归属问题看起来是一个影响深远的决策”，请几个子代理讨论：一方论证留在本体、一方论证做成插件、一个不带立场的调研员查成熟项目（Goose、OpenClaw、Hermes、Claude、Codex、VS Code、Home Assistant），两轮之后由没参与的裁判判。结论：
  - **两个都留在本体。** computer use 底下那层（绑住游戏窗口、截图、按键、输入锁）不只它在用：插件的“截一块识别文字”（英雄联盟读三选一）和按键程序都用它，放进插件就成了本体的眼睛反过来依赖插件；look / act 这层要在 Esc 时停掉她这一轮、要免问，都是她自己的回路，做成插件就得把“停掉她”“免问”这类权力开给插件，换来的只是插件列表里一张卡片。浏览器的代码是主窗口里的网页视图，硬叫它插件一行也隔离不了。
  - **原来写的理由错了**：浏览器其实过得了 D3 第 1 条（11-21 起它是玩家自己也会用的完整浏览器：多标签、地址栏、扩展）。它留在本体的理由是：它和覆盖层一样是本体给的显示面（D5），代码离不开主窗口。
  - **成熟项目**：都让这两样能单独开关（computer use 默认关或要单独打开，浏览器多半默认开），开关放在哪和是不是插件无关；按实现边界分的（Goose 的平台扩展、Home Assistant 的必加载集成）把要直接动宿主内部状态的放在核心层。
  - **有多深远**：一期插件都编译在一起，代码放哪、开关摆哪以后都能改；真正难回头的是给插件开的大权力（等以后“每个插件一个进程”就收不回来），所以少开。
  - **跟着定的**：每个游戏“允不允许程序按键”（`allowAutomationInput`）和“让她操作”（`computerUse`）都留在游戏配置里（这个游戏容不容忍模拟输入是游戏自己的事，D3 第 9 条），按键程序插件经宿主读；程序按键和她操作只用一把输入锁；`screen_text` 挪进本体的眼睛；本体的工具也走统一的 `ToolSpec` 登记（超时、放宽步数、免问），删掉写死的名单。
  - **浏览器的开关放在设置里**（玩家选的；另一个选项是插件列表里一张卡片）：设置里“浏览器”一节有开关（默认开）、扩展（Chrome 扩展改叫“扩展”，免得和插件撞名）、清除登录、同意过的网站。
- **插件可以用系统调用，不能碰本体的状态**（2026-11-24，讨论时发现游戏语音插件用了系统适配层的音频设备列表和重采样，和第一步写的“不再直接依赖 kotone-platform-windows”冲突）：系统调用（音频设备、重采样、打字注入）放在哪个进程都一样能调，不妨碍以后“每个插件一个进程”；难收回来的是本体的状态和权力。所以插件可以用系统适配层里没有状态的部分；全进程只有一份的钩子（Esc、呼叫键）、停下她、免问只经宿主。
- **左侧栏不放插件入口**（玩家：“插件组没必要吧，进入插件页面再点击插件详情好一点，没必要侧边栏放一堆插件入口”）：插件都在“设置 → 插件”，点开是插件自己的页面；音乐另有左侧栏的小播放条（在放的时候）。
- **插件是一个单独的左侧栏页面，每个插件是一张 App 卡片**（2026-11-24 后来，改掉上一条的“放在设置 → 插件”）。玩家：“我觉得插件应该得是一个单独的侧边栏页面，每个插件应该是一个卡片，对应我们 MCP APP 的概念，点击卡片进入插件或者说 APP 界面，不同的插件可以有完全不同的界面设计语言，因为这都是独立的 APP，以后肯定会加入第三方插件，从其他仓库拉取 MCP apps 的。”于是：左侧栏只有一个“插件”入口（不是每个插件一项，上一条“不放一堆入口”仍然成立）；“插件”页是 App 卡片墙，卡片上有开关；点卡片进 App，宿主不管它长什么样（不套宿主的页边距、标题），只留“← 插件 · 名字”；“设置 → 插件”去掉（只留一个地方）。内置插件现在还是编进宿主的 Svelte 页面，但 App 的位置按“以后放一个沙盒 iframe”的样子留（MCP Apps：`ui://` 资源是一个 HTML，宿主在沙盒 iframe 里显示，经 postMessage 调工具）。
- **提醒、联网搜索、游戏列表、看屏幕**留在本体。

## 不做

- 不让模型拼界面 JSON，不让模型写 HTML。
- 一期不装第三方插件。但方向定了（玩家 2026-11-24：“以后肯定会加入第三方插件，从其他仓库拉取 MCP apps 的”）：第三方插件就是别人的 MCP 服务器和它的 MCP Apps；宿主要做的是装 / 开关 / 权限，以及在“插件”页和聊天里用沙盒 iframe 显示它们的 `ui://` 页面（D7 第 6 期）。所以给内置插件开的宿主能力要分级：第三方拿到的是更窄的一份（软件哲学原则 11：给插件的权力是单向门）。
- 不按“现在在玩什么”增减她的工具。
