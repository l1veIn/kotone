# ADR 038：Kotone 是什么——她，加上装在她身上的 App（照 MCP Apps）

状态：Proposed（2026-11-23），等玩家确认 D1–D6，尤其是“要玩家定的”那几条。

## 背景

玩家（2026-11-23）讨论战绩怎么显示时说：

- “为什么不直接参考 LeagueAkari 这类战绩软件做一个完整的页面？……这个卡片本身就是一个完整的 LeagueAkari，用户可以查看、点击用户跳转到玩家个人战绩……我们的 Agent 不需要自己拼 json，只需要导航到这个页面就行……数据类工具我也是这么想的。”
- “我们也需要做成 MCP Apps 或者 OpenAI Apps SDK，音乐那套也应该规范一下……我们需要哪些 Apps 呢？这些 Apps 的边界是怎样的？……通过这种 Apps 的方式可以拆分出很多工具出去。”
- “游戏语音也拆出去……我们可以把整个架构做的轻量又简单，所有的复杂度拆到 MCP App 里去，我们甚至现在可以确定下来‘我们到底是什么’。”

Kotone 的定位改过几次：

| 时间 | 定位 |
| --- | --- |
| 0.1.x | 游戏里的语音输入法 |
| 2026-11-15（[产品演进 §1](../product-evolution-game-tools.md)） | “固定定位为工具”：人格和对话交给外部桌宠，Kotone 给本机能力 |
| ADR 014、028、029 | 内置的她成了中心：玩家只要一个 Key 和一个呼叫键 |
| 现在 | 功能越来越多：主会话 35 个工具，工具服务 72 个，英雄联盟、音乐、游戏事件、数据类工具还在往里加，每加一样本体就重一点 |

## 参考了谁

| 照搬什么 | 来自 |
| --- | --- |
| **一个 App = 工具 + 它自己的界面**：工具声明用哪个界面（`_meta.ui.resourceUri` 指向 `ui://` 资源）；宿主拿工具结果把界面画出来，用户在界面里操作不经过模型；工具结果里给模型的文字（`content`）和给界面的数据（`structuredContent`）分开；不支持界面的宿主照样能用文字 | [MCP Apps](https://modelcontextprotocol.io/docs/extensions/apps)（MCP 第一个官方扩展） |
| **只给界面用的工具**：`_meta.ui.visibility: ["app"]`，不进模型的工具清单，界面照样能调 | MCP Apps |
| 和 ChatGPT 的 App 用同一套：OpenAI 2026-02 起兼容 MCP Apps，自己的 `window.openai` 成了可选扩展 | [OpenAI Apps SDK](https://developers.openai.com/apps-sdk/reference) |
| **本体小、本事都在集成里**：核心只管状态、事件、自动化和界面，每种设备、服务是一个集成，能单独装、单独开关 | Home Assistant |
| 不采用：模型自己拼界面 JSON（A2UI）、模型现写 HTML。慢、费 token；数据里有别人起的名字，容易被注入 | A2UI、CopilotKit 的“生成式界面” |

Kotone 已经有 `kotone.exe mcp`：把所有工具作为 MCP 工具对外提供。照 MCP Apps 做，以后 Claude Desktop 这类宿主也能显示 Kotone 的页面。

## 提议的决定

### D1 一句话

**Kotone 是一个陪你打游戏的角色。她听得见、看得见、说得出、记得住；她会的本事都装在 App 里。你和外部 Agent 用的是同一套 App。**

- “她”是产品，App 是她的本事。
- “能力都开放给 Agent”（产品演进 §1）不变，现在按 App 开放。

### D2 本体只有三块

判断一样东西是不是本体，就问：**没有它，她还是她吗？**

| 本体 | 包括 |
| --- | --- |
| **她** | 角色卡（名字、声音、人格）、记忆（含复盘）、对话（主会话马上答、后台慢慢做）、技能、联网搜索、提醒（过一会儿说一句） |
| **感官和表达** | 耳朵：麦克风、呼叫、唤醒、语音识别、热词。眼睛：看屏幕、文字识别。知道你在玩什么：游戏列表、游戏配置、游戏中心（ADR 036 的状态和通用事件）。嘴：语音、气泡、弹幕 |
| **宿主** | App 的清单、开关、权限（允许 / 询问 / 禁止）、她的工具清单、页面怎么显示（聊天卡片、右侧栏、左侧栏）、对外接口（工具服务、MCP、CLI）、模型连接和用量、诊断、开机启动、更新 |

剩下的都是 App。

### D3 App 的边界

1. **一个 App 就是你不叫她也会打开来用的一块东西**：有自己的页面，有自己的数据来源。
2. **开关和风险提示都在 App 身上**，例如英雄联盟“读这局的数据”。App 关掉，它的工具、页面、事件都没了。
3. **给她的工具尽量少**，每个 App 1 到 4 个，都是入口型的（“查这局的战绩”）。页面里翻页、看详情、搜索要用的工具标成只给页面用（`visibility: ["app"]`）。
4. **工具结果分三份**：给她的文字（很短，她要拿来说话）；给页面的数据（她那一刻看到的样子，存进记录）；用哪个页面显示（`ui://kotone/<app>/<页面>`）。
5. **App 之间不直接调用。** 要配合就经过她（她先后调两个 App 的工具），或者经过游戏事件（ADR 036）。
6. **她的工具清单只跟着开关变，不跟“现在在玩什么”变。** 一段对话里工具清单不变，DeepSeek 的前缀缓存才命中（ADR 024）。
7. **游戏专用的 App 自己带游戏中心的适配器**，例如英雄联盟 App 带 `lol` 适配器（ADR 036）。本体只知道哪个游戏在跑、在哪个阶段；游戏里面发生什么，由 App 报告。

### D4 App 清单

| App | 页面 | 给她的工具 | 只给页面用的 | 现在的代码 |
| --- | --- | --- | --- | --- |

### D5 契约（照 MCP Apps）

- **每个 App 一份清单**：
  - id、名字、说明；
  - 页面列表（`ui://kotone/<app>/<页面>`）；
  - 工具列表（每个标给她 / 只给页面）；
  - 开关和风险提示；
  - 挂在哪些游戏配置上（游戏专用的 App）；
  - 带哪个游戏中心适配器。
- **工具结果**：`content`（文字）、`structuredContent`（数据）、`_meta.ui.resourceUri`（页面）。只有文字进她的上下文。
- **页面怎么显示**：
  - 聊天流里是这个页面的小尺寸版本（快照），点开在右侧栏显示完整页面，旁边还能接着和她聊；
  - 左侧栏也有入口，不叫她也能直接打开。
- **`ui.open {app, page, params}`**：她（和外部 Agent）直接打开某个页面，例如“打开我的战绩”。本体的设置页也给地址，她可以带你过去。
- **她的系统提示**：能力概览按 App 列，关着的不列。

### D6 分期

- **一期**：
  - App 清单和宿主（开关、工具清单、`ui.open`、聊天卡片、右侧栏）；
  - 内置 App 的页面用 Kotone 自己的 Svelte 组件画（快、跟主题、有中英文），数据格式照 MCP Apps；
  - 英雄联盟 App 先做这局、玩家、单局三个页面；
  - 音乐、游戏语音按这个规范整理。
- **二期**：
  - 其余 App 搬进来；
  - `kotone.exe mcp` 提供 `ui://` 资源（把同样的页面打包成单个 HTML），外部宿主能显示；
  - 数据类工具（ADR 037）做成英雄联盟 App 的“英雄”页。
- **三期**：Kotone 的聊天里也能显示别人的 MCP Apps，放在沙盒 iframe 里，照 MCP Apps 的安全规则。

## 要玩家定的

1. **游戏聊天算 App 吗？** 语音输入是 Kotone 最早的功能。归进 App 以后，本体里就没有往游戏里打字的代码了，复杂度（聊天键、频道、控制台通道、挡键）都在 App 里。代价是“她替你在聊天里说一句”要靠这个 App 开着。
2. **哪些留在本体**：提醒、联网搜索、游戏列表、看屏幕。我倾向留下，它们是她的基本能力，或者 App 都要用。
3. **界面上叫什么**：“应用”、“App”，还是别的？要写进 `docs/glossary.md`。

## 不做

- 不让模型拼界面 JSON，不让模型写 HTML。
- 一期不装第三方 App。
- 不按“现在在玩什么”增减她的工具。
