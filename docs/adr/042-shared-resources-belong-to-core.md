# ADR 042：共享资源归本体——每样一个管家

状态：Proposed / 提议（2026-11-25）。总则是两份已确认的 ADR 的共同做法：[ADR 040](040-hotkeys-belong-to-core.md)（玩家：“可以，你这套很清晰”）和 [ADR 041](041-send-to-game.md)（玩家：“发到游戏这部分没问题”）。同一天照它修了评估第二节的第 2、3、5–10、13 条，见 D3；第 4 条先修了一半、第 12 条核对过没改行为，见末尾实施记录。还没做的几样（D4）先后顺序等玩家看过再定。每样做之前先复现，做完写进本 ADR 末尾的实施记录。

来源：[共享资源评估](../research/2026-11-25-shared-resources-audit.md)第一节（诊断）、第四节（方向）。本 ADR 定了以后，评估第四节那张表以这里为准。

## 背景

玩家（2026-11-25）：

- “现在我们有了 MCP APPS，整个项目有了明确的边界，那么我们是不是应该考虑对现有的一些边界进行评估？”
- “插件有自己的快捷键，陪伴智能体也有自己的快捷键，迟早有一天，这个快捷键的数量会多到记不清在哪。”

玩家看过快捷键的清点以后，同意把同类的东西都查一遍。四组（快捷键、声音、屏幕和注意力、往游戏里输入）查出来是同一种形状（评估第一节）：

1. **运行时的机制大多只有一份，设置却散在很多地方。** 快捷键散在 7 个以上的页面，麦克风设置有两处，屏幕上的东西设置在 3 处以上。
2. **插件接口里没有这样资源。** 插件要么被写死在本体里（语音输入的 5 个键、悬浮窗），要么自己去开设备（游戏语音自己开麦克风）。
3. **“能不能用、谁先用”的规矩有好几份，各写各的。** 压低音量 5 处，“她在说话”的判断 2 种，“能不能打断她”4 种，全屏判断 4 份。
4. **文档说了“只有一份、经过本体”，代码没做到。** 包括 ADR 038 D3 第 7 条“麦克风只有一个”、D5“覆盖层只有一个”、D6“宿主给插件语音识别”，还有 ADR 038 / 039 说的“共用一把输入锁”。

所以要定的是一条规矩，不是四个零散的修补。

### 今天实测推翻 / 修正了评估的几处

评估全是只读代码推出来的。2026-11-25 照它修的时候每条都先复现，有六处和评估说的不一样（详见各自的实施记录）：

## 决定

### D1 总则：每样共享资源一个管家

**共享资源**：全进程（或全屏、全机）只有一份，又有两个以上的用户要用的东西，例如热键、往游戏里输入、麦克风、扬声器、屏幕上的位置和前台、聊天流和她的上下文、语音识别。判断照[软件哲学](../philosophy.md)原则 12：有两个以上的用户，或者要动本体的状态，就归本体。只有一个用户的不算（原则 14）。

五条：

1. **一个管家拥有它。** 本体里由一处代码（一个文件或一个类型）拥有这样资源的状态，别处不另存一份。管家放在拥有那份状态的那一层：不碰窗口的放 `kotone-core`，要碰窗口、Tauri 的放桌面端。放哪一层是双向门。
2. **插件只声明要什么，经宿主拿。** 插件要么在 `plugin.toml` 里声明（例如命令），要么调 `Host` 的方法向管家要（例如 `speak`、`overlay`）。插件不自己开设备、不自己开窗口、不自己按键。这类能力先只给内置插件，第三方拿更窄的一份（单向门，原则 11，同 ADR 039 D3、041 D7）。
3. **规矩只写在管家里一次。** “能不能用、谁先用、等多久、压多低”都只写在管家里，调用的地方不再各写一份判断。怎么查：同一个判断（例如独占全屏）的调用方都经过管家；`grep` 底层函数，只剩管家本身和写明了理由的例外。
4. **设置只有一个地方。** 每样资源的设置放在一页里，别的页面只显示现在的值和一个“去改”（ADR 040 D3 的做法）。配置搬家照原则 19：读旧写新，有迁移测试。
5. **边界写成测试。** 每个管家至少有一条测试：要么查插件源码里没有绕过它的底层调用（已有 `kotone-plugin-api/tests/boundaries.rs` 的 `plugins_never_touch_process_global_hooks`、`plugins_never_press_keys_themselves`），要么查所有用户都经过它（已有 `attention::tests::windows_over_the_game_never_take_the_focus`）。

“管家”只是代码和文档里的叫法（[术语表](../glossary.md)“架构文档里的叫法”）。玩家看到的只是“只在一个地方改”“窗口不再互相盖住”“声音不再抢着出”，不多记一个概念（原则 2、5）。

### D2 又多出一样共享资源时

照这个顺序做：先数用户（只有一个就留在它自己那里）→ 找成熟做法（原则 7）→ 定管家放哪、管什么 → 写会失败的复现测试 → 把规矩和设置搬进管家 → 加边界测试 → 在本 ADR 的 D3 表里加一行。

### D4 还没做的，排期

先后照**玩家感觉的轻重**排，看三件事：① 一局里会不会碰到；② 碰到了是出事（听不见、队友听错、抢焦点），还是只是不顺；③ 今天有几个用户（原则 14：只有一个用户的先不抽象）。下面几条全是读代码推出来的、都没实测，做之前先复现。（2026-11-25：第 1 条里的“系统默认是 CABLE”那一半复现并先修了，见末尾实施记录。）

#### 1. 麦克风（排第一）

- **依据**（评估第二节第 4、11 条）：本体用“系统默认”麦克风时，不查它是不是 CABLE（`kotone-platform-windows/src/audio.rs` 的 `open_stream`），只有游戏语音自己查（`plugins/game-voice/src/router.rs`）。所以 `voice_chat.default_mic` 把系统默认麦克风设成 CABLE Output 以后，呼叫和语音输入听到的可能是她自己的声音，听不到你。这坏的正是玩家唯一要记的那个键（原则 1）。游戏语音的麦克风选“默认”时，下次重开也会因为默认成了 CABLE 而失败。（这两半 2026-11-25 先修了：跟随系统默认时改用上一个默认，见实施记录。管家要做的“只在一处选、只开一次”还没做。）另外，游戏语音自己开麦克风、自己存一份麦克风设置，所以在“声音”里换了麦克风，队友听到的不跟着换。
- **管家管什么**：
  - 用哪个真麦克风只在一处定（「设置 → 声音」）。CABLE Output 永远不当真麦克风，这条规矩只写在管家里。
  - 本体只开一次麦克风。本体自己的收音（呼叫、语音输入、`reply.ask`、唤醒）和游戏语音的转发都从这一份拿声音。
  - 游戏语音经宿主订阅，要加一个新的 `Host` 能力。游戏语音是第二个用户，满足原则 14。
  - 同传不归这个管家管（它听的是程序的声音）。和琴音说话时要不要转给队友，也不管（评估第二节第 1 条，玩家：游戏里大多是按键说话）。
- **照谁**：Android 的共享音频输入（系统照规矩分麦克风，App 只管录）；VRCT。
- **玩家看得到什么**：换一次麦克风，她和队友听到的都跟着换。游戏语音页的麦克风那一行只显示现在用的哪个，加一个“去改”。系统默认麦克风设成 CABLE 以后，她照样听得到你。
- **怎么验**：
  - 先写复现的单元测试，用假设备表：系统默认是 CABLE Output 时，本体不用它，并说下一步怎么办；在“声音”里换了麦克风，游戏语音的转发跟着换。
  - 真机脚本只读设备、不改 Windows 默认设备（ADR 020 实施步骤第 6 条），改默认设备那一项留给玩家。
  - 边界测试：插件源码里不打开输入设备。
  - 游戏语音的麦克风设置读旧写新，有迁移测试（原则 19）。

#### 2. 声音焦点（排第二）

- **依据**：今天收了最响的一处，就是插件的话和她的话同时出声、音乐也不压低（评估第 8 条，复现了）。剩下的是几处判断不一致：
  - 呼叫键打断、填充话、通话空闲计时、回合结束时等她说完，这几处各看各的（ADR 020 实施记录）。
  - 压低音量有 5 处各自的规则：音乐每 150 毫秒问一次她在不在出声；通话里你一开口，她的声音就压低；她说话时，CABLE 里你的麦克风压低；收音时压低系统音量；开始收音时停掉她的话。
  - 所有声音都走系统默认扬声器。

  通话里她一直在说，所以这些常碰到，但多半只是不顺、不会出事，所以排第二。
- **管家管什么**：
  - 谁要出声，先向管家申请，说明是“独占”（她的话、插件的 `speak`：别人等着或者压低）还是“可以被压低”（音乐）。
  - 压低的规则只写在管家里；上面那几处“她忙不忙”都问它。
  - 扬声器在「设置 → 声音」里选一个（缺省跟着系统）。她、插件、音乐都跟着这个选择。
  - 插件自己开输出流照旧可以（这是系统调用，没有状态），但用哪个设备、什么时候压低，听管家的。
- **照谁**：Android 的音频焦点（长期 / 短暂 / 允许别人压低自己，系统自动压低）；Windows 的默认压低（设置只在一处）。
- **玩家看得到什么**：她、插件、音乐不再抢着说；不管谁在说话，音乐都压得一样低；「设置 → 声音」里能选扬声器，压低的设置也在这一页。这一页现在已经有麦克风和“录音时降低扬声器音量”。
- **怎么验**：先把“各看各的”那几处列成表，每处写一个复现测试（用假时钟、假播放）；真机跑 `voice_chat_real.py`，再听一遍音乐压低的效果（要登录网易云）。

#### 3. 屏幕（排第三）

- **依据**：今天收了抢焦点（第 5 条）和右下角互相盖住（第 10 条），两条都复现了。剩下的：
  - 插件覆盖层里不同插件的东西会叠在一起、没人分配位置。但今天只有英雄联盟一个插件用覆盖层（原则 14）。
  - 悬浮窗、气泡、消息提示、弹幕、插件覆盖层这五个窗口谁在上面没定义，还没见过真叠在一起的。
  - 弹幕的全屏判断还在 `assistant.rs`。

  这些玩家今天都感觉不到，所以排第三。
- **管家管什么**：
  - 插件覆盖层按插件分区：插件声明要贴在哪（某个角、某块区域）、要多大，由宿主分配；撞上时照定好的先后让开（照 `screen_corner.rs` 的做法）。
  - 几个窗口谁在上面，只写在一处。
  - “现在能不能出来”都问 `attention`，弹幕那份也搬进去。
- **照谁**：Steam 覆盖层的 `SetOverlayNotificationInset`；Android 的桌面小部件。
- **玩家看得到什么**：第二个插件用上覆盖层时，两个插件的东西不会叠在一起；“提示和覆盖层”的开关都在一处（见第 5 条）。
- **怎么验**：照 `screen_corner::tests` 写纯摆位的单元测试；真机截图（照 `message_popup_real.py`，用测试窗口代替游戏）。
- **什么时候做**：弹幕的全屏判断随时能并进去（双向门、改动小）；覆盖层分区和窗口的上下顺序，等第二个用覆盖层的插件出现时一起做。

#### 4. 聊天流（排第四）

- **依据**：今天收了“她正忙时插进来会丢”（第 9 条）和“`ui.open` 打断玩家”（第 6 条）。剩下的：
  - 自动卡片只按 key 去重，不按插件限频。今天只有英雄联盟在发，一局两张。
  - 第三方 MCP App 发 `ui/message` 被拒（回 isError）；发 `ui/update-model-context`，宿主回成功，但不存、不进她的上下文（`apps/desktop/src/lib/components/plugins/McpAppFrame.svelte`）。
  - 第三方工具返回的 `ui://` 结果，在聊天里没有卡片。

  要等第二个发卡片的插件出现，或者第一个要用这些的第三方 App 出现，玩家才碰得到，所以排第四。
- **管家管什么**：谁能往聊天和她的上下文里放东西、放多少、什么时候放。
  - “什么时候放”已经由 `when_free.rs` 管了。
  - 要加的是按插件限频（同一个插件一局最多几张），玩家也能按插件关。
  - 给不给第三方、给多少是单向门。默认不给；要给时走和自动卡片同一条路：给她的那句按不可信数据处理、截短（原则 9）。
- **照谁**：Android 的通知渠道（按 App、按种类关）；Hermes 的合并思路（ADR 039 D3）；MCP Apps 的 `ui/message` / `ui/update-model-context`（[规范](https://modelcontextprotocol.io/docs/extensions/apps)）。
- **玩家看得到什么**：一个插件刷不了屏；“自动卡片”能按插件关（开关放在“提示和覆盖层”那一处）。
- **怎么验**：照 `when_free::tests` 写单元测试；第三方 App 发消息用 Playwright 测。
- `ui/update-model-context` 回成功却不存，对 App 不诚实。这次先不改：宿主能力里没声明它，守规矩的 App 不会调。等做“给不给第三方”那一步时一起定。

#### 5. 设置收拢（跟着 1–4 一起做）

设置收拢不单独排期：每个管家做完，它的设置就搬到一处（D1 第 4 条）。

- **「设置 → 声音」一页**：麦克风（包括游戏语音的，跟第 1 条一起做）、扬声器和压低（跟第 2 条一起做）。
- **“提示和覆盖层”一处**：这些开关现在散在几处：“游戏陪玩 → 角色 → 交互”（自动卡片、消息提示）；语音输入页（悬浮窗，存在顶层的 `settings.overlay`，不符合 ADR 038 D6“插件的设置放到 `plugins.<id>`”）；英雄联盟 App（覆盖层）。跟第 3、4 条一起收到一处。放在哪一页是双向门，做的时候再定。
- **怎么验**：Playwright 查每个设置只在一页能改、别处是“去改”；`settings_guide.rs` 里写的位置对得上（照 ADR 040 第 1 期的测试）。

## 不做

- 不为所有资源先搭一个通用的“插件申请资源”框架。每个管家只在第二个用户出现时，加那个用户要的一个 `Host` 方法（原则 14）。
- 界面上不出现“资源”“管家”这类词（原则 5）。
- 和琴音说话时自动不转给队友（ADR 041“不做”）。
- 外部 Agent 调工具前先问玩家（ADR 014 第 5 节；要改就改 014，留给玩家定）。
- 替玩家重按键（ADR 032）：输入锁轮不到就返回失败，不补发。

## 这个决定有多深远

- **双向门**：管家放在哪个文件、哪个 crate，内部怎么拆，先做哪样。一期的插件都编译在一起，放错了挪得动。
- **单向门**：
  - 给插件的 `Host` 能力（订阅麦克风、申请出声、覆盖层分区、往聊天里放东西）：给了第三方就收不回来（原则 11），所以先只给内置插件，给第三方的另定一份更窄的。
  - 设置搬家：动的是配置格式，照原则 19 读旧写新、有迁移测试（游戏语音的麦克风、悬浮窗的 `settings.overlay`）。
  - 对外的工具名和结果（`voice_chat.default_mic`、`game_chat.send`……）：只加字段、不改名。

## 什么事实会让我们改主意

- 某个管家成了瓶颈。例如游戏语音改成经宿主订阅麦克风以后，转发的延迟比现在自己开麦克风明显变大（真机量改前、改后）。
- 某样资源只剩一个用户（例如游戏语音没人用了）：把规矩搬回那个用户身上，删掉管家（原则 14）。
- 玩家要同一样资源在不同用途上各设各的（例如她听这个麦克风、队友听另一个）：在管家里加一项，照旧只在一处设，不退回各插件各存一份。
- 规矩放进管家以后，反而比原来散着时更多了（原则 2）：说明分错了，重新分。

### 2026-11-25 跟随系统默认时不收 CABLE Output（评估第二节第 4 条；第 1 期之前的一小步，不是麦克风管家）

- **复现**（单元测试，改前都失败）：
  - `kotone-platform-windows` 的 `virtual_cable::tests::following_the_default_never_hears_cable_output`：系统默认是 CABLE Output 时，跟随系统默认的收音（呼叫、语音输入、`reply.ask`、唤醒）选的就是它，输出 `SystemDefault("CABLE Output (VB-Audio Virtual Cable)")`。CABLE Output 里是她说给队友的话和转过去的麦克风：游戏语音在转时她听到的是自己，不在转时什么也听不到。
  - 游戏语音的 `router::tests::the_default_mic_still_forwards_after_windows_switched_to_cable`：麦克风是“默认”时，重开转发报“真麦克风不能选 CABLE Output”。为什么是“下次重开”：`voice_chat.default_mic` 改完设置以后，转发器的配置（`default`）没变，所以不重开，正在转的还是原来的真麦克风；重启 Kotone、改音量或麦克风时才重开，这时才打开 CABLE Output 并失败。
  - 没在真机上把 Windows 默认麦克风切成 CABLE Output：这会改玩家的系统设置（ADR 020 实施步骤第 6 条）。
- **改法**：
  - “收音用哪个录音设备”只在 `kotone-platform-windows/src/virtual_cable.rs` 的 `choose_input` 判断一次，没有状态。本体的收音（`audio.rs`）、回声消除（`echo_cancel.rs`）、游戏语音的转发都经 `audio::input_device`。
  - 跟随系统默认、而系统默认是 CABLE Output 时，改用上一个默认。依据：Windows 在 MMDevices 注册表里给每个录音设备记了 `Level:0`，设成默认时变成最大的，所以按它从大到小排就是“现在的默认、上一个默认……”（`default_order.rs`）。取排在前面的第一个看着不像虚拟声卡的设备，和 Windows 自己在默认设备被拔掉时的选法一样。
  - 开发机上只读核对过：现在的默认 PD200X 的 `Level:0` 最大（144），默认播放设备也是。按枚举顺序取第一个真麦克风会拿到 EDIFIER（另一个麦克风），所以没用枚举顺序。注册表这几项没有公开文档（和切默认设备用的 `IPolicyConfig` 一样），读不到时退回枚举顺序，不报错。
  - 玩家明确选的设备照用（真机脚本就是明确选 CABLE Output、往 CABLE Input 里放录音来测的）。游戏语音另外拦掉明确选成 CABLE Output 的（会把自己的声音循环回去）。
- **说清楚**：
  - 日志：`audio: the system default mic is CABLE Output (…), using <真麦克风> instead`。
  - 设备列表里“系统默认”那一项写成“系统默认（CABLE Output 是虚拟麦克风，改用 <真麦克风>）”。设置里的麦克风、游戏语音的麦克风、诊断、`audio.devices` 都显示这一项。
  - 一个真麦克风也没有时报错，并说下一步：接上麦克风，或者在「设置 → 声音」里选。
- **“是不是 CABLE”只剩一处**：原来游戏语音 `cable.rs` 有一份，命令行 `devices` / `doctor` 的 `looks_virtual` 有一份，本体没有。现在都在 `virtual_cable.rs`（游戏语音 `pub use`，命令行 `use`）。注册表读法从 `games.rs` 挪到 `registry.rs`，游戏库扫描和它共用。还剩游戏语音页面 `GameVoicePage.svelte` 下拉框的过滤（`startsWith("CABLE Output")`），在前端，挪不过来。
- **测试**：
  - `virtual_cable::tests` 7 个、`default_order::tests` 1 个、游戏语音 `router::tests::the_default_mic_still_forwards_after_windows_switched_to_cable`。
  - 真机只读：`audio::tests::this_machines_default_mic_and_what_cable_as_default_would_pick`（`--ignored`），列出设备和 `Level:0`，算一遍“切成 CABLE 以后改用哪个”，开发机上是原来的默认 PD200X。
  - `router::tests::tone_reaches_cable_output`（`--ignored`，VB-CABLE）照样过。
- **没测**：真的把 Windows 默认麦克风切成 CABLE Output。切完以后 `Level:0` 是不是像推的那样变（CABLE 最大，原来的默认第二），要玩家自己验，步骤是：
  1. 游戏语音页点“设成 CABLE Output”。
  2. 「设置 → 声音」的麦克风下拉框里，“系统默认”那一项应该写“改用 <原来的麦克风>”。
  3. 按呼叫键说一句，她应该听得到。
  4. 回游戏语音页点“改回原来的”。

### 2026-11-25 控制台发话两条同时发（评估第二节第 12 条，只核对，没改行为）

- **经入口的不会撞**：入口一条发言拿一次输入锁（ADR 041 D4）。`console_chat::send` 唯一的调用方是 `WindowsInjector::send_line`，它只经入口调。
  - 测试 `console_chat::tests::two_statements_through_the_entry_never_swap_the_file`：注入器照 `WindowsInjector` 控制台那一支写文件、按触发键，“游戏”在按下时读文件。两条同时经入口发，每条各执行一次。
  - 临时改成两个入口、各一把锁（相当于另一个进程），就撞了：`["say_team \"撤退\"", "say_team \"撤退\""]`，第一条丢、第二条两次。不经入口、两个线程直接调也一样。生产代码里没有这两种调法。
- **还能同时调到它的**：只有命令行的 `kotone send` / `listen`，它们是另一个进程（D3 记着“不在锁里”）。评估建议的“序号在按键之后再放”是进程内的锁，管不到另一个进程，所以没改。
- **改了什么**：只把写文件、按键、清空拆成 `write_and_press`，好测，行为没变。
