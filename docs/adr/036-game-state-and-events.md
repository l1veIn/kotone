# ADR 036：游戏状态和事件——所有游戏共用一层，自动化可以按游戏事件触发

状态：Accepted（2026-11-23）。玩家确认了 D7、D8、D9，都选了推荐的那一项：

- D7：游戏一启动就自动切到它的配置；
- D8：可以有“让她做”，每次触发花一次 AI 调用；内置模板默认关；
- D9：CS2 / Dota 2 的 GSI 配置文件**默认就写**（比草案的“玩家打开才写”更进一步），配置页能关。

其余按草案。

## 背景

玩家（2026-11-23）问：“对于游戏生命周期的监控怎么做？或者说怎么理解？监控也是工具吗？自动化条件里的触发器能跟游戏生命周期联动吗？”又说：“这个状态机或者说状态订阅可以做的通用一点，未来肯定会有更多的游戏接入，如何定义各种游戏事件也是在一开始就要考虑好的设计。”

现在 Kotone 里“盯着游戏”的东西有三处，各管各的：

| 哪里 | 看什么 | 多久一次 | 用来干什么 |
| --- | --- | --- | --- |
| 设置里的 `activeProfileId` | 玩家**手动选**的游戏配置 | — | 附注里的“当前游戏”、热词、游戏记忆 |
| 对局复盘（ADR 025，`recap.rs`） | 每个游戏配置的进程出现、退出 | 5 秒 | 进程退出时整理复盘 |
| 英雄联盟（ADR 035，`lol.rs`） | 客户端的对局阶段 | 2 秒 | 进加载界面就查战绩，这局结束时清掉技能记录 |

自动化（ADR 013）只有四种触发方式：手动、她调用、热键、定时。ADR 013 当时写了“数据结构为以后的……事件留位置，暂不实现”。

**监控不是工具。** 工具是她想知道时去问（拉）；监控是 Kotone 一直在后台看着，有变化就告诉关心的地方（推）。两者读的是同一份状态：工具随时读，监控负责保持它是新的，并在变化时发事件。

调研见 [`docs/research/2026-11-23-game-events.md`](../research/2026-11-23-game-events.md)。

自己设计的部分是**跨游戏的通用阶段**（D3）：上面的项目都只管自己支持的游戏，没有统一的对局阶段。原因写在 D3 里。

## 提议的决定

### D1 两种东西：状态和事件

- **状态**：每个在跑的游戏一份，随时能读（工具、附注、界面）。新的订阅者先拿到当前的一份；值没变就不通知。
  ```json
  {"game": "lol", "phase": "in_match", "nativePhase": "InProgress", "match": "301077229404",
   "since": 1795357452903, "attrs": {"lol.gameTime": 754.2, "lol.mode": "KIWI", "lol.queueId": 2400}}
  ```
  `attrs` 按“功能”分组：键名以适配器 id 开头，各游戏自己定。
- **事件**：一次性发生的事。状态变化本身也发一个事件（`game.phase_changed`，带 `from` / `to`），所以“按状态触发”和“按事件触发”是同一套机制。

### D2 事件信封和命名

```json
{"id": "lol-live-7", "type": "lol.dragon_kill", "game": "lol", "match": "301077229404",
 "time": 1795357960000, "gameTime": 600.5, "source": "lol/live-client",
 "data": {"team": "enemy", "dragon": "fire", "stolen": true}}
```

- `type` 一律小写，用点分隔：`<范围>.<名字>`，名字是 snake_case 的过去式或状态。
  - **通用事件**（任何游戏，不需要适配器）以 `game.` 开头：`game.started`、`game.stopped`（带 `elapsedSeconds`）、`game.focused`、`game.unfocused`、`game.phase_changed`（带 `from`、`to`）。
  - **游戏专用事件**以适配器 id 开头：`lol.dragon_kill`、`lol.ace`、`lol.my_death`、`cs2.bomb_planted`、`dota2.roshan_killed`。写 `lol.` 前缀就能匹配英雄联盟的全部事件。
- `game` 是游戏配置 id（玩家自己的配置也有，例如 `lol`、`genshin`）；`match` 是对局 id，没有时为空。
- `data` 只放这件事本身的数据。字段名照适配器声明的目录（D4），用 camelCase，和设置、工具参数一致。
- 别人起的名字（玩家名、聊天）放进 `data` 时，交给模型一律按不可信数据处理（照 OpenClaw）。

### D3 通用阶段（所有游戏共用的状态机）

| 阶段 | 意思 | 英雄联盟（客户端阶段） | CS2（`map.phase`） | Dota 2（`game_state`） | 没有适配器的游戏 |
| --- | --- | --- | --- | --- | --- |
| `stopped` | 没在跑 | 进程不在 | 进程不在 | 进程不在 | 进程不在 |
| `running` | 在跑，不知道细节 | — | — | — | **一直停在这** |
| `menu` | 大厅、主界面 | None、Lobby | 没有地图 | 没有地图 | — |
| `queue` | 排队、确认 | Matchmaking、ReadyCheck | — | — | — |
| `pre_match` | 选英雄、选角色、热身 | ChampSelect | warmup | HERO_SELECTION、STRATEGY_TIME、TEAM_SHOWCASE | — |
| `loading` | 加载 | GameStart、InProgress（局内接口还没给数据） | — | WAIT_FOR_PLAYERS_TO_LOAD、WAIT_FOR_MAP_TO_LOAD | — |
| `in_match` | 对局中 | InProgress（局内接口有数据）、Reconnect | live、intermission | PRE_GAME、GAME_IN_PROGRESS | — |
| `post_match` | 结算 | WaitingForStats、PreEndOfGame、EndOfGame | gameover | POST_GAME | — |

- 游戏自己的值放在 `nativePhase`，想按细节触发（例如 CS2 每回合的 `freezetime`）就用游戏专用事件或 `nativePhase`。
- 阶段可以跳（例如没有排队的游戏直接从 `menu` 到 `loading`），不强制顺序；只有 `stopped` 由进程决定。
- 为什么自己设计：
  - 自动化和她都需要“进了对局”“这局结束了”这种和游戏无关的说法。否则每个游戏要写一遍触发条件，她也要记住每个游戏的叫法。
  - 原生值不丢，所以不会损失细节。
- **一局**：从进 `pre_match` / `loading` / `in_match`（先到哪个算哪个）到 `post_match` 或 `stopped`。没有适配器的游戏还是“进程从出现到退出算一局”（ADR 025 的定义不变）。

### D4 每个游戏一个适配器，先声明自己能给什么

照 Overwolf 的“功能”。适配器是 Rust 里的一个实现，声明这些：

- `id`（`lol`、`cs2`……）和它认哪些进程（照 Playnite：进程名，以后加“这个目录里的任何进程”）；
- **能给的东西的目录**：每个状态键、每种事件（名字、中文说明、`data` 字段及其说明）。她写自动化、界面里选触发器、保存时校验，都按这个目录。
- **数据来源**，一个适配器可以有几个：
  - 进程（通用，所有游戏都有）；
  - 本机接口轮询（英雄联盟的客户端接口和局内接口，ADR 035）；
  - 游戏推送（Valve GSI：Kotone 在 127.0.0.1 上开一个端口收，要往游戏的 cfg 目录写一个文件，D9）；
  - 以后可能有日志文件、屏幕识别。
- **可用状态**（照 Overwolf 的绿 / 黄 / 红）：每个功能“可用 / 部分可用 / 用不了”，例如国服局内接口连不上时英雄联盟的局内事件是红的。界面在触发器旁边显示“这个游戏现在收不到这个事件”。

内置适配器：

- `generic`：只有进程，所有游戏配置都有；
- `lol`：ADR 035 的代码挪进来，现在的 `lol.rs` 盯阶段的那部分变成它的数据来源；
- 二期加 `cs2`、`dota2`。

### D5 游戏中心：一处合并、一处分发

桌面端一个“游戏中心”：

- 把各适配器的结果合并成一份状态，给事件编号、去重。两种来源报同一件事时，只发一次。
- 在 Rust 内部广播；同时发给界面（`kotone://game`）。
- 每局留最近的事件（有上限），复盘和她都能看。
- 攒一会儿再发、限频（照 GSI 的 buffer / throttle），免得多杀、连续推塔刷屏。

**现有的都改成订阅它：**

| 谁 | 订阅什么 |
| --- | --- |
| 对局复盘 | `game.stopped`，或者 `game.phase_changed` 变成 `post_match`（不再自己每 5 秒看进程） |
| 英雄联盟预查战绩 | `game.phase_changed` 变成 `loading` |
| 英雄联盟技能记录清空 | 一局结束 |
| 附注的“当前游戏” | 现在在玩的游戏（D7），加上阶段和这局多久了 |
| 自动化 | 事件触发（D6） |
| 界面 | 侧栏显示“英雄联盟 · 对局中 12:34” |

**新工具 `game.state`**：现在在玩什么、在哪个阶段、这局多久了、最近几件事，以及每个游戏能给哪些事件（目录和可用状态）。她回答“我玩了多久了”、写“按游戏事件触发”的自动化时用它。外部 Agent 通过工具服务也能读（Kotone 的能力都要对外部 Agent 开放）。

### D6 自动化可以按游戏事件触发

自动化在 `schedule`（定时）旁边加一个可选的 `on`（旧配置没有这个字段，照兼容规则缺省为空）：

```json
"on": {
  "event": ["game.phase_changed"],
  "game": "lol",
  "match": {"to": ["loading"]},
  "for": 0,
  "mode": "single",
  "oncePerMatch": true,
  "cooldownSeconds": 0,
  "enabled": true
}
```

- `event`：一个或几个事件类型（“或”），也可以写前缀 `lol.*`。
- `game`：只在这个游戏配置上触发；不写 = 任何游戏。
- `match`：照 EventBridge，对 `data` 做子集匹配，数组表示“或”。一期只做相等；以后加 `prefix`、`exists`、`numeric`。
- `for`：照 Home Assistant，阶段进入后保持这么多秒才触发（“对局开始 60 秒后提醒我买眼”）；期间阶段变了就不触发。
- `mode`：照 Home Assistant，`single`（默认：正在跑就忽略新的）、`restart`、`queued`。不做 `parallel`。
- `oncePerMatch`、`cooldownSeconds`：这两个是自己加的，防止一局里刷屏（照 Hermes 的合并和限频思路）。
- **事件数据当入参**：自动化里和 `data` 字段同名的参数自动填上（照 ADR 013 的“云函数”：事件是函数的输入）。例如播报“对面拿了{dragon}”。
- **规矩不变**（ADR 013）：
  - 最多触发一次（每个事件）；
  - 错过的不补（Kotone 没开、游戏没在跑时发生的不补）；
  - 绑定游戏窗口；
  - 玩家随时能停。

  对局里模拟键鼠的限制（ADR 019）也不变。往聊天里发字的自动化，保存时照常问玩家一次。

### D7 自动识别“现在在玩什么”

现在的“当前游戏”是玩家手动选的。提议：

- 游戏中心知道哪些游戏配置的进程在跑、哪个在前台。附注里的“当前游戏”和游戏记忆用**正在玩的**那个。
- 某个游戏配置的进程启动时，`activeProfileId` 自动切过去（语音输入的热词跟着变）；游戏退出后保留，不切回。
- 玩家手动选的照样有效，下次有别的游戏启动时才会再自动切。

玩家确认（2026-11-23）：自动切。

### D8 第三种动作：“让她做”

自动化现在有两种动作：播报（固定的话）和程序（Luau）。“进加载界面就告诉我对面谁是突破口”这种事，两种都做不了：要查、要判断、要说。

提议加第三种动作：**一句交给她的话**（照 OpenClaw 的 `/hooks/wake` 和 `/hooks/agent`）：

```json
"action": {"type": "prompt", "text": "用 lol.scout 看看对面谁是突破口，一句话告诉我"}
```

- 触发时，这句话和事件（按不可信数据引用）作为一条系统通知放进主会话。她跑一轮，用工具、开口说。
- 复杂的事照常由她交给后台。
- **每次触发花一次 AI 调用**。界面写明这一点；默认每局最多触发 3 次。
- 内置一条模板“英雄联盟进加载界面播报突破口”，默认关。

玩家确认（2026-11-23）：可以，内置模板默认关。

### D9 Valve 游戏（CS2、Dota 2）要往游戏目录写一个文件

GSI 要在游戏的 cfg 目录放 `gamestate_integration_kotone.cfg`，游戏才会把状态推给 Kotone。GSI 是 Valve 自己的机制，不涉及封号：

- **默认就写**（玩家 2026-11-23 确认）：找到游戏目录、游戏没在跑时写；游戏配置页写明写了什么文件，有开关，关掉就删；
- 写之前备份（照 ADR 032 的“控制台通道”）；只在游戏没开时写、删；
- 端口只听 127.0.0.1，带随机令牌（GSI 的 `auth`）。

这是二期的事。

## 分期

- **一期**：
  - 游戏中心；
  - `generic` 适配器，复盘改成订阅；
  - `lol` 适配器：阶段来自客户端接口；局内事件来自局内接口的事件列表（拿龙、男爵、先锋、推塔、水晶、团灭、一血、多杀），以及 `playerlist` 推出来的“我阵亡 / 复活”；
  - `game.state` 工具；
  - 自动化的 `on` 和三种动作；
  - 界面：自动化编辑里选“游戏事件”，游戏配置页显示这个游戏能给哪些事件、现在能不能收到。
- **二期**：`cs2`、`dota2` 适配器（D9）；外部 Agent 订阅事件（工具服务推送）；`match` 的更多运算。

## 不做

- 不读游戏内存，不注入。数据只来自进程列表、游戏 / 客户端自己提供的本机接口、游戏自己推送的数据。
- 不自动操作客户端（例如自动接受对局、自动选英雄）。LeagueAkari 有这些功能，有人因此被封（#523）；要做以后另议。

## 一期实现记录（2026-11-23）

**做了什么**：

- `kotone_core::games`（纯逻辑，有单测）：阶段、状态、事件信封；`Hub` 把适配器的观察变成事件；`on` 的校验和匹配；`Triggers` 管 `for`、每局次数、冷却。事件目录也在这里（通用的 `game.*` 和英雄联盟的 `lol.*`），保存自动化时按它校验。
- `kotone_lol::events`：客户端阶段 → 通用阶段；局内接口的事件列表 → `lol.*`。
- 桌面端 `games.rs`（游戏中心）：每 2 秒看一次进程和前台窗口（`generic` 适配器），分发给界面（`kotone://game`）、Rust 内部订阅、自动化；`game.started` 时切当前游戏配置（D7）。
- `lol.rs` 成了 `lol` 适配器：客户端开着时认领英雄联盟，报阶段（`InProgress` 时局内接口有游戏时间才算“对局中”，之前是“加载”）、局内的新事件和“我阵亡 / 复活”；客户端关了交回给进程那一路。
- 对局复盘改成订阅 `game.match_ended`，不再自己每 5 秒看进程。
- 自动化：定义里加 `on`；第三种动作 `prompt`（“让她做”）；内置模板“英雄联盟进加载界面播报突破口”（装上时触发是关的）。
- `game.state`：工具服务里（外部 Agent 也能用），也在主会话马上返回的那套里；界面用 `game_state`。
- 界面：自动化编辑里的“让{name}做”和“按游戏事件运行”，列表和详情里显示触发；游戏配置页的“游戏事件”（现在在哪个阶段、能给哪些事）。

**和草案不一样的地方**：

- **加了两个通用事件 `game.match_started` / `game.match_ended`**（带 `elapsedSeconds`），由阶段推出来，就是 D3 里“一局”的定义。复盘要的是每一局结束；英雄联盟的状态来自一直开着的客户端，`game.stopped` 要等客户端关了才有。
- **`match` 是 Kotone 自己起的这一局的编号**（`<游戏>-<开始时间>`，一局里不变）。游戏自己的对局 id 放在 `attrs`（`lol.gameId`）：英雄联盟选英雄时还没有 gameId，用游戏的 id 会让“一局一次”在一局中途换了编号。
- **英雄联盟预查战绩、清技能记录还在 `lol.rs` 里**：它本身就是英雄联盟的适配器，不用订阅自己发出的事。
- **“让她做”那一轮不能交给后台**：消息来源是 `automation`，不是玩家亲口说的。ADR 030 第 2 节规定只有玩家亲口说的一轮能派活；她可以用马上返回的工具（`lol.scout` 等）。草案写的“复杂的事照常由她交给后台”没有做。
- **“让她做”不当成工具给她**（`saved.*` 里没有），免得她自己调用自己。
- **事件数据当入参**：参数名只能是小写加下划线，所以 `elapsedSeconds` 这类字段也能填进 `elapsed_seconds`。
- **`mode` 只对程序生效**（播报、让她做没有“还在跑”的状态）。`queued` 最多等 30 分钟。
- **“现在能不能收到”先做简单的**：游戏配置页写现在在哪个阶段；英雄联盟对局数据关了时写明只有通用的事。按功能的绿 / 黄 / 红以后再做。
- **“让她做”在她忙的时候最多等 2 分钟**，还没空就不做了（事件已经过去了）。
