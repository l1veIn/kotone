# 2026-11-22 调研：实时通话的交互（orb、voice-call）与 orb 这个桌面陪伴项目

起因：0.2.0-rc.3 真人测试（见 ADR 033 背景）。玩家给了两个参考：

- [mini-yifan/dsh-orb-cordis](https://github.com/mini-yifan/dsh-orb-cordis)（下称 orb，MIT）：DeepSeek Harness 的悬浮球插件，带 Computer Use、语音、划词、套索、后台桌面、多设备互联。文档 21 篇约 75 万字节，修订记录只追加。
- [crease123/voice-call](https://github.com/crease123/voice-call)（MIT）：DeepSeek Harness 的语音通话插件，DeepSeek 整段识别 + 流式合成（也支持豆包）。

两个仓库只读研读（克隆在会话临时目录，没有运行里面的任何东西）。出处写仓库相对路径。

## 一、orb 的语音

### 听法是一个纯函数

四种听法由当前状态算出来（`packages/voice/src/listen.ts:88-106`），麦克风开不开另算（`:141-161`）：

| 听法 | 什么时候 | 听什么 |
| --- | --- | --- |
| wake | 球没固定、Agent 空闲、没在念 | 只喂关键词检测（普通采集，不做回声消除） |
| command | 固定且空闲 | 回声消除采集 → silero → SenseVoice；整句去掉开头的唤醒词，是“退下”就退下，否则发出去 |
| interject | Agent 在做或正文在念 | 全开，只认“退下”和带名字（“大肥鱼”）的插话，别的句子丢掉 |
| off | 提问卡在等、应答语 / 退下语在念、停止还没生效 | 设备都释放 |

- 一句话按**开口那一刻**的听法判（子进程把状态带进识别结果，`child.ts:820-821, 889-891`）；用户正说着时不切换听法。
- 答完只要还固定着就接着在 command，**没有“接着听 N 秒”**；空闲 30 秒取消固定（5–600 可设），Agent 在做、提问卡在等、在念、用户在说时暂停计时（`idle.ts:41-51`）。
- 插话：最初用官方 `steer`，长工具时要等约 30 秒才生效，推翻成“硬停旧轮、等它真正结束再发新的一轮”（`docs/04-addenda.md:334-343`）。

### 退下

ASR 文字匹配（不用关键词检测）：去标点、全半角大小写统一后包含匹配，两个音节以上允许同音字；出厂“你退下吧 / 退下吧 / 退一下吧”（`dismiss.ts:86-90`，`settings.ts:75`）。执行中、念的时候都生效：停掉执行 → 停播清队列 → 这句不上屏 → 取消固定 → 念“好的，再见”（`voice.ts:654-666`）。

### Windows 回声消除（最值得抄）

`packages/voice/native/windows-voice-capture.cpp`：

- WASAPI 共享模式、事件驱动，48k 单声道 float。
- **参考 = 默认扬声器的回采（loopback）**：同一输出设备上任何进程的声音都能消（她、游戏、音箱里的队友语音）。另开一路一直写静音的渲染流，否则没声音时 loopback 不出数据（`:394-426`）。
- WebRTC AEC3：降噪、自动增益关，高通开（`:327-346`）；参考和麦克风**严格按时间逐帧对齐**，只取 ±5 ms 内的那一帧，stream delay 设 0（`:356-392`）——这是修“念的时候转写严重走样”的办法（`04-addenda.md:433-446`）。
- **不设成通信类别**：那样 Windows 会把其他程序音量压低 80%（`08-voice-listen-plan.md:818`）。
- MMCSS “Pro Audio” 线程优先级；stdin EOF 就退出，父进程死了麦克风不被占着。
- 兜底：**文字回声过滤**——转写和最近念过的文字按拼音最长公共子序列比，≥ 0.6 判为回声；不足 2 个音节不判；念的文字长于转写 4 倍不判；带口令、而念的文字里没有这个口令的豁免（`echo.ts`）。
- 验收：边播边由真人说 20 句、10 句带关键词，带关键词的至少命中 19 句，整体字错率 ≤ 10%；其他程序音量被压低 ≤ 1 dB（`08:789, 855`）。

### 其他参数

silero 阈值 0.5、最短静音 0.5 s、最短语音 0.25 s、最长 30 s；预录 300 ms，自己的声音之后重开时预录取 0（`child.ts:806-820`，`voice.ts:608`）。千问流式合成首包 0.3–0.5 s，3 秒没首包换连接重试、出过声不重试（`qwen-tts.ts:187-197`）。

### orb 没做的

- 提问卡期间麦克风关着，**确认只能点**（`listen.ts:142`）。
- 被打断的回答完整上屏，不记“只说到哪”。
- 本地 Matcha 整段合成，不流式、合成中停不下。

## 二、voice-call

- 状态 idle / connecting / listening / recognizing / thinking / speaking / stopping / paused / error（`call.ts:16`）。开着通话麦克风一直开；识别时又开口，两段合并成一条（修复提交 d25bc0b）；积压 2 段待识别就结束通话。
- 起音：RMS ≥ 阈值的连续样本累计到 `minSpeechMs`（默认 200 ms）；保留起音前最多 1 秒；静音 650 ms 判停、最长 15 s（`utterance.ts:42-72`）。**起音那一刻**就停播、取消合成、撤回自己排队的输入、取消这一轮、等它停下再提交新的一句（`call.ts:151-183`）；识别为空回到聆听，原回答不恢复。
- 回声：只有浏览器 `getUserMedia` 的 `echoCancellation`，参考信号只有页面自己的声音；README 建议戴耳机。
- 通话状态：每次模型请求附带一段 runtime context（不改系统提示）。默认通话说明（`personal-agent/src/index.ts:36`）：

  > 用户正在通过实时语音与你交谈。先直接回答核心问题，默认每次说 1–3 句，尽量控制在 100 字以内。使用自然口语，避免标题、表格和长列表。复杂问题先讲关键结论，用户要求展开时再详细解释。执行任务时简短说明进展，完成后报告结果。代码、长路径和详细资料留在文字中，不逐字朗读。

- 结束：只有挂断按钮。审批：语音答不了。
- 合成串行：上一句播完才请求下一句（我们已经提前连好下一路）。

## 三、对 Kotone 的结论（写进 ADR 033）

| 要的 | 照谁 | 怎么做 |
| --- | --- | --- |
| 一直在通话 | orb command 态 + 空闲规则 | 呼叫 = 接通；silero 检测开口就收这一句；30 秒没人说话挂断，她在说 / 想 / 做 / 等确认时不计时 |
| 开口就打断 | orb 回声消除 + LiveKit 防误打断 | 纯 Rust `sonora`（WebRTC AEC3）+ 默认扬声器 loopback 参考，逐帧按时间戳对齐，不用通信类别；她说话时玩家开口先压低音量，识别出真话再停，空的 / 回声 / 只是“嗯”就恢复 |
| 说“退下 / 安静”挂断 | orb dismiss | 整句匹配，执行中、念的时候都生效；停掉她这一轮，后台的事不停 |
| 说“允许”放行 | 两个项目都没有 | 用嘴问过的确认登记起来；之后整句只是“可以 / 不要”就交给它 |
| 通话里的说话风格 | voice-call callPrompt | 只在通话里写进每轮附注 |

没选的：orb 必须喊名字才能插话（玩家要开口就打断）；voice-call 起音就取消这一轮（游戏声、咳嗽会丢回答）。

## 四、orb 作为桌面陪伴产品，值得学的（按优先级）

研读了 docs 01–21、helper / host / computer-use 源码和提交记录。orb 没有正式用户研究，依据是问题反馈、用户截图和作者自用；它的修订记录（`04-addenda.md`）每条按“现象 → 根因（带对照实验）→ 修法 → 测试（反向验证）→ 真机验证 → 未做”写，很值得照着写。

| # | 学什么 | orb 怎么做 | 对 Kotone | 工作量 |
| --- | --- | --- | --- | --- |
| 1 | 自家窗口不进截图 | Agent 截图期间按引用计数打开 `WDA_EXCLUDEFROMCAPTURE`，等 50 ms 再截；平时照常可见（`hp/cloak.ts:71-89`） | 气泡、弹幕可能被 OCR 当成游戏聊天（`window_tools.rs:30` 写明截图含自家覆盖窗口） | 小 |
| 2 | 截图画上光标 | `GetCursorInfo` + `GetIconInfo` 合成（`cu/windows-native.ts:676-719`） | `game.act` 点偏了模型看不出 | 小 |
| 3 | 后台完成通知的护栏 | 后台和前台都空闲才投递；玩家停掉的“除非要求不要重启”；别人占屏时“只报文字” | 子代理报告模板加上 | 小 |
| 4 | 派发说明写成正反例 | `code_agent` 说明逐条列例子；把 GUI 推给后台的提示词改动被回滚（b357ee8） | `agent.start` 说明 | 小 |
| 5 | 失败原因点名 | 点名“锁屏 / UAC 安全桌面”后同一任务 35 步降到 9 步（`13-background-desktop.md:437-451`） | `game.act`、聊天发送失败时返回具名原因（不在前台、聊天框没开、锁屏、游戏是管理员） | 小 |
| 6 | 一把输入锁，争用即失败 | 进程级 GUI 锁不排队（`cu/gui-lock.ts:10-12`），之前四套锁互不知情导致点击交错 | 聊天发送、`game.act`、自动化共用一把；和“不替玩家补按键”同一原则 | 小到中 |
| 7 | 最新一句赢 | 先取消旧轮，等真正结束再开新轮，用轮次编号防迟到的结束信号停掉新轮 | 通话插话路径核对 | 中 |
| 8 | 下载器四件套 | 钉死 commit 和哈希、固定文件名续传、停滞检测代替总超时、国内镜像优先 | 模型下载 | 小到中 |
| 9 | 用会话日志测量 | 从日志解出步数、墙钟、模型耗时占比，用数据推翻自己的设计 | `game.act`、子代理各一个脚本 | 小 |
| 10 | 只显示、不进上下文 | 翻译带“未计入对话”标记 | 队友聊天翻译、OCR 结果 | 小 |
| 11 | 文档 | ADR 末尾“文档同步清单”；工具说明写“模型看到什么 / token / 缓存影响” | 和 ADR 024 前缀缓存直接相关 | 小 |

看起来好但不适合我们：可聚焦、悬停展开的球（游戏里抢焦点，ADR 019 已否决）；装上即授权、后台自动选推荐项答问（和 allow / ask / deny 冲突）；无障碍树优先（游戏没有）；自己下载 Electron 当 helper、多设备互联、自建中继、安卓虚拟屏（插件形态逼出来的或太重）；三档权限芯片（多一层规则）。

orb 自己记录的教训也值得记住：543 个用例全过、菜单却从没显示过（测试桩跟着错误假设一起写错）；改代码里的默认值不会覆盖用户磁盘上已保存的配置；上游模型被重传导致全新安装 100% 校验失败（所以钉 commit）。
