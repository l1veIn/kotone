# 2026-11-26 rc.9 试玩讨论记录

玩家装了本地打包的 rc.9（`D:\琴音`），打了两把海克斯大乱斗，一边玩一边和主会话讨论。这次只讨论、不改代码。“决定”是玩家说定的；“我的建议”是主会话提的，玩家没有反对，实现时写进 ADR 再确认。

## 一、呼叫键在游戏和客户端前台时没反应

**现象**：Ctrl+\` 在游戏里、英雄联盟客户端前台时没反应；桌面、Chrome、QQ、Warp 前台时正常。（玩家一开始说 Warp 也不行，后来改口说可以。）

**原因**：Windows 的权限隔离（UIPI）。国服的 `League of Legends`、`LeagueClientUx`、`LeagueClient`、`RiotClientServices`、`wegame`、`tcls_core` 都是管理员权限（High），Kotone 是普通权限（Medium）。前台窗口权限比自己高时，普通权限程序的低层键盘钩子收不到按键，所以呼叫键、说话键、Esc 停下、快捷指令、一键喊话、鼠标侧键全都失效，往这些窗口发键（SendInput）也会被挡。

**证据**：
- 日志里，能用的那几次都有 `named hotkey fired: assistant`；在客户端或游戏前台按的，一条都没有，也没有 `NamedKeyMissed`。
- 玩家的配置里，两段“要管理员权限”的提示都点了“不再提示”（`adminPromptDismissed`、`autoAdminPromptDismissed` = true，`runAsAdminOnStart` = false）。那段提示只说“发文字会失效”，没说热键也会失效。
- 对照实验：一个普通权限的小脚本用 `RegisterHotKey` 登记 Ctrl+\`，在 `LeagueClientUx` 前台按了 7 次，7 次都收到。

**决定**：Kotone 默认以管理员身份运行，每次启动（包括开机自启）点一次 UAC 的“是”（玩家：“可以，默认管理员权限吧”）。
- 用现成的“启动时自动请求管理员权限”（`runAsAdminOnStart`）：新装默认打开。点过“不再提示”的人用新说法再问一次（热键 + 往游戏里打字）。点了“否”就照常以普通权限运行，等发现前台游戏是管理员权限时，再说清楚哪些用不了。
- 装好后第一次打开时，先用一句话说明原因，再弹 UAC；以后直接弹。
- **必须一起做**：Kotone 打开的东西一律用普通权限运行，包括 `shell.run` 和 `kotone-exec` 起的进程、后台任务、打开的链接和文件夹、启动的游戏。现在 `kotone-exec` 用的是 `Command::new`，会继承 Kotone 的权限。
- **不做静默提权**（最高权限计划任务）：Kotone 可以装在普通程序也能写的目录里，静默提权等于让任何程序换掉 `kotone.exe` 就能不弹窗拿到管理员；杀毒软件也会报；维护面也会变大。长期的路是代码签名 + 装进 Program Files + uiAccess：这样不要管理员也能听键、打字，UAC 也不用弹了。
- 只给呼叫键加 `RegisterHotKey` 的办法先不做，因为它解决不了往局内打字。

## 二、陪玩信息流：插件按时机主动推送

玩家的评价：插件往聊天里发卡片“非常牛，是一种全新的体验”，玩了一把就养成了看聊天的习惯。“主动探测游戏状态、根据局势推送有价值信息……这些功能我都想要，包括一键符文出装。”

### 推送的三种样子

- **卡片**：发进聊天，悬浮窗的小窗里也弹出来。
- **一行**：悬浮窗气泡里显示一行字。
- **语音**：她说一句固定的短话，有几个说法轮着用，不调模型。

规矩：
- 要紧的用语音，其余显示一行，全都记进聊天。
- 同一时刻只说最要紧的一句，几十秒内不连着说。
- 每条推送单独一个开关（见第八节）。
- 插件的推送不调模型、不花钱。

3. 海克斯识别里还剩的部分：剩余刷新次数等。

## 三、悬浮窗

玩家给的规格：
- **两种状态**：气泡（现在这样，一行字）和小窗。小窗本质上就是聊天界面，用来显示插件推送的卡片。弹出时高度跟着卡片走，但有上限（我的建议：屏幕高度的 40% 左右）。消失之前可以点里面的卡片，也可以用滚轮往回翻。
- 显示着的时候**可以关、可以拖**，拖到哪里，下次就从哪里出现。
- 参考 [mini-yifan/dsh-orb-cordis](https://github.com/mini-yifan/dsh-orb-cordis)，只显示关键信息。

我的建议：
- 现在右下角的消息提示和她说话时的气泡，都并进这一个窗口。
- 小窗直接用聊天页的组件，不另写一套。
- 鼠标停在上面时不消失，移开后再开始倒计时。
- 游戏在哪块屏幕上，悬浮窗就显示在哪块屏幕上。
- 硬规矩：在游戏里绝不抢焦点。2026-11-22 的调研否掉过“可聚焦、悬停展开的球”。点击在非聚焦窗口里验证过能用；**滚轮还没验证**。独占全屏时什么窗口都盖不上去，无边框全屏没问题。
- 本体的覆盖层层（`overlay_layer`）只有英雄联盟在用。覆盖层去掉以后，它“置顶、不抢焦点、不进截图、跟着游戏所在屏幕”这几样直接拿来做悬浮窗。

## 四、英雄联盟插件的覆盖层全部改成推送（决定）

玩家：“同意，记成决定吧，覆盖层出现改为事件推送。”
- 去掉选英雄覆盖层（`ui://kotone/lol/champ-select`），改成选人卡。
- 去掉海克斯评分覆盖层（`ui://kotone/lol/augment-scores`），改成悬浮窗里一行三列（左 / 中 / 右：首选 / 可选 / 可刷新）。截图识别三张卡片照旧。
- **三选一刷新了怎么办**：卡片在屏幕上时每秒看一次（本地识别一次 0.1–0.3 秒）。刷新了哪张就原地换哪一格。她在卡片刚出现时说一次；刷新后最好的那张变了才再说，结论没变不重复。卡片消失就收起。
- 还不知道：剩几次刷新（屏幕上有显示，以后可以识别；剩 0 次就不再建议刷新）。
- 注意：拳头那条“不能显示海克斯胜率”管的是“网站、应用和覆盖层”。换成聊天显示，风险一样，所以这次改动是为了简单，不是为了合规。

## 五、已经推送的卡片怎么更新（我的建议，玩家：“可以”）

现在同一个插件、同一个 `key` 只发一次（宿主记最近 256 个），再推一次会被丢掉，还不能更新。

建议改成：**用同一个 `key` 再推一次，就是更新**（和 Telegram、Discord 机器人编辑已发消息的思路一样）。
- 新的 `key`：追加一张新卡片。
- 同一个 `key`、内容变了：改那条通知里的卡片数据，聊天和悬浮窗里的那张原地重画，位置不动。
- 同一个 `key`、内容一样：什么都不做。
- 这次推送带了给她的一句话：追加一条新的隐藏说明。说明要少给，只在关键时刻带（锁定、选人结束），中间的变化只更新卡片。
- 卡片还在排队（她正忙）时：直接换掉排队里的那张。
- 这张卡片上面已经有别的消息时：插件可以把这次更新标成“要提醒”，悬浮窗就把更新后的卡片再弹一次。

为什么不影响前缀缓存：通知本来就不发给模型，发给模型的说明仍然只追加。ADR 039 里“前面的消息一个字不改”要改成更准确的说法：**发给模型的部分只追加；通知里的卡片数据可以改。**

## 六、数据事实（这次核实的）

- **局内接口（2999）没有冷却**：录下的所有数据和接口自带的字段说明里都没有冷却字段。它只告诉你每个人带的是哪两个召唤师技能。拳头也限制冷却计时（ADR 035 D5）。所以“闪现好了”只能靠标记加计时；“有大招了”只能靠到 6 级判断。
- **局内接口没有海克斯**：2026-11-26 13:55–14:13 用只读脚本录了一整把海斗（`KIWI`），从 1 级到 18 级，每 20 秒一份，共 56 份，在 `target/lol-probe/20261126-mayhem-midgame/`，里面还有整局出现过的全部字段 `all-keys.txt`。谁的海克斯都没有，自己的也没有。
- **接口里有的**：10 个人的装备、等级、阵亡和复活倒计时（`isDead`、`respawnTimer`）、峡谷局内的分路（`position`）、召唤师技能、比分；事件有一血、击杀、多杀、团灭、推塔、推水晶等。
- **对面海克斯的调研**（子代理查了 GitHub 和文档）：局内接口、客户端接口（按 hasagi-types 16.21 的完整接口清单）、拳头网页接口都拿不到；Overwolf 只给自己的。唯一试过的项目是 [kiwiiiii-eth/aram-mayhem-analyzer](https://github.com/kiwiiiii-eth/aram-mayhem-analyzer)：认 Tab 计分板上的图标（每人 5 格），准确率约 60%，项目已经停了。我们不做。以后可以当个小实验：玩家按着 Tab 时顺手记下来，只给她参考、写进结算卡片。
- **拳头的规定**（[developer.riotgames.com/docs/lol](https://developer.riotgames.com/docs/lol) 原文）：“Products cannot display win rates for Augments or Arena Mode items. This applies to all websites, applications and overlays.” 我们的三选一评分（AramHex 也一样）就在这条里面。照“提醒风险、不拦”的规矩，写进插件那一个风险弹窗（第八节）。

## 七、插件的边界：插件说“是什么”，她说“意味着什么”

玩家：“突破口跟插件没关系，这个插件不应该推测谁是突破口，推测突破口是完完全全的模型行为，只存在于自动化。插件的边界要清晰，只做游戏插件分内的事。”

**插件是什么**（玩家的说法）：**独立的 App + 事件推送器 + 提供可调用的工具。**

主会话补的四点（待玩家确认）：
1. “事件推送器”有两类东西。一类是**事件**（出了什么事），给自动化和她用。另一类是**内置触发**（“时机 → 行为”），面向玩家：行为可以是推送卡片 / 一行 / 语音，也可以是自动接受这类客户端操作。每条在插件页上一个开关，不能改。
2. 工具的调用方不只是她：还有别的 Agent（经 MCP）、插件自己的 App 和卡片上的按钮（一键导入）、热键（ADR 040 的插件命令）、自动化。
3. **游戏适配器**：告诉本体这个游戏现在处在哪个阶段（房间 / 选人 / 加载 / 对局中 / 结算）。本体靠它自动切游戏配置、做复盘、按局去重。
4. **对内的边界**：要用本体的东西（截图识别、往游戏里打字、悬浮窗和聊天、存储、凭据），只能经过宿主，并在清单里写明。麦克风、识别、键盘钩子、输入锁这些共用资源归本体（ADR 042，Proposed）。“独立”指的是 App 和工具在别的 MCP 宿主里也能用；推送要靠 Kotone。

内容上的规矩（下面这段）管的是这几样里放什么：

**插件分内的事**
1. 读游戏：客户端接口、局内接口、截图识别。
2. 查数据：战绩、统计，原样给出，写明出处。
3. 发事件：出了什么事（一血、到了几级、出了什么装备……），给自动化和她用。
4. 按固定规则推送：时机加上固定的内容或说法，同样的输入永远得到同样的输出。统计排序、三选一的判断（照 AramHex 的规则）、等级 / 装备 / 刷新提醒都算。
5. 替玩家操作客户端：只在玩家点了按钮或打开了开关以后。
6. 自己的页面、设置、推送开关。

**归她的事**：评价人（突破口、谁会坑）；看局势说该怎么打；措辞和语气；把几个插件、几个数据源放在一起判断；记住玩家。

**判断方法**：说的是游戏里的东西（数字、装备、时间、数据源给的结论）是什么，还是对一个人、对局势的看法？前者归插件，后者归她。

**要改的**：英雄联盟插件里去掉突破口（`scout::weak_spots` 这一套）。开局战绩卡片、给她的说明、`lol.scout` 都只给事实：最近的胜负、连胜连败、这个英雄打过几局、谁在开黑。“进加载播报突破口”这个自动化模板留着，那里才是她判断的地方。

## 八、其它细节

- **三选一评分第一把没出来**：那时用的是在线文字识别，这个功能只认本地识别，失败了只在日志里写一句（“海克斯评分看不了画面：选的是在线文字识别”），玩家完全不知道。第二把本地识别（`ppocrv5-ch-mobile`）选上了，玩家看到了评分。改法：三选一固定用本地识别，和全局的识别设置无关；第一次用时问一句要不要下载模型；用不了时说清楚原因。
- **开局战绩里我方少两个人**：那把我方有两个人（卡牌大师、无极剑圣）**隐藏了身份**，局内接口里这两人的名字都是空的，客户端也不给他们的 puuid。`members()` 把没有 puuid 的人当成电脑跳过了，所以卡片上只剩 3 个。这是对方主动隐藏的，查不到，也不该去“反查”。改法：这两行照样显示英雄，标“隐藏了身份”，不要当成电脑漏掉。另外日志里“选人时开始查 3 个队友”其实把自己也算进去了，措辞要改。
- **开局战绩卡片的排布照 LeagueAkari**：大家都习惯了。要适度简化，因为要在小窗里显示（窄的时候两队上下排，每人一行，点开看详情）。只学排布、不抄代码，视觉原创（ADR 039 D5）。
- **风险提示**：卡片下面的风险提示去掉。设置页里大量的风险说明和数据说明也要精简：每个插件的风险和许可说明收进**一个弹窗**，第一次打开有风险的开关时弹一次，以后从一个小链接打开。许可证要求的署名（aramhex-data 是 CC BY-NC；OP.GG 我们答应过放标志和链接）留成一个小的来源标签，这个标签同时就是数据源的切换。整个 Kotone 的设置页也值得照这个思路清理一遍。
- **OP.GG 直接用**（玩家决定）：默认打开，不再等 opgginc/opgg-mcp#26 的回复（2026-11-26 还没人回）。issue 里答应过的用法照旧：按需请求、最多 2 个并发、缓存 24 小时、`client_app` 写 `kotone`、放标志和链接、她说的时候带上出处。
- **数据源怎么展示**（我的建议）：同一块内容一次只用一个数据源，不把不同来源的数字混在一张表里。来源的名字是卡片或页面上的小标签，点它可以切换，选了会记住。默认：国服的峡谷和大乱斗用腾讯 101；海斗的海克斯用 aramhex-data；101 没有的（全球数据、对线指南）用 OP.GG。她被问到时可以用任何一个来源，说清出处。
- **插件页列出所有内置推送**（玩家决定）：插件里显示它会推送的每一条，写明时机和做什么，每条一个开关，用户不能改。和自动化的区别是：推送是插件内置的、只能开关；自动化是玩家自己建的、能改，也能订阅同样的事件。我的建议：推送在插件清单里声明，由宿主画开关、由宿主执行开关（关掉的推送宿主直接丢掉，开关一定管用）；叫法统一为“推送”，卡片是推送的一种样子（`docs/glossary.md` 和 terminology.spec 实现时一起改）；现在“角色 → 交互”里的总开关怎么收，实现时再定。

## 九、把插件形态推广到其它插件（讨论中）

**语音输入的历史记录全是“提醒”**：玩家的 `~/.kotone/history/history.jsonl` 一共 276 条，其中 171 条是 `finalText = "提醒"`、`engineId = "stub-final"`、`audioMs = 0`、没有游戏配置。这些不是玩家说的，是测试写进去的：`crates/kotone-core/tests/orchestrator.rs` 的 `capture_lifecycle_orchestrator`（约 3287 行）用了“提醒”的 stub 引擎，没有像 `make_orchestrator_tuned` 那样把 `history.mode` 关掉，也没有给 `history_dir`，所以每跑一次 `cargo test` 就往玩家真实的历史里追加一条（2026-10-04 起每天都有）。改法：这个夹具关掉历史；再加一道防线，测试永远不能写真实的 `~/.kotone`。玩家同意后，2026-11-26 已经从玩家的历史里删掉这 171 条：只删 `engineId = stub-final`、没有录音、没有游戏配置的，剩 105 条。删之前备份在 `~/.kotone/history/history.jsonl.bak-2026-11-26-before-cleanup`。

**暂缓**（玩家先说“可以”，后来改成“有点纠结，屏蔽词这块先别动了”）：屏蔽词保持现在的样子，留在语音输入的文字处理方案里；也不给她做屏蔽词工具。下面两段是当时的方案，留着以后再议。

当时的方案：屏蔽词放进本体“发到游戏”的入口，谁发都过一遍；语音输入插件不提供屏蔽词工具。

“发到游戏”的入口说的是 `crates/kotone-core/src/send_to_game.rs` 的 `GameChat`（ADR 041），往游戏聊天里发话只有这一个入口。用它的有：语音输入、她和外部 Agent 的 `game_chat.send`、旧工具 `companion.type`、旧陪玩流程、自动化的 `chat()`，以及英雄联盟一键喊话（`Host::send_to_game`）。屏蔽词放在入口的第 1 步“整理文字”之后、第 2 步“挑发法”之前，所以按键、交给插件（英雄联盟选人和房间里的聊天走客户端接口）、Source 2 控制台三条路都覆盖到。它排在语音输入的润色和翻译后面，AI 改写出来的字也会过一遍。入口的结果里说明替换了几处，她和语音输入的卡片显示的都是过滤后的话。

配置：屏蔽词从语音输入的“文字处理方案”里拿出来，变成本体的一项设置（开关 + 词表，词表还是 `kotone-postprocess` 的本地 CSV）。旧配置照“读旧写新”迁过去：方案里有屏蔽词这一步的，就打开本体的屏蔽词、沿用原来的词表，再把这一步从方案里去掉。语音输入的文字处理只剩润色和翻译。界面放在哪见第十一节。

**语音输入按新形态**（我的建议）：
- App：现有的语音输入页（常规、文字处理、历史、热键）。

**其它插件**（我的建议）：
