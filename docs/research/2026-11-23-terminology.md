# 2026-11-23 术语统一与界面文案提取（i18n 前置）

起因：玩家指出软件里“游戏里”这类说法很多、意思不清，经过多轮迭代术语冲突越来越多，要求做一轮术语统一，顺便把前端文案提出来，为以后的多语言做准备。结论写进 [术语表“界面用语（v2）”](../glossary.md)，这里记做法和取舍。

## 一、怎么做的

1. **先提取、不改字**（提交 `405f9c2f`）：`apps/desktop/src` 里给玩家看的中文搬进 `apps/desktop/messages/zh-CN/*.json`（Paraglide JS，约 2230 条，按界面分 6 个文件），代码里用 `m.<key>()`。提取前后逐页比对可见文字（24 个页面逐字相同，只差时间数字），Playwright 131 个原样通过——证明没改字。
2. **在提取出来的目录上统一术语**：前端的改动几乎都落在这 6 个 JSON 里，一个文件就能看完 diff；Rust 里玩家看得到 / 模型会照着说的字符串、`settings_guide.rs`、`docs/assistant.md`、官网另外改。
3. **守门**：`e2e/terminology.spec.ts`
   - 前端代码里不再写中文（故意留下的用 `i18n-ignore` 包起来并写原因：和后端文字比对的、存进配置的默认值、角色内容、浏览器预览的示例数据、和 `settings_guide.rs` 对应的设置位置词）；
   - 目录里每条都有人用、不重复，和 `project.inlang` 一致，插件不从网上拉；
   - 术语表“不说”一栏的词不出现在界面文案、气泡和她念的固定的话、设置说明、系统提示和工具说明、`docs/assistant.md`、官网（纯英文的词按整词找）。

## 二、选 Paraglide 的理由

| | Paraglide JS 3.2 | svelte-i18n 4.0 | 自己写 JSON 字典（官网现在的做法） |
| --- | --- | --- | --- |
| 维护 | 活跃（2026-11 还在发版），Svelte 官方 CLI 推荐 | 2024 年以后没更新 | — |
| 类型检查 | 消息编译成带类型的函数，拼错 key、少传参数在 svelte-check 时就报错 | 运行时查字符串 key | 没有 |
| 和我们的栈 | 纯 Vite 能用（我们不是 SvelteKit）；`.ts` 里也能直接用 | store 写法 | — |

坑：Paraglide 默认从 jsdelivr 拉 inlang 插件（编译时联网、执行网上下载的代码）。改成从 `node_modules` 读（`@inlang/plugin-message-format@4.5.0`，锁在 `pnpm-lock.yaml`），编译不联网。

## 四、几个取舍

- **“游戏里”拆成两个意思**：字面的“在游戏窗口里”保留；指“用嘴叫她”的入口一律改成“通话”（ADR 033 之后它就是一个通话）。代码里的 `Entry::Game` 同时改名 `Entry::Call`。快捷指令也算“在通话里说一句”：按了会接通。
- **“她怎么回答”里的小节改名**：“AI 连接”→“她用的模型”（里面两项：API 连接、模型），“对话气泡”→“气泡”。旧名字在导航里留作别名，之前对话里引用的旧位置照样能跳过去。
- **玩家说的话不改**：“退下”“停下”“可以 / 不要”、唤醒词是玩家嘴里的命令，不是界面文字。
- **没提取的**：Rust 发出来的字（错误、气泡状态、托盘、她念的固定的话）和模型看的字。这次只统一术语；要做多语言，Rust 侧还得另做（错误码或 Rust 端的 i18n），她说哪种语言也是另一个决定。
- **英文先不加**：这次只有 zh-CN 和机制；有了目录以后加英文主要是翻译工作。
