# 语音对话的及时性与连续性：实测与成熟方案调研（2026-11-20）

玩家试用 0.2.0 的反馈：Kotone 是新品类，但语音对话的手感像 Coding Agent，不像 GPT 实时语音或豆包语音通话。最明显的两点是**及时性**（说完要等很久）和**连续性**（答完就结束，要再按键或再喊唤醒词）。本文先用玩家本机的日志拆开延迟，再看成熟项目怎么做，最后给出方案。

参考源码浅克隆在 `target/research/voice/`：LiveKit Agents `06731db`（Apache-2.0）、Pipecat `77bb176`（BSD-2）、xiaozhi-esp32-server `3219a28`（MIT）、TEN framework `238da29e`（Apache-2.0 附加条款）、Home Assistant core `f93f4567`（Apache-2.0）。另查了 OpenAI Realtime、火山引擎端到端实时语音、声网、ElevenLabs、Retell、Vapi、DeepSeek 的公开文档。

## 一、实测：时间花在哪

玩家本机 `~/.kotone/kotone.log` 与 `usage.jsonl`（2026-11-20，本地 X-ASR、DeepSeek 对话 / 文字识别 / 语音合成，呼叫键触发）：

| 阶段 | “你好，能听到吗？” | “你能做什么” |
| --- | --- | --- |
| 说完 → 识别出字（本地流式 X-ASR） | 0.06 s | 0.04 s |
| 截游戏窗口 + DeepSeek 文字识别（每个语音回合固定先做） | **约 12.2 s** | **约 11.7 s** |
| 模型（deepseek-flash） | 1.3 s（11 个 token，没思考） | **约 19.6 s**（开着思考 157 个推理 token，回答 226 个 token） |
| 语音合成（整段合完再播） | 1.7 s（17 字） | 4.1 s（109 字），念了 20.6 s |
| **说完 → 听到回答** | **约 15 s** | **约 35 s** |
| “先接一句”（1.5 s 后） | 合成 1.3 s 才出声 | 合成 7.8 s 才出声 |

结论：

1. 最大的一块不是模型，而是**每个语音回合开始前固定做的一次在线读屏**（`agent.rs` 的 `attach_screen` → `companion::read_chat`），连“你好”都要先等 12 秒。成熟项目没有一个在回合开始前固定读屏：看画面是按需调用的工具。
2. 语音入口开着 DeepSeek 思考（默认 high），回答也太长，20 秒的回答本身就不像对话。
3. 回答是整轮结束才交给语音合成，合成也是整段合完再播。
4. “先接一句”的三句话每次现合成，比回答本身还慢。

## 二、成熟项目怎么做

### 及时性

| 做法 | 谁这样做 | 要点 |
| --- | --- | --- |
| **边生成边念** | LiveKit、Pipecat、xiaozhi、TEN、OpenAI | 模型每段文字一到就进分句器，一句话合成一句、出音就播。xiaozhi 的中文分句：第一段可以在“，、”处切（更快出声），之后只在“。？！；：”处切，不在引号里切（`core/providers/tts/base.py:84-107, 506-584`）。LiveKit 中文短于 20 字的片段并到下一句（`tokenize/blingfire.py:72-73`）。 |
| **语音回合关掉思考** | Pipecat（DeepSeek 默认关，注释说开着推迟第一个字，`services/deepseek/llm.py:22-44`）、xiaozhi（`deepseek.com` 默认 `thinking: disabled`，`llm/openai/openai.py:13-20`）、TEN（快 / 慢路由：分类器 2.3 s 内决定，超时走不思考的快模型，`routing.py:53-93`） | 推理内容永不送进语音合成。 |
| **回答要短** | OpenAI 语音提示词指南 | 语音里一两句，细节等追问。 |
| **填充话预先生成** | xiaozhi（唤醒应答缓存，`core/handle/helloHandle.py:26-209`）、LiveKit（预录“思考声”）、Pipecat（工具开始时 TTS 一句 “Let me check on that.”）、声网（`response_wait_ms` 默认 1500，每轮最多一句，模型先答就不说） | xiaozhi 的做法正是“第一次接入时批量生成”：按音色哈希存一份合成好的音频，启动时预热，用掉一条就在后台换一句新的，附带一个内置兜底音频，从不当场现合成。 |
| **慢工具前先说一句** | OpenAI 指南、Pipecat、Retell `speak_during_execution`、LiveKit `ctx.with_filler` | 模型在调用慢工具前自己说一句短话（每次说法不同），快工具不说；再加一个“工具跑太久才说”的看门狗。工具在说话的同时运行。 |
| **提前开跑** | LiveKit `preemptive_generation`（默认开） | 识别结果一出来就让模型生成，确认说完时文字没变就直接用，变了就丢掉；工具要等确认后才执行。 |
| **静音判停** | OpenAI `silence_duration_ms` 500；Pipecat VAD 0.2 s + Smart Turn 模型（中文支持未写明）+ 3 s 兜底；xiaozhi 200 ms；LiveKit 0.3–2.5 s 动态 | Kotone 现在 0.7 s，不是主要矛盾。TEN 的“说完 / 没说完 / 等一下”判停模型是 7B、要 GPU，许可证禁止装在用户设备上，只能照思路做。 |
| **语音合成走流式** | DeepSeek 官方文档有 `wss://api.deepseek.com/v1/tools/tts`：分段发文字、边收 24 kHz PCM | DeepSeek 的语音识别只有整段上传（`/v1/tools/asr`），没有流式识别、也没有实时语音接口。 |

公开的延迟预算：Pipecat / Daily 指南目标说完到出声 1.5 s（判停 + 识别 0.3 s、模型首字 0.65 s、首句合成 0.12 s）；Vapi 典型 2.3 s。

### 连续性

| 做法 | 谁这样做 | 要点 |
| --- | --- | --- |
| **答完自动再听** | xiaozhi（`auto` 模式：念完约 0.24 s 设备重新开麦，`sendAudioHandle.py:50-77`）、Pipecat（唤醒后 10 s 内不用再喊，谁说话都重新计时，`wake_phrase_user_turn_start_strategy.py`）、Home Assistant（回答以“？”结尾才再听一次，`conversation/chat_log.py:400-415`） | 半双工：她说话时不收音，所以开着音箱也不会录到自己。 |
| **一直在听（通话模式）** | LiveKit、Pipecat、豆包 / OpenAI 实时语音 | 不用唤醒；LiveKit 15 s 没人说话记为“离开”，xiaozhi 120 s 后说句告别再断开，豆包 10 分钟断开。 |
| **结束对话** | xiaozhi：精确匹配“退出 / 关闭”立即结束；“再见 / 拜拜 / 晚安”由模型调工具结束；火山 `enable_user_query_exit` | |
| **打断** | xiaozhi：识别出超过 2 个字才打断（不是只要有声音）；Pipecat：她说话时至少 3 个字（中文按字算）；LiveKit：先暂停，2 s 内没识别出字就接着念（防误打断）；OpenAI / LiveKit / Pipecat：对话记录只保留玩家**实际听到**的部分 | 打断后一个信号同时取消模型、合成、播放队列（xiaozhi 用一个代号 + 中止标记）。 |
| **打断时正在跑的工具** | LiveKit：不取消，5 s 后转到后台，结果之后再说；Pipecat：默认取消，可设为后台继续 | |
| **回声** | LiveKit 桌面模式用 WebRTC 回声消除（音箱输出作参考）+ 前 3 s 暖机不接受打断；Pipecat 不做回声消除，提供“她说话时静音”；xiaozhi 固件没开回声消除就只用半双工 | Windows 可选：Voice Capture DSP（`CLSID_CWMAudioAEC`）、纯 Rust 的 `sonora`（WebRTC AEC3 移植，BSD-3）。坑：通信类音频流会让 Windows 默认把其他程序（游戏）音量压低 80%，要 `SetDuckingPreference(TRUE)`。 |

## 三、建议方案

分三期，先做收益最大、风险最小的。

### 第一期：去掉固定的等待，答完接着听（预计“你好”从 15 s 降到 3 s 左右）

1. **语音回合不再先读屏。** 只把前台窗口标题和进程名带上；要看聊天、看画面时由她调用现有的 `companion.read_chat` / `game.look`。（成熟项目都是按需调用。）
2. **语音入口关掉思考**（`thinking: disabled`），聊天窗口保持现在的设置；推理内容不念。
3. **语音回答要短**：提示词里写明一两句、口语、细节等追问；慢工具前先说一句短话。
4. **填充话预先生成**（回答你的问题：是的，照 xiaozhi）：填好 Key、换音色、换角色时，在后台把一组短句（应答“嗯？/我在”，等待“我看看/稍等哈/让我想想”……）用当前音色合成好存下来；1.2 s 左右还没出声就播一句，每轮最多一句，回答先到就不播；系统语音时用内置兜底。
5. **答完自动再听**：她念完（半双工，念的时候不收音）就开麦等 8 秒，开口就接着这段对话，没开口就安静结束；说“没事了 / 退下 / 拜拜”结束。复用现有的 `voice_ask`（她追问时已经是这样）。
6. **每段计时写进日志**：说完 → 识别 → 模型首字 → 首句出声。

### 第二期：边生成边念，按键打断

7. **流式**：模型文字 → 分句（照 xiaozhi 规则）→ DeepSeek 流式语音合成 WebSocket → 收到就播；其他语音引擎按句合成、排队播放。
8. **她说话时按呼叫键或喊唤醒词 = 打断并开始听**：停掉合成和模型，对话记录只留已经念出来的部分。

### 第三期（可选）：通话模式

9. 像豆包语音通话一样一直在听，可以直接用声音打断。需要回声消除（`sonora` 或 Windows Voice Capture DSP，用系统输出作参考，同时消掉游戏声音），打断要求识别出 2–3 个字，先暂停、2 秒内没识别出字就接着说；15 秒没人说话收起，长时间没说话说句告别再挂断。戴耳机的玩家第一、二期就够用，所以这一期做成可选。

### 不照搬的

- TEN 的判停模型（不能装在用户设备上）、Smart Turn（中文支持没写明）：先不用模型判停，把静音判停从 0.7 s 调到 0.5–0.6 s 试试。
- DeepSeek 没有流式识别：本地 X-ASR 已经是流式；在线识别只能整段上传，这是剩下的延迟下限。要做到豆包那样，长期看要换实时语音模型（火山端到端实时语音是参考）。
