# 2026-11-25 共享资源评估：本体里只有一份、谁都想用的东西

玩家（2026-11-25）：“现在我们有了 MCP APPS，整个项目有了明确的边界，那么我们是不是应该考虑对现有的一些边界进行评估？例如……快捷键……插件有自己的快捷键，陪伴智能体也有自己的快捷键，迟早有一天，这个快捷键的数量会多到记不清在哪。”看过快捷键的清点后玩家同意把同类的东西都查一遍。

**怎么查的**：四个只读的子代理照 [软件哲学](../philosophy.md) 最后一节的做法逐项查代码（分快捷键、声音、屏幕和注意力、往游戏里输入四组），每条带文件和行号。**全部只读了代码、没有实测**；标“没实测”的是代码推出来的，修之前先复现。

## 一、共同的毛病

四组查出来的是同一种形状：

1. **运行时的机制大多已经只有一份，设置却散在很多地方。** 快捷键只有一个钩子、一个管理器，设置散在 7 个以上的页面；麦克风有两处设置；屏幕上的东西设置在 3 处以上。
2. **插件接口里没有这项资源，插件要么被写死在本体里，要么自己去开设备。** 语音输入的 5 个快捷键、悬浮窗、注入器都是本体按具体类型接上的；游戏语音、音乐自己用 cpal 开麦克风和扬声器；同传自己建了一个 SenseVoice。
3. **“能不能用、谁先用”的规矩有好几份，每个调用的地方各写各的。** 5 处压低音量的规则、2 种“她在说话”的判断、4 种“能不能打断她”的规矩、4 种全屏判断。
4. **文档说了“只有一份、经过本体”，代码没做到。** ADR 038 D3.7（麦克风只有一份）、D5（覆盖层只有一个）、D6（宿主给插件语音识别）、ADR 038 / 039 说的“打字、`game.act`、按键程序共用一把输入锁”。

所以要改的是一条规矩，不是四个零散的修补：**每样共享资源由本体里的一个管家拥有；插件只声明要什么，经宿主拿；规矩只写在管家里一次；设置只有一个地方；边界写成测试。** 快捷键（[ADR 040](../adr/040-hotkeys-belong-to-core.md)）和发到游戏（[ADR 041](../adr/041-send-to-game.md)）是头两个照这条做的。

## 三、逐项

### 快捷键（详见 [ADR 040](../adr/040-hotkeys-belong-to-core.md)）

- 有：一个低级键盘钩子线程、一个 `HotkeyManager`（`apps/desktop/src-tauri/src/hotkey.rs`）、前端一个冲突检查 `findHotkeyConflict`（`hotkeyCombo.ts:105`）覆盖 16 个可设置的键。（2026-11-25 ADR 040 第 1 期：冲突检查挪到后端 `kotone_core::hotkey_table` 一处，补上游戏聊天键、控制台触发键、Esc；「设置 → 热键」只读列出全部。）
- 毛病：设置散在 7 个以上的地方（代码注释自己写着“现在分散在三处”，`navigation.ts:141`）；插件接口没有快捷键，语音输入的 5 个键在本体设置、桌面端、命令行里分别写死；快捷指令是 8 个固定格子；冲突检查不看游戏聊天键、F23、Esc，插件不参与；ADR 028 写默认呼叫键是 `~`，代码是 `Ctrl+Backquote`（2026-11-25 ADR 028 已改成和代码一样）。

### 往游戏里输入（发到游戏，见 [ADR 041](../adr/041-send-to-game.md)）

- 发到游戏聊天的路有：`game_chat.send`（本体）、语音输入识别完以后、旧的 `companion.type`、自动化程序（`builtin-chat-repeat` 自带一份“回车—打字—回车”，写死回车，对 CS2 是错的）、`game.act`、控制台发话、剪贴板粘贴、调试命令。
- 游戏特有的知识在本体里：各游戏的聊天键和频道、时序、英雄联盟的 `companionNotes`、Source 2 控制台的全部细节（`console_chat.rs`）、为英雄联盟低帧率调的 `KEY_HOLD_MS`。
- 英雄联盟插件没有用客户端的聊天接口；LeagueAkari 选人 / 大厅阶段走 `POST /lol-chat/v1/conversations/{id}/messages`，对局里先确认客户端在前台再逐行“回车—打字—回车”（[send-executor.ts](https://github.com/LeagueAkari/LeagueAkari/blob/main/src/main/shards/in-game-send/send-executor.ts)）。
- 其他：`game_chat.send` 用的是“当前选中”的游戏配置，不是前台检测到的那个；没有频道参数；不接受换行（英雄联盟的提示词却让她“一行一条”发战绩）；各条路的前台检查都不一样。

### 声音

- **麦克风**：本体的语音会话（呼叫键、语音输入、`reply.ask`、唤醒）有锁、互斥；唤醒监听一直开着；游戏语音自己一直开着；没有一个对象拥有麦克风。插件接口没有麦克风或识别的方法。边界测试不管麦克风。
- **谁在说话**：所有声音都走系统默认扬声器，没有选输出设备的地方；`output_lock` 让提醒、回复、垫话轮流；压低音量有 5 处各自的规则（音乐每 150 毫秒查一次她在不在说话、通话里你开口时她的声音压低、CABLE 里你的麦克风在她说话时压低、收音时压低系统音量、开始收音时停掉她的话）；“她在说话”有两种判断（`she_is_audible`、`her_voice_playing`）（2026-11-25 收成一种 `assistant::she_is_audible`，音乐压低和唤醒、通话的半双工都用它，见第二节第 8 条；呼叫键打断、填充话、通话空闲计时、回合结束等她说完这几处还各看各的几项）。
- **语音识别**：本体只有一个引擎注册表，所有本体的收音都经它，一次一个——除了同传（见问题 7）。ADR 021 给同传选了 SenseVoice，ADR 039 D2 说同传用本体唯一的识别，代码是前者。（2026-11-25 代码改成了后者：同传用本体的识别，见问题 7；ADR 021“已确认”第 1 条、039 D2 都跟着写了。）

### 屏幕和注意力

- **游戏上方的窗口**有五个，各自定位：插件覆盖层（经 `Host::overlay`，只有英雄联盟用）、语音输入悬浮窗（本体代码，设置在顶层的 `settings.overlay`，违反 ADR 038 D6“插件的设置放到 `plugins.<id>`”）、消息弹窗、气泡、弹幕。插件覆盖层里不同插件的东西可以重叠，没有分配；五个窗口之间的上下顺序没有定义；全屏判断写了四份。（2026-11-25：角落里的三个——悬浮窗、气泡、消息提示——排成一列，`screen_corner.rs`；独占全屏的判断气泡和悬浮窗改调 `attention::exclusive_fullscreen`，还剩弹幕自己查，插件覆盖层本来就没查，见 ADR 039 实施记录“右下角排成一列”。）
- **右下角弹窗**：只有内置插件的自动卡片能弹；不抢焦点；独占全屏、演示模式、别的程序全屏、Kotone 在前台时不弹；没有频率限制，只按 key 去重；只有一个总开关，不能按插件关。
- **聊天流**：都只追加，经 `append_to_conversation`；“她正忙时插进来怎么办”有四种规矩（自动卡片等、复盘提示 3 分钟后放弃、自动化结果插进正在进行的回合、“让她做”等 `PROMPT_WAIT`）（2026-11-25 收成两种：只记进对话的排同一个队列，`agent/when_free.rs`；要叫她开口的照旧等她空，“让她做”过时不做、在聊天里留一句）；第三方 App 的 `ui/message` 被拒、`ui/update-model-context` 收下但丢掉；第三方工具的 `ui://` 结果在聊天里没有卡片。
- **窗口和焦点**：见问题 5、6；右侧栏谁最后写谁赢。
- 用词：叫 `overlay` 的窗口是语音输入悬浮窗，“覆盖层”是 `plugin-overlay`；弹幕窗口的标题“Kotone 提醒”和术语表里的“提醒”撞了。

## 四、建议的方向（每样一个管家）

| 资源 | 管家管什么 | 照谁 |
| --- | --- | --- |
| 快捷键 | 一张表、一个地方改；插件只登记命令 | VS Code、Obsidian、Raycast（ADR 040） |
| 发到游戏 | 一个入口 `game_chat.send`；通用发法在本体，每个游戏特有的发法由游戏插件提供，宿主按前台的游戏挑；一把输入锁管打字、`game.act`、按键程序；等修饰键松开写在入口里 | 系统输入法框架、VS Code 的语言 provider（[ADR 041](../adr/041-send-to-game.md)） |
| 麦克风和识别 | 本体开一次麦克风，游戏语音经宿主订阅（和琴音说话时转不转给队友不管，见问题 1）；只有一个识别服务，同传也用它（同传不用麦克风，听的是程序的声音；两路可以同时识别，同一个模型只加载一份——2026-11-25 做了，见 ADR 039 实施记录“同传用本体的识别”） | VRCT（麦克风和别人的声音共用一处选识别）、Android 的系统识别服务 |
| 谁在说话 | 一个“声音焦点”：谁要出声先申请（独占 / 可以压低别人），压低规则只写一处；插件的 `speak` 走和她一样的路；“她在说话”只有一种判断；可以选输出设备 | Android 的 AudioFocus |
| 屏幕 | 一个“能不能现在打扰”的判断（全屏、游戏在前台、不抢焦点）全宿主共用；屏幕角落按位置分配，右下角排成一列；插件覆盖层按插件分区 | Windows 的通知状态 / 专注助手 |
| 聊天流 | 一种“她正忙时插进来”的规矩（排队，不丢）；自动卡片按插件限频；`ui.open` 不打断玩家正在看的东西，外部 Agent 调要经权限 | — |

设置也跟着收：快捷键一页；声音一页（麦克风、输出设备、压低）；“提示和覆盖层”放在一处。
