# Privacy

Kotone is a local-first voice input tool with optional network speech recognition, AI text processing, and reminder creation. Whether audio or text leaves the computer depends on the features and connections you choose.

- The default X-ASR model and other local sherpa models process microphone audio on the computer. After model download, local recognition does not require a remote recognition service.
- If you select online ASR (OpenAI-compatible, Volcano, or iFlytek), audio is sent to that service for recognition. The provider's privacy policy and retention terms apply. Kotone's evaluation replay only uses local models and does not send the recorded corpus to online ASR.
- If you enable network AI polishing/translation, recognized text and the configured processing instructions are sent to the selected connection. Reminder creation sends your typed or recognized reminder request and tool instructions to the selected AI connection. Using a local compatible endpoint may keep these requests on-device; any onward network use depends on that server. These requests are part of the feature you enabled, not telemetry.
- Spoken output defaults to "automatic": when the AI connection used by 琴音 is a DeepSeek connection with a saved key, the text to be spoken (answers, reminders, the short wake-up and "let me look" lines) is sent to DeepSeek's speech synthesis API (`/v1/tools/tts`) with that connection's key and billed by DeepSeek per character; otherwise, or when you choose another engine in the settings, the rules below apply. Without a DeepSeek connection, reminder speech uses installed Windows SAPI voices and requires no Kotone TTS model download. Kokoro is an optional local engine (about 147 MB downloaded only on request); an existing explicit engine choice is preserved. Model download contacts the selected download source/proxy. With the default and Kokoro engines, spoken text is not sent anywhere. Only if you choose an online speech engine (an OpenAI-compatible `/audio/speech` endpoint bound to one of your connections, or Volcano speech synthesis) is the text to be spoken sent to that provider; its key stays in the system credential manager. Synthesized audio is cached in memory only (voice + rate + text) and cleared on exit. Edge TTS is not used. Reminders address the person using Kotone. Their text can also appear in a mouse-transparent scrolling overlay visible to people or screen-sharing software viewing that display.
- Kotone does not automatically upload analytics or diagnostic events. It does not include advertising SDKs or account login.
- Kotone keeps a low-sensitivity diagnostic event log locally for troubleshooting and offline process analysis. It contains lifecycle stages, durations, outcomes, and stable error codes, but no recognized text, audio, hotwords, window titles, process lists, or tool-service screenshots. This data leaves the computer only when the user explicitly exports and shares a diagnostic package.
- Network access is also used to check for updates and download speech models from the sources listed in the application. Users can choose the official source, a mirror, and an optional GitHub proxy. Those hosts receive normal connection metadata such as the client's IP address.
- Settings, game profiles, recognition history, optional evaluation recordings, reminders and automation runs (`automation-runs.json`), saved automations (`automations.json`) with their template images (`automation-images/`; an older `reminders.json` is read once and left unchanged), connection metadata, and downloaded models are stored locally under `~/.kotone` by default. Models and history can use custom directories. Reminder records include their text, due time, output choices, and delivery status; they are not a cloud calendar or background Windows service.
- AI connection API keys are stored separately from public connection settings in Windows Credential Manager. Direct ASR credential fields and legacy engine/model options may be stored in local settings; do not treat a raw settings file as a shareable diagnostic report. Ordinary diagnostic packages exclude settings and credentials, and game profile/pipeline exports do not include managed connection keys.
- Recognition history can be disabled or cleared in the application. Evaluation recording and history audio are disabled by default. Assistant requests do not create recognition-history entries, history audio, or evaluation recordings; the resulting reminders are stored separately as described above.
- Uninstalling the application preserves `~/.kotone` so that large models are not lost accidentally. To remove local data, also remove any custom model/history directories and credentials saved in Windows Credential Manager as applicable. Exported files remain wherever you saved them.

- The optional local Agent tool service is disabled by default (`toolService.enabled`). When enabled, it listens only on `127.0.0.1` and requires a per-launch session token stored in a descriptor file under `~/.kotone/run/` that only the current Windows user (and SYSTEM) can read. Authenticated local clients such as `kotone-cli tools` can list window titles and process names and obtain screenshots of the foreground window's visible client area plus crops of them. These images stay in Kotone's memory with a short expiry, are never uploaded or written to disk by Kotone, and are not recorded in diagnostics; a client that saves a PNG with `--output` owns that file. Any software you allow to run as your user can read the descriptor and use the service while it is enabled. If an Agent forwards an image to an online model, that transfer is performed by the Agent, not by Kotone.
- The tool service can also run OCR on those in-memory images and track chat lines across frames. The local Korean OCR backend runs entirely on the computer; its model (about 18.3 MB, PP-OCRv5 mobile from ModelScope/RapidOCR, Apache-2.0) is downloaded only when you explicitly run `kotone-cli ocr install`, which contacts ModelScope. The online DeepSeek OCR backend is off by default: it becomes usable only after you set `toolService.ocr.deepseekConnectionId` to one of your saved connections, and then only when a client explicitly selects that backend. It uploads exactly the PNG of the selected image (plus the request purpose) to that connection's endpoint using the API key from Windows Credential Manager; it does not send window titles, frame metadata, chat history or other images. Per the provider's documentation, recognition continues and may be billed even if Kotone cancels the request. OCR results and chat-tracking state stay in Kotone's memory with bounded size and expiry, are cleared when a tracking session is reset or the app exits, and are not written to disk or diagnostics. Recognized chat text is returned as data and never executed as instructions.
- With the tool service enabled, an authenticated local client can also start or quit Kotone, start or stop the speech runtime, and read Kotone's event stream. If you set `assistant.route` to `agent` (the default is `companion`), what you say or type into the assistant entry is no longer planned by Kotone's own AI connection; Kotone publishes the text, its source and the foreground window reference as a request for the local Agent, and the Agent's replies are spoken or shown as danmaku. Requests, replies and events stay in Kotone's memory with bounded size and expiry (requests expire after 10 minutes), are not written to history, diagnostics or disk, and are discarded when the app exits. Whether the Agent then sends your request to an online model is decided by that Agent, not by Kotone.
- With the tool service enabled, an authenticated local client (an Agent you connected) can also change everything the settings window can: read and update settings, download, activate and delete models, move the models directory, create or delete connections, edit game profiles, toggle start-with-Windows, restart Kotone as administrator (Windows still shows its own UAC prompt), list or clear recognition history, and export or clear diagnostics. API keys passed to `connections.upsert` are write-only: they go straight to Windows Credential Manager and are never returned by any tool, event or log. `history.list` returns the text you dictated, so it reaches whichever local Agent you connected. Instances started with a separate `KOTONE_HOME` use their own credential namespace and cannot read or overwrite the keys of your main installation. Diagnostic exports requested this way are written under `<KOTONE_HOME>/exports/` with the same redaction as exports from the settings window.
- Voice wake-up ("琴音琴音") is off by default. When you turn it on and download its model (about 33 MB from the official sherpa-onnx GitHub release, of which about 5.5 MB is kept), Kotone keeps the selected microphone open while the speech runtime is running and checks the audio for the wake word on this computer; Windows shows the microphone as in use. Nothing is uploaded or written to disk for wake-word detection; only the last few seconds are kept in memory so that words spoken right after the wake word are not lost. After a wake-up, what you say next is handled exactly like the assistant hotkey (recognized with your selected speech recognition, then sent to 琴音 as described below). Other people's voices or game audio that sound like the wake word can wake it up; headphones reduce this.

Kotone injects the final text into the target window using Windows input APIs. Reminder delivery uses speech and/or an overlay to notify the user personally. The built-in agent 琴音 (the assistant hotkey, quick-command sentences and the 琴音 chat window, unless you turn off `agent.inGame`) sends your message and the conversation so far to your selected AI connection, together with descriptions of the tools it may use, the active game profile's notes and the names and descriptions of your saved automations. For messages from the hotkey or quick commands it first captures the foreground window and recognizes its text with the OCR model you selected (a local model keeps the screenshot on this computer; an online OCR model uploads it to that provider), and sends the recognized lines and recent chat tracking with the request. While answering, the model may call tools; what those tools return (for example recognized chat, window titles, settings it reads, saved automations and run records) is sent to your AI connection as well. Recognized screen text and window titles are marked as untrusted data and are never followed as instructions. By default Kotone asks for your confirmation before tools that change settings, delete data, download models, launch or close a game, quit or restart Kotone, request administrator rights, or run a program the AI wrote for the first time; you can change these rules. Conversations are stored on this computer in `~/.kotone/agent/` (attached screenshots are not stored), and text the agent types into game chat for you is recorded in the automation run history. Opening a game uses only the launch path you entered in its game profile, and closing a game sends a normal close request to its windows; Kotone never ends a game's process. With `agent.inGame` turned off, the older one-shot companion makes one request with your words, the recognized chat lines, the profile notes and recent chat tracking, then sets a reminder, types for you or answers by speech/danmaku. Screenshots and recognized text are not written to history or diagnostics. Automations (short sandboxed Luau programs started by the companion or a local Agent) press keys and type only into the window that was in front when the script started and only while it stays in front; when they read the screen they capture that window and, through `ocr()`, use your selected OCR model (an online model uploads the cropped region). Automations cannot access files, the network, other programs or settings, and are stopped by the stop-automations hotkey (default Ctrl+Shift+F12), the tray menu or when Kotone exits. The assistant voice entry requires the speech runtime to be started and has its own interaction mode, defaulting to push-to-talk. Typed requests do not require the speech runtime, and already scheduled reminders continue while the application remains open. Kotone does not read game memory, alter game files, or communicate directly with game servers.

See [diagnostics](docs/diagnostics.md) for diagnostic contents and [reminder behavior](docs/assistant.md) for persistence and delivery limits.
